# DreamWalker — инструкции для Codex

## Репозиторий и границы работы

Проект: `https://github.com/Stasik1960/Dreamwalker`, основная ветка `main`. Рабочая копия находится в `D:\DreamWalker`. Конфигурация Codex хранится на `C:\Users\vakir\.codex`; `D:\DreamWalker\.codex` должен быть junction на `C:\Users\vakir\.codex\dreamwalker\project`.

Перед **каждым** чтением или изменением файлов проекта, Git/GitHub действием, сборкой либо запуском/делегированием subagent выполни в PowerShell:

```powershell
& 'C:\Users\vakir\.codex\dreamwalker\Assert-Workspace.ps1'
```

Если проверка сообщает, что `D:` недоступен, остановись и сообщи пользователю по-русски. Не создавай заново junction или рабочую копию ни на `C:`, ни на `D:`. Не обходи проверку через GitHub, кэш, другой checkout или subagent.

Для shell-сессии, работающей с проектом, выполни `. 'C:\Users\vakir\.codex\dreamwalker\Initialize-Environment.ps1'` (dot-source) в начале. Он настраивает `GRADLE_USER_HOME` в `D:\DreamWalker\.local\gradle` и направляет tool caches и временные файлы на `D:`. Не меняй постоянные переменные окружения пользователя. Не запускай SSH-тесты; допустимы локальная работа и GitHub.

Пользователь ожидает взаимодействия по-русски. Не утверждай, что ошибки устранены, пока это не подтверждено соответствующей проверкой; не обещай численную экономию.

## Модули и сборка

Основная среда Minecraft 1.20.1, Fabric, Java 17, Yarn `1.20.1+build.10`. Пять модулей — `RP-Chat`, `RP-Chat-UI`, `MC-Pool`, `DW_Languages` и `DW_Magic_Connect` — имеют независимые Gradle-проекты на Gradle 8.10.2 без Gradle Wrapper. `DW_Languages` и `DW_Magic_Connect` используют composite build `RP-Chat`.

- `Model-Props`: Gradle Wrapper 8.6, Java 17.
- `Bloodborne-Blocks`: Wrapper 8.8, Java 17. Python 3.11+; CI-зависимости указаны в `tools/requirements-ci.txt`. Среди задач есть `check`, `build`, `logicalGameTest`, `checkReleaseVersion`; ограничивай параллелизм `--max-workers=1`.
- `Danny-AOT-Backport` и `player-animation-backport`: Wrapper 8.12.1, JDK 21, выходные артефакты рассчитаны на Java 17.

У модулей разные toolchain и Gradle. Перед запуском определи нужный модуль и следуй его настройкам; не переноси версии между проектами. Для пяти независимых проектов без wrapper не выдумывай команду wrapper: сначала проверь локально доступный Gradle и совместимость окружения.

Начинай с целевого исходного кода и связанных тестов. После правки запускай подходящую целевую задачу сборки или проверки, не повторяй полный набор проверок без причины. Документационные изменения сами по себе не требуют сборки. Офлайн-проверки не заменяют проверку фактического игрового поведения. Для `Bloodborne-Blocks` и `bloodborne complete` миграция большая и специальная: внимательно изучи README с инструкциями миграции до изменений; не сканируй широко бинарные ресурсы.

## Игровая безопасность и протоколы

Не меняй протокол аутентификации Gravit и правила определения identity/UUID. Для сетевой логики сервер является источником истины: проверяй клиентские пакеты на сервере, применяй лимиты и не добавляй client-only импорты в общий/common код. Проверяй сторону выполнения кода и границы доверия перед изменением сетевого поведения.

## Делегирование и модели

Не делегируй простой локальный вопрос, если среда позволяет быстро решить его напрямую. Обычно запускай не более двух дочерних агентов, а для большинства задач — одного. Координатор отвечает за их инструкции, проверку результатов и остановку дочерних работ при отключении или прерывании сессии; дочерние агенты не порождают новых агентов без прямого указания координатора.

Настроенные роли и модели:

- `dw_scout` — `gpt-6-luna`, medium: узкий поиск и исследование.
- `dw_builder` — `gpt-6.1-terra`, medium: ограниченная реализация.
- `dw_reviewer` — `gpt-6.1-sol`, high: независимая проверка.
- `dw_ops` — `gpt-6.1-sol`, medium: локальные операции и диагностика.
- `dw_architect` — `gpt-6-astra`, low: только для действительно сложной архитектурной проблемы после решения координатора об эскалации.

Поддержка выбора role-файла может отсутствовать в текущем интерфейсе чата. Если так, координатор должен прочитать соответствующий файл роли и задать модель и усилие явно при запуске агента, когда это поддерживается; не заявляй, что роль автоматически выбрана. Для делегирования используй `fork_turns: none`, если доступно, чтобы не передавать лишнюю историю.

Каждому агенту назначай точные файлы и границы владения, критерии приемки и нужные команды проверки. Попроси вернуть краткие факты, измененные файлы, запущенные проверки и риски. Координатор владеет всеми Git-изменениями, ветками, коммитами и push. Не выполняй `reset --hard`, force push, merge или deploy без прямой авторизации пользователя.

При длительной операции проверяй диск между этапами; при отключении останови дочерние процессы. Единственная рабочая копия — D:\DreamWalker; исходный путь приложения на C: может быть junction на неё. Локальные .codex/ и .local/ исключены из Git. Проверку выполняй также перед коммитом и push.
