Восстановление не требует Codex CLI. Нужны Windows x64, PowerShell 7.2+, свободное
место для ZIP и распакованных файлов, интернет к GitHub и доступ к репозиторию
`Stasik1960/Dreamwalker`. Для приватного релиза нужен доступ владельца и установленный
GitHub CLI с собственной авторизацией (`gh auth login`), либо ZIP/манифест,
скачанные браузером под своим аккаунтом. Секреты прежнего владельца не нужны.

Скачай `Restore-Handoff.ps1` и опубликованный SHA256 манифеста именно из фиксированного
релиза `dw-city-handoff-20261017`. Не используй `latest` или изменяемую ветку.
Ниже `<SHA256 из релиза>` нужно заменить точным опубликованным значением.

Для доступного по HTTPS релиза:

```powershell
pwsh -File .\Restore-Handoff.ps1 `
  -ManifestUri 'https://github.com/Stasik1960/Dreamwalker/releases/download/dw-city-handoff-20261017/MANIFEST.json' `
  -ManifestSha256 '<SHA256 из релиза>' `
  -Destination 'D:\Dreamwalker-Handoff-20261017'
```

Для приватного репозитория с авторизованным `gh`:

```powershell
pwsh -File .\Restore-Handoff.ps1 -UseGh `
  -Repository 'Stasik1960/Dreamwalker' -Tag 'dw-city-handoff-20261017' `
  -ManifestSha256 '<SHA256 из релиза>' `
  -Destination 'D:\Dreamwalker-Handoff-20261017'
```

При ручном скачивании всех assets в одну папку:

```powershell
pwsh -File .\Restore-Handoff.ps1 `
  -ManifestPath '.\Downloads\MANIFEST.json' `
  -AssetDirectory '.\Downloads' -ManifestSha256 '<SHA256 из релиза>' `
  -Destination 'D:\Dreamwalker-Handoff-20261017'
```

Папка назначения должна быть **новой**: скрипт откажется даже от существующей пустой.
Не требуется восстанавливать прежние имена пользователя, диск C: или структуру
CodexControl. В примерах D: — произвольный локальный диск нового ПК.
ZIP независимы; их нельзя склеивать двоично. Скрипт проверяет SHA256 манифеста,
размер/SHA256 каждого ZIP и каждого извлечённого файла. Он отказывает при выходе
пути из папки, ссылках, reparse points, дублях и перезаписи. После ошибки он оставляет
новую неполную папку и `.handoff-transfer/RESTORE-FAILED.txt` для разбора.
Игру, конвертацию и статическую миграцию скрипт не запускает.

В результате `.handoff-local/local-paths.json` содержит пути нового ПК. Можно
передать `-JavaHome17`, `-PythonExecutable` и `-GameDirectory` сразу восстановлению.
Не передавай путь к папке чужого лаунчера и не копируй его аккаунты/токены.
Если конфигурация уже создана, меняй только этот локальный JSON осознанно;
исходные манифесты подготовки и доказательства по SHA не редактируй.

Для разработки нужны Java **17 JDK** (включая `javac`, желательно `jcmd` и `jfr`),
Python 3.11+ и Git. Для графической проверки нужен Minecraft 1.20.1, лицензированный
аккаунт при необходимости лаунчера, совместимый Fabric, моды по безопасному списку
и OpenGL-совместимый драйвер. Во время сравнения оставь Xmx **10240 MiB**, дальность
**12/12** и полный набор модов. Карту всегда сначала копируй в независимый рабочий
мир; архивный baseline и упакованный снимок не должны записываться игрой.

Сборка текущего исходного снимка .5:

```powershell
pwsh -File .\handoff\Build-Mod.ps1 -JavaHome17 'D:\Tools\jdk-17'
```

Используются Gradle Wrapper **8.8**, Fabric Loom **1.6.12**, Minecraft **1.20.1**,
Yarn **1.20.1+build.10**, compile Fabric Loader **0.16.10**, Fabric API
**0.92.9+1.20.1**, GeckoLib **4.4.9**, mclib **20**, локальный WorldEdit API **7.2.15**.
Фактическая полная сборка владельца использовала Fabric Loader **0.20.0**.
Wrapper/зависимости скачиваются из публичных Maven/Gradle репозиториев;
`-Offline` сработает только при уже заполненном собственном Gradle cache.
Старые ignored `.gradle` и пользовательские кеши не требуются и не переносятся.
Скрипт вызывает remapJar, sourcesJar и существующую transactionCheck;
`-SkipTransactionChecks` отключает только последнюю по осознанной необходимости.
Он не запускает GameTest, Minecraft, сервер или конвертер.

Предоставленный .4 JAR — отдельный неизменяемый baseline. Назначение текущим
исходникам номера .4 не восстанавливает старую реализацию: для .4 используй
упакованный исходный архив .4. Новая сборка из текущего дерева не обязана побайтово
повторять исторический JAR; записывай её SHA и совместимость явно.

Подготовленные legacy-инструменты статической миграции, каталоги и их проверки
сохранены. Однако старые Python-обёртки в `project/build` содержат привязки к
прошлым SHA/путям/.4/8G и старому Guard. Они **не являются готовыми переносимыми
контроллерами**. До требуемого пилота следующему агенту нужно привязать отдельную
копию нужного инструмента к `local-paths.json` и целевому JAR, сохранив исходный
инструмент и документируя изменения pin. Не отключай ограничения вслепую.
`pack_city_owner_nbt.py` уже отработал: не повторяй упаковку просто для восстановления
комплекта. Упаковка NBT не заменяет будущую статическую миграцию.
