# DreamWalker: внешний вид города и исправления блоков

Модуль для Minecraft 1.20.1 / Fabric. Собирается поверх закреплённого checkpoint `test-launch-microstutter-v22-20261029` и выпускается одним объединённым JAR мода `bloodborne_dw`.

## Редактор cityeditor.2 — 3 ноября 2026

В креативном каталоге оставлены исходные строительные типы: один предмет на тип. Городские позы, дубли состояний и технические носители не добавляются. Их данные в существующей карте сохраняются. Обычная установка задаёт базовый вид текущего режима, даже внутри цветной области города. Ручной ALT-цвет сохраняется в мире до разрушения блока; переключение на Original показывает исходные материалы и сохраняет выбранный ALT-цвет для обратного переключения.

Исходные установочные параметры предметов сохранены. Для обычной установки нормализуются только известные смещения статуй и эквивалентный сухой вид кирпичной стены; сохранённые городские объекты не меняются. Подвесной фонарь ставится на нижнюю грань опоры сверху.

Кисть находится в креативном каталоге; оператор также может получить её командой `/dwedit`. Для работы нужен творческий режим и право изменять участок. Держите кисть в основной руке: `F9` открывает настройки, левая кнопка красит, правая копирует цвет палитры с блока. Для режимов «Один» и «Плоскость» можно удерживать левую кнопку и вести по блокам; один мазок объединяется в одну отмену до установленного лимита.

Доступны пять цветов карты: база, роза, шалфей, песок и красный. Палитра действует на каменные поверхности DreamWalker и городских носителей, включая ограды; ванильные блоки Minecraft не окрашиваются; стекло и деревянные участки общих текстур защищены. Настройки позволяют выбрать:

| Режим | Действие |
| --- | --- |
| Один | Одна ячейка под прицелом |
| Плоскость | Квадрат по направлению выбранной грани, размер 1×1–9×9 |
| Область | Ячейки между двумя отмеченными точками |
| Заливка | Связанный участок одной формы и видимого цвета в плоскости грани, внутри выделения |
| Шум | Выбранный цвет (85%) и базовый (15%) внутри выделения |

`Shift + ЛКМ` и `Shift + ПКМ` отмечают первую и вторую точки под прицелом. Голубая рамка показывает выделение. Выбор «База» возвращает базовый ALT-вид. В F9 оставлены пять цветов, режим, размер, отмена и повтор; Escape закрывает окно. «Отменить» и «Повтор» работают с историей текущего подключения: до 50 операций и суммарно 32768 ячеек. Если объект заменён, участок защищён или выгружен, устаревшая операция отклоняется либо останавливается с сохранением уже выполненной части.

Одна операция ограничена 4096 загруженными ячейками в пределах 128 блоков от цели. Редактор не подгружает чанки ради выделения. Сервер распределяет изменения между тиками; данные цвета добавляются только изменённым ячейкам в существующее хранилище чанка. Нет дополнительных block entity на каждый цветной блок и преобразования всего города. Окраска сохраняется вместе с чанком; WorldEdit 7.2.15 переносит её через дополнительный NBT-тег при копировании и вставке.

Проверки cityeditor.2 на изолированных копиях карты: 634 уникальных предмета каталога, одна кисть; 541 BlockItem установлен и разрушен обычными взаимодействиями, кисть проверена отдельно, 92 остальных предмета не являются блоками. Реальные кнопки F9 подтвердили выбор цвета и режима на сервере. Все четыре ручных цвета проверены на четырёх существующих форматах города и обычной ограде, включая фактически изменённые поверхности при сохранении геометрии и света. Отдельный функциональный прогон завершил 253 проверки покраски, копирования цвета, областей, плоскости, заливки, шума, мазков, истории и нормального сохранения. Подробные результаты и ограничения приведены в `validation/editor2-20261103/RESULTS-RU.txt`. Итоговая сопоставимая пара полётов завершилась PASS: средний FPS 28,54 → 28,41 (−0,43%), p99 84,48 → 79,50 мс, пиковый Working Set +5,94%, private memory +3,17%, пиковый heap −0,27%. Кадры дольше 50/100 мс: 984/49 → 967/40; дольше 250 мс — ноль в обеих версиях. Все показатели в допуске 15%, дополнительный запрет роста счётчиков задержек также пройден.

Изолированные игровые драйверы `editorqa`, `serverqa`, `perfqa`, `flightqa` и диагностический мод `renderdiag` собираются отдельно. `tools/editor_runtime.py` запускает клиент на копии мира. Для сравнения cityeditor.2 используется `tools/compare_editor_flights.py` и зафиксированный протокол в `validation/editor2-20261103/protocol`: одинаковый полный клиентский модпак, настройки и маршрут из двух кругов. Все измеренные кадры сохраняются; допуск показателей кадров и памяти — 15%, дополнительные проверки счётчиков задержек отражаются отдельно. Диагностический наблюдатель покраски и JFR в этих полётах выключены.

Исторические результаты **cityeditor.1** (до очистки каталога): функциональные проверки редактора, установка 4606 канонических форм, сохранение, очистка цвета при разрушении и интеграция WorldEdit проверены; границы и переиспользование результатов для неизменившихся классов указаны в [отчёте](validation/city-editor/REPORT-RU.md). В итоговой паре полётов с 50000 окрашенными ячейками все показатели кадров, памяти и частоты задержек укладываются в согласованный допуск 15%. Средний FPS: 28,47 → 28,00; пиковый heap: +1,71%, пиковый Working Set: +2,54%. Кадров дольше 250 мс нет в обеих версиях. Кадров дольше 50/100 мс стало на 12,08/11,13% больше; дополнительный строгий критерий полного отсутствия роста счётчиков **не пройден**, поэтому сравнитель сохраняет статус `INVESTIGATE`. Нулевое ухудшение коротких задержек не заявляется.

## Установка

Заменить прежний JAR DreamWalker на объединённый релизный JAR на сервере и у всех игроков. Отдельный ресурс-пак не нужен. Прежние экспериментальные ресурс-паки города следует отключить, чтобы они не перекрывали встроенный визуал.

Команды оператора:

- `/dwvisual status` — выбранный внешний вид и версия состояния мира.
- `/dwvisual alt` — осенний альтернативный вид.
- `/dwvisual original` — оригинальный вид.

Переключение предупреждает игроков за пять секунд, сохраняет новое состояние и отключает подключённых игроков. Клиент готовит ресурсы вне мира и повторяет вход. При совпадении подготовленного вида и состояния сервера повторной перезагрузки ресурсов нет. Неактивный набор остаётся в архиве JAR; его текстуры и модели отдельно не декодируются. Повторная команда уже выбранного режима ничего не перезагружает. Обычная смена сервера и ручная отмена подключения отменяют автоматическое возвращение.

## Содержание

- Альтернативные материалы города, сдержанные дополнительные цвета, трава, модели и текстуры деревьев. Листва спрайтов нарисована в их текстуре; отдельного слоя листвы нет.
- Исправления прозрачных материалов и смешанных моделей, палитры архитектуры и V12, размещения с поворотом, поведения оград, рамок и стандартного фонаря.
- Рамка source 63 пропускает игрока и сохраняется как данные клетки при размещении другого блока вместе с ней.
- Ограды автоматически выбирают соединения; прежние идентификаторы сохраняются для совместимости существующих миров.
- Обычная установка поддерживающих диагональ блоков использует шаг 90°, установка с Shift — диагональ 45°.
- Фонарь получает отдельный напольный вид. В Survival/Adventure напольный снимается ударом, подвесной раскачивается и снимается пятью ударами за пять секунд; Creative использует обычное разрушение. Ручное снятие работает при `doTileDrops=false`, используемом картой.
- Постоянный кэш перекраски хранит устойчивые исходные модели. Временные модели с отсечением граней по окружению не удерживают мир в кэше и не проходят повторную предварительную проверку видимости.

## Сборка

Для компиляции интеграции с WorldEdit нужен отдельный `worldedit-mod-7.2.15.jar` из серверной сборки. Его путь задаётся параметром `-PworldEditJar=<абсолютный-путь-к-JAR>`. По умолчанию используется файл из `.local/modpacks/client-server-20261028/server_mods/` рядом с модулем; при сборке отдельно передайте свой путь. Этот JAR не включается в готовый мод.

Нужны JDK 17, Python 3.11+ и Git LFS. После клонирования выполнить `git lfs pull`. Gradle 8.8 закреплён включённым wrapper. Python-зависимости устанавливаются через `python -m pip install -r DW-City-Visuals/requirements.txt`. Контрольная сумма `baseline/mod.jar`: `1f2e71c6203a9b3794d9c3cf6cf6cbe6e0a93a750584dc9df967bd2cd166e621`.

`DW-City-Visuals/gradlew.bat -p DW-City-Visuals --no-daemon --max-workers=1 remapJar` собирает слой изменений. Первый запуск требует доступа к репозиториям зависимостей; при заполненном кэше допустим `--offline`. `JAVA_HOME` должен указывать на JDK 17. При необходимости путь к Python задаётся `-PpythonExecutable=<python.exe>`. Привязки к внешнему диску нет. Локальный `tools/build.ps1` использует существующий `CodexControl/Guard.ps1`, если он установлен, и сохраняет лог/код завершения.

`tools/package_overlay.py` объединяет результат с закреплённой базой. Изменения существующих ресурсов передаются явно через `--replace-entry`; базовые runtime-классы не перезаписываются. Скрипт проверяет CRC и сохранность записей базы. Устанавливать следует объединённый JAR, а не промежуточный `dw-altvisual-overlay`.

После `remapJar` готовый мод можно собрать командой `python DW-City-Visuals/tools/build_release.py --output <новый-путь>/DreamWalker-v22-City-Editor2-20261103.jar`. Она вычисляет перечень замен ресурсов и передаёт его строгому упаковщику; проверки защищённых классов сохраняются. Новый выходной файл не должен существовать.

Сборка автоматически выполняет запекание палитр, импорт проекта деревьев, исправление спрайтов и фасадов, затем обновляет индекс и отпечатки ресурсов. Все входные данные генераторов включены в исходники. Архив исходников выпуска включает настоящий `baseline/mod.jar`, поэтому отдельно скачивать LFS для него не требуется. Это воспроизводимый модуль поверх закреплённой двоичной базы; исходники старых исправлений базы находятся в `baseline/repair-sources.zip`, история базового проекта — в том же репозитории.

`baseline/repair-sources.zip` содержит исходники исправлений закреплённой версии. Новые исходники находятся в `src/main` и `src/client`. Тестовые драйверы и данные измерений не входят в релизный мод.

Результаты проверки конкретного релиза и изменения карты приведены в приложенном отчёте релиза.

## Откат 3D-деревьев — altvisual.5

По запросу возвращены исходные три 3D-модели и их текстура. Расширенный конверт отсечения для отменённых моделей удалён. Спрайтовые деревья не изменены. Редактор моделей расположен в соседнем модуле `DW-Tree-Editor`; сохранение — один `.dwtree.json` с тремя геометриями и текстурой. Результаты прежнего полного прогона в `validation/` относятся к altvisual.4; для отката проверяются сборка и эквивалентность четырёх 3D-ассетов базовой версии.
