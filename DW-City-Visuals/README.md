# DreamWalker: внешний вид города и исправления блоков

Модуль для Minecraft 1.20.1 / Fabric. Собирается поверх закреплённого checkpoint `test-launch-microstutter-v22-20261029` и выпускается одним объединённым JAR мода `bloodborne_dw`.

## Ревизия altvisual.7 — 2 ноября 2026

Пользовательский проект трёх ALT-деревьев сохранён в `inputs/trees/DreamWalker-trees.dwtree.json`. Геометрия импортируется без изменений, встроенный PNG — побайтово. Original-деревья сохранены. Дополнительная граница отсечения действует только на ALT-деревья и не меняет их физику.

Исправления охватывают общие материалы окон со ставнями и кирпичных стен, корпус арки и угловую кладку в обоих режимах, ALT-декор, фриз, RP-дверь `door_1`, верх крыши `prototype_roof` и спрайтовую кору/листву. Точные идентификаторы и UV-маски описаны в `tools/prop-repair-contract.json` и отчётах `validation/*v7*`.

У мини-шпиля со скриншота 5 видимая модель смещена относительно клетки-корня. Поэтому F3 может показывать `minecraft:air` в соседней клетке. Новый ALT-материал добавлен; исходная геометрия, прицеливание, коллизии и данные карты сохранены.

`src/visualqa` — отдельный конечный драйвер съёмки города. Его JAR не входит в выдаваемый мод. Исторические отчёты `.4`–`.6` ниже описывают прежние ревизии; результаты `.7` вынесены отдельно.

## Установка

Заменить прежний JAR DreamWalker на объединённый релизный JAR на сервере и у всех игроков. Отдельный ресурс-пак не нужен. Прежние экспериментальные ресурс-паки города следует отключить, чтобы они не перекрывали встроенный визуал.

Команды оператора:

- `/dwvisual status` — выбранный внешний вид и версия состояния мира.
- `/dwvisual alt` — осенний альтернативный вид.
- `/dwvisual original` — оригинальный вид.

Переключение предупреждает игроков за пять секунд, сохраняет новое состояние и отключает подключённых игроков. Клиент готовит ресурсы вне мира и повторяет вход. При совпадении подготовленного вида и состояния сервера повторной перезагрузки ресурсов нет. Неактивный набор остаётся в архиве JAR; его текстуры и модели отдельно не декодируются. Повторная команда уже выбранного режима ничего не перезагружает. Обычная смена сервера и ручная отмена подключения отменяют автоматическое возвращение.

## Содержание

- Альтернативные материалы города, сдержанные дополнительные цвета, трава, модели и текстуры деревьев. Листва спрайтов нарисована в их текстуре; отдельного слоя листвы нет.
- Исправления прозрачных материалов и смешанных моделей, палитры архитектуры и V12, размещения с поворотом, поведения оград, рамок и стандартного фонаря.
- Рамка source 63 пропускает игрока и сохраняется как данные клетки при размещении другого блока вместе с ней.
- Ограды автоматически выбирают соединения; прежние идентификаторы сохраняются для совместимости существующих миров.
- Обычная установка поддерживающих диагональ блоков использует шаг 90°, установка с Shift — диагональ 45°.
- Фонарь получает отдельный напольный вид. В Survival/Adventure напольный снимается ударом, подвесной раскачивается и снимается пятью ударами за пять секунд; Creative использует обычное разрушение. Ручное снятие работает при `doTileDrops=false`, используемом картой.
- Постоянный кэш перекраски хранит устойчивые исходные модели. Временные модели с отсечением граней по окружению не удерживают мир в кэше и не проходят повторную предварительную проверку видимости.

## Сборка

Нужны JDK 17, Python 3.11+ и Git LFS. После клонирования выполнить `git lfs pull`. Gradle 8.8 закреплён включённым wrapper. Python-зависимости устанавливаются через `python -m pip install -r DW-City-Visuals/requirements.txt`. Контрольная сумма `baseline/mod.jar`: `1f2e71c6203a9b3794d9c3cf6cf6cbe6e0a93a750584dc9df967bd2cd166e621`.

`DW-City-Visuals/gradlew.bat -p DW-City-Visuals --no-daemon --max-workers=1 remapJar` собирает слой изменений. Первый запуск требует доступа к репозиториям зависимостей; при заполненном кэше допустим `--offline`. `JAVA_HOME` должен указывать на JDK 17. При необходимости путь к Python задаётся `-PpythonExecutable=<python.exe>`. Привязки к внешнему диску нет. Локальный `tools/build.ps1` использует существующий `CodexControl/Guard.ps1`, если он установлен, и сохраняет лог/код завершения.

`tools/package_overlay.py` объединяет результат с закреплённой базой. Изменения существующих ресурсов передаются явно через `--replace-entry`; базовые runtime-классы не перезаписываются. Скрипт проверяет CRC и сохранность записей базы. Устанавливать следует объединённый JAR, а не промежуточный `dw-altvisual-overlay`.

После `remapJar` готовый мод можно собрать командой `python DW-City-Visuals/tools/build_release.py --output <новый-путь>/DreamWalker-v22-Visual-Fixes7-20261102.jar`. Она вычисляет перечень замен ресурсов и передаёт его строгому упаковщику; проверки защищённых классов сохраняются. Новый выходной файл не должен существовать.

Сборка автоматически выполняет запекание палитр, импорт проекта деревьев, исправление спрайтов и фасадов, затем обновляет индекс и отпечатки ресурсов. Все входные данные генераторов включены в исходники. Архив исходников выпуска включает настоящий `baseline/mod.jar`, поэтому отдельно скачивать LFS для него не требуется. Это воспроизводимый модуль поверх закреплённой двоичной базы; исходники старых исправлений базы находятся в `baseline/repair-sources.zip`, история базового проекта — в том же репозитории.

`baseline/repair-sources.zip` содержит исходники исправлений закреплённой версии. Новые исходники находятся в `src/main` и `src/client`. Тестовые драйверы и данные измерений не входят в релизный мод.

Результаты проверки конкретного релиза и изменения карты приведены в приложенном отчёте релиза.
