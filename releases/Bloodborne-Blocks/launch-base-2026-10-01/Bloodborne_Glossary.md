# Bloodborne: глоссарий понятий

Утверждён пользователем 30.09.2026. Уточняющий документ к [техническому плану](Bloodborne_Technical_Workplan.md).

Чтобы избежать главной путаницы, слово **«блок»** будем уточнять: *блок Minecraft*, *конструкция* или *предмет*.

## Объекты и их представление

| Термин | Значение в проекте |
|---|---|
| **Клетка мира** | Место размером 1×1×1 блок с конкретными координатами. В каждой клетке записано одно состояние блока, включая воздух. |
| **Блок Minecraft** | Зарегистрированный тип блока, например камень или дверь. Это техническая сущность, не обязательно целая видимая конструкция. |
| **Состояние блока — BlockState** | Тип блока вместе с его свойствами: направление, открытость, соединения и т. п. Разные состояния не обязательно требуют разных предметов. |
| **Конструкция / цельный объект** | Дерево, окно, скульптура или другой утверждённый объект, который устанавливается и разрушается целиком. Может занимать несколько клеток. |
| **Деталь конструкции** | Часть объекта: ветвь, створка, основание, декоративный выступ. Наличие детали не означает, что для неё нужен отдельный предмет. |
| **Модель** | Визуальное описание формы. Одна конструкция может использовать несколько моделей; одна модель может повторно использоваться в разных конструкциях. |
| **Предмет — BlockItem** | То, что находится в инвентаре и используется для установки. Один предмет может поддерживать несколько направлений, состояний и вариантов внешности. |
| **Запись каталога** | Отдельная позиция в творческом инвентаре. Несколько записей могут представлять один предмет с разными настройками. |
| **Семейство** | Группа определений и состояний объекта. В технических данных logical/city число семейств **не гарантирует** столько же уникальных по смыслу объектов. |
| **Канонический объект** | Выбранная правильная версия конструкции, с которой сопоставляются старые версии и дубли. «Канонический» не означает единственный экземпляр на карте. |
| **Вариант внешности** | Отличие рисунка или формы внутри одного типа объекта: например золотая и медная крона. |
| **Функциональное состояние** | Изменение поведения объекта: открыто/закрыто, включено/выключено. Его нельзя удалять как обычный визуальный дубль. |

## Положение и хранение конструкции

| Термин | Значение в проекте |
|---|---|
| **Точка привязки — anchor** | Опорная точка, относительно которой модель размещается и поворачивается. |
| **Корень конструкции — root** | Мировая клетка, представляющая основной блок объекта и связывающая его части. Root и геометрическая точка привязки — разные понятия. |
| **Смещение — offset** | Расстояние от опорной точки до детали, модели или служебной клетки. |
| **Служебная клетка — helper** | Клетка, через которую реализуется многоклеточная конструкция. Не является самостоятельным предметом. |
| **Общая служебная клетка — shared carrier** | Клетка, обслуживающая части нескольких конструкций. Это совместное хранение, а не объединение конструкций в один объект. |
| **Владение частями — ownership** | Связь части с конкретной конструкцией. Нужна, чтобы разрушение одного объекта не удаляло соседний. |
| **Registry ID** | Технический идентификатор типа блока или предмета, например `bloodborne_blocks:…`. Не является названием, координатой или ID отдельного экземпляра на карте. |
| **NBT** | Сохранённые дополнительные данные блока или предмета: например связи владельцев или выбранные настройки. |

## Физика и установка

| Термин | Значение в проекте |
|---|---|
| **Физическая коллизия — collision** | Форма, с которой сталкиваются игроки и другие сущности. Она может быть проще видимой модели. |
| **Форма выделения — outline** | Область выбора объекта курсором. Может отличаться от физической коллизии. |
| **Объём запрета установки — placement footprint** | Форма, пересечение которой мешает поставить другой объект. В сборке от 01.10.2026 механизм реализован отдельно от физической коллизии; явно пустой объём разрешает пересечение. Отсутствующее описание использует прежнее правило по коллизии. |
| **AABB** | Прямоугольный объём, грани которого параллельны осям мира. Из таких объёмов собираются простые коллизии. |
| **Пересечение форм** | Физические объёмы объектов занимают общую область. Простое соприкосновение границ — отдельный случай. |
| **Однократное разрешение пересечения** | Разрешение нужных пересечений при подготовке карты. После разрушения обычная установка снова проверяет конфликт; повторное разрешение не выдаётся. |
| **Постоянное исключение** | Персональное правило объекта, позволяющее соседнее размещение и после подготовки карты. Отличается от однократного разрешения. |
| **Конфликт root/root** | Две конструкции требуют самостоятельные корневые блоки в одной клетке. Разрешение пересечения коллизий само по себе этот конфликт хранения не решает. |

## Графика и материалы

| Термин | Значение в проекте |
|---|---|
| **Полигон** | Отдельная поверхность модели с координатами и привязкой текстуры. |
| **Mesh — полигональная геометрия** | Набор полигонов, описывающих форму модели. Не определяет автоматически её игровую физику. |
| **Текстура** | Изображение поверхности: кладка, листва, металл и т. п. |
| **Текстурный атлас** | Одна картинка, содержащая участки нескольких деталей или материалов. Перекраска всего атласа может затронуть посторонние объекты. |
| **UV-разметка** | Соответствие поверхностей модели участкам текстуры. Показывает, какая часть картинки нанесена на конкретную грань. |
| **Материал** | В обсуждении дизайна — поверхность определённого назначения: камень, кровля, металл, листва. Не обязательно отдельный PNG или блок. |
| **Alpha / прозрачность** | Прозрачность пикселей текстуры. Например, позволяет видеть ветви без прямоугольного фона вокруг них. |
| **Шейдер** | Клиентский способ обработки света, теней и атмосферы. Может сильно менять восприятие тех же текстур. |
| **Ресурс-пак** | Пакет визуальных ресурсов, подменяющий поддерживаемые текстуры и модели. Сам по себе не исправляет состав конструкций или серверную физику. |
| **BASE / ALT** | Основное и альтернативное оформление в поддерживающих их объектах. Это не обозначения старой и новой версии карты. |
| **Overlay — наложение ресурсов** | Замена ресурсов пакетом поверх базовых ресурсов с учётом приоритета загрузки. |

## Обработка и проверка

| Термин | Значение в проекте |
|---|---|
| **Рецепт сборки** | Точное правило состава объекта: какие детали брать, как размещать, что исключать и какие свойства сохранять. |
| **Шаблон распознавания** | Признаки, по которым на карте находится экземпляр конструкции: состояния, смещения и допустимые варианты. |
| **Mapping — соответствие** | Правило перевода старого ID и состояния в новый объект и его состояние. |
| **Миграция / пересборка карты** | Применение соответствий и рецептов к сохранённому миру. Отличается от простой подмены текстур. |
| **Дедупликация** | Устранение доказанных дублей. Сходство картинки не позволяет автоматически объединять функционально разные объекты. |
| **Атомарная обработка** | Связанный набор изменений применяется целиком либо не применяется совсем. Предотвращает наполовину разобранные конструкции. |
| **Галерея объектов** | Набор собранных образцов для проверки и утверждения, включая необходимые варианты и функциональные состояния. |
| **Ревизия** | Конкретная версия кода, ресурсов или мира. Более поздняя ревизия не обязательно содержит все удачные прежние исправления. |
| **Единая сборка** | Согласованный комплект мода, подготовленной карты и визуальных ресурсов, проверенных вместе. |
