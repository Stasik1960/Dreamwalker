# Объединённые модели и редактируемая галерея

Выпуск `2.1.0-unified-gallery.1`, Minecraft 1.20.1, Fabric, Java 17.

## Что изменено

Аудит взят из ветки `codex/bloodborne-model-duplication-audit`, исходный коммит `b5acd39e494e4efa505b65d63631230993a897a9`. Старые страницы, объединявшие несвязанные модели по 16 штук, разобраны на объекты. Одинаковые повороты и совместимые похожие фрагменты объединены по материалу, размеру и физике. Цельные объекты объединены только при совпадении нормализованной формы и поведения. Все исходные модели, UV, положения и коллизии сохранены внутренними состояниями для переноса города; новая установка использует каноническую форму и направление взгляда игрока.

Реестр города сократился с 3 805 до 3 324 ID. Полный мод содержит 3 374 ID, включая 49 логических семейств и служебный `architecture_part`. Удалены 3 732 старых ID, добавлены 3 251 объединённое семейство. Число внутренних состояний не равно числу доступных объектов.

Сухое дерево и сухой куст объединены в `o_c001`: куст — вариант `bush_asset_e`, четыре направления установки внутри одного ID. Варианты дерева сохранены. Решения «Правки финал», ручные цельные конструкции, функциональная стена и нативные блоки защищены от автоматического слияния. Существенно разные цельные формы остаются отдельными.

Исторический цельный куст доступен в этом семействе. Старые частичные модели кустов в городе перенесены с сохранением формы: достоверной схемы их сборки в этот исторический куст в исходной карте нет. Эти фрагменты можно отметить в галерее для следующей ручной правки.

Во всём исправленном городе заменены 27 393 913 записей блоков. Входные данные — исправленный город предыдущей галереи, без её старых площадок; повреждённая rc.4 не используется. Замена выполняется непосредственно в сохранении, сохраняет координаты и существующие наложения коллизий. Обычная игровая установка по-прежнему проверяет свободное место. Все 416 блоков Yuushya и 6 605 351 чужой блок сохранены.

## Карта для правок

Основной архив содержит город и галерею непосредственно над ним, начиная с Y=228. На 3 374 площадках представлен каждый зарегистрированный ID; промежутки между площадками — три воздушных блока. Исходное содержимое, координаты, числовые ID и границы площадок записаны в `editable-gallery-manifest.json` внутри мира.

Точка появления — на первой площадке, `-776 229 -460`, случайное смещение появления отключено. На площадке показан канонический образец ID; внутренние состояния, сохранённые для старого города, не требуют отдельных площадок.

1. Редактируйте образец над плитой своей площадки. Стройте замену внутри её границ X/Z, по высоте до Y=319.
2. Удаление всех блоков образца обозначает удаление его ID. Один новый блок обозначает замену. Постройка из нескольких блоков обозначает новую цельную конструкцию.
3. Плиты и таблички не входят в замену. У вспомогательных частей конструкции нет самостоятельного решения о новом ID.
4. Служебный `architecture_part` показан на отдельной подписанной площадке вместе с необходимым хозяином. Изменение этой площадки фиксируется отдельно: удаление внутреннего носителя требует пересмотра зависимых конструкций.
5. Верните весь сохранённый мир вместе с исходным манифестом. Не редактируйте манифест вручную.

Для перехода к объекту используйте поле `tp` его строки манифеста. Команда `/bloodborne debug id 12345` показывает соответствующий registry ID. Все числовые ID состоят из пяти цифр и уникальны.

Мод этого выпуска устанавливается вместе с его картой: прежние миры содержат удалённые ID и требуют конвертации. Существующие Fabric API, Yuushya и Architectury оставьте в сборке. Архив не включает персональные данные игроков.

## Неоднозначные объединения

В `images/shortimageindex.json` перечислены восемь объединений похожих фрагментов и дерево с кустом. Карточки `images/*.png` получены из настоящих текстурированных моделей программным рендером; это сравнения геометрии, не скриншоты Minecraft. Разные сохранённые формы внутри этих ID сохранены для города.

В `screenshots/` находятся десять настоящих скриншотов Minecraft: дерево с кустом, восемь сравнений объединённых фрагментов и обзор галереи. На сравнительных площадках в проверочной копии мира добавлены две исходные формы по бокам от канонического образца. Эти дополнительные образцы не внесены в карту для редактирования, чтобы сохранялось правило «одна площадка — одно решение по ID».

Клиент проверен с максимальной Java-кучей 7 ГБ. Новые семейства содержат много внутренних состояний; совместимость с малым лимитом памяти не подтверждена.

Dedicated-сервер проверен с кучей 5 ГБ: два запуска, сохранение, штатная остановка и повторное чтение мира. После повторного сохранения все 3 373 редактируемых образца и служебная площадка определяются как неизменённые. Проверка выполнена локально на Windows; производственная конфигурация сервера не менялась.

## Воспроизведение

Из каталога `Bloodborne-Blocks`, с Python, содержащим NumPy и Pillow:

```powershell
python tools/prepare_unified_inputs.py
python tools/build_unified_registry.py --apply
python tools/add_unified_tree_variants.py --asset-e --apply
python tools/build_creative_equivalence.py
python tools/verify_unified_registry.py
.\gradlew.bat check build
```

Для исторического куста нужен отслеживаемый `releases/Bloodborne-Blocks/bloodborne-blocks-2.0.1-mc1.20.1.jar`. LFS-файлы должны быть загружены (`git lfs pull`). Версии зависимостей не менялись. Не запускайте генератор поверх пользовательских изменений моделей: он восстанавливает этот конкретный выпуск из закреплённых исходников.

Для мира:

```powershell
python tools/convert_unified_city.py --help
python tools/build_editable_city_gallery.py --help
python tools/inspect_editable_city_gallery.py --world <edited-world> --manifest <original-manifest> --output <changes.json>
```

Манифест хранит постоянные поля ресурса отдельно от игровых переключателей. Поэтому обычное пересохранение мира Minecraft не считается правкой образца.

## Проверки выпуска

Проверены все 53 272 перенесённых состояния и 48 794 уникальных сочетания модели с поворотом. Во всём городе отсутствуют удалённые ID; сохранены чужие блоки и их данные. Независимая проверка сравнила город до и после добавления галереи: ниже Y=228 содержимое блоков, сущностей блоков и запланированных тиков совпадает.

Полный запуск `check build --continue` выполнил 82 задачи и обнаружил две ошибки проверок ресурсов и каталога. После исправления обе проверки повторно прошли, итоговый `build` завершился успешно. Отдельно прошли проверки определения правок галереи и безопасной точки появления. Машинные результаты находятся в `*-proof.json` рядом с этим документом.
