# Dreamwalker BB исправления инструмента и галерея

Ревизия `0.1.0-90009-fix.1` основана на v10, коммите `d5d78282b5df3d274a49be8e5b947bedc6bf3ecc`, в отдельной ветке `codex/bb-v10-90009-fix`. Это кандидат для проверки пользователя, не принятая v11. Комплексная серверная проверка прошла; обязательные клиентские сценарии пока закрыты частично. Пользователь остановил игровые проверки 10 октября и поручил опубликовать незавершённый снимок для продолжения на другом компьютере. Полная приёмка не завершена; HANDOFF.md содержит актуальную передачу.

## Сборка и происхождение

Проект `bloodborne complete`: Minecraft 1.20.1, Fabric Loader 0.16.10, Fabric API 0.92.9+1.20.1, GeckoLib 4.4.9, Yarn 1.20.1+build.10, Java 17.0.20.1, Gradle wrapper 8.8, Loom 1.6.12. Архитектура и RP находятся в одном обычном combined JAR; QA-мод не является зависимостью пользователя.

Исходная v10 пересобрана из указанного снимка без производственных изменений: SHA256 `cabd5b35777a4c69f6f95e4b0363ca5d33daadaddba08dbcd379fe03a1a753ee`. Это собственная пересборка исходников, не опубликованный ранее бинарник с SHA `ad7fb47b…`.

Текущий ordinary JAR: `dreamwalker-bb-fabric-1.20.1-0.1.0-90009-fix.1.jar`, SHA256 `61b206c7bd2d253fbf1387b8d95c7e3663f192759ce4673c808798246e90a4fa`. Проверить сумму выдаваемого файла по окончательному манифесту: промежуточные сборки имели другие суммы.

Воспроизведение из исходников: задать `JAVA_HOME` на JDK17, затем `gradlew.bat --no-daemon -Dorg.gradle.java.home=ПУТЬ_К_JDK17 remapJar`. Проверки: `runRepairtest`, `transactionCheck`, `-Pgametest_run_name=90009-full-07 runGametest`. `--offline` использовался с уже заполненным локальным кэшем; для новой машины зависимости сначала должны быть доступны.

## Причины и исправления

| Случай | Причина и изменение | Подтверждение |
|---|---|---|
| Многократное открытие меню и короткие клики | Закреплённый UUID и контекстные режимы; ввод теперь принимает нативное событие нажатия, а не опрашивает удержание раз в тик. Короткий отпуск до следующего тика больше не теряется | Настоящий ПКМ, первый ЛКМ, поворот закреплённой двери, Ctrl+Z и X; сочетания с колесом отдельно проверяет пользователь |
| Выбор после смены взгляда | Серверный луч инструмента использовал интерполированное направление головы. Теперь выбор и проверка препятствий используют один луч по действительным yaw/pitch игрока | Настоящий выбор клетки; новый тест с противоположным headYaw, разворотом и каменным препятствием |
| Сложные формы и двойное сохранение | Разделены рабочий выбор, источник, линия и черновик; сервер проверяет UUID, версии, порядковый номер и уникальный ID запроса. Черновик не стирается чужим обновлением | Внутренние тесты повторов/версий; в клиенте Esc → Остаться → Отмена формы и сохранение с ACK |
| Рычаги | Простые связи создаются сразу без пустого группового правила; источник закреплён, следующие цели добавляются к нему. Сохранены ANY/ALL, признаки источников, порядок и задержка 70 тиков | Серверные тесты связей и правил; полный ручной маршрут 1→3 ещё проверяется |
| Фонари | Автоматическая регистрация UUID-узлов, отдельные поля имён фонаря и линии, явные направления и пары. Переименование линии обновляет выбранную линию инструмента, следующий LINK не создаёт старую | Серверные тесты сети и переименования; настоящие переходы A→B→A и A→C→A ещё проверяются |
| Собаки | Скрытие корневой кости теперь скрывает потомков; состояние заново применяется при каждом рендере конкретной сущности, включая возврат visible=true | Реальное исчезновение собаки 91007 после Save при сохранённой клетке; все три ID/повторный вход ещё проверяются |
| События | Два упорядоченных списка принадлежат UUID, сохраняются явно и исполняются только после реального изменения состояния. OP4 проверяется на сервере | Серверные тесты событий, прав, порядка и сохранения; клиентский редактор ещё проверяется |
| Диагностика | Явные статус, session ID, ACK и действительные пути. Локальная кнопка открывает только проверенную клиентскую папку, не путь удалённого сервера | Тесты записи/автоостановки/экспорта; отдельный сервер с клиентом ещё проверяется |

Исходная v10 также проверена отдельным QA-зондом на её неизменённом JAR: шесть ожидаемых наблюдений подтверждены, включая отсутствие миграции 90008, недопустимый угол 90002, запрет без нижней опоры, пустую коллизию свободной диагональной лестницы, прерываемую дверь и дублированные UV 90020. Это внутреннее воспроизведение, не ручной прогон всех жалоб. Старый обёрточный отчёт ошибочно ожидал строку PASS вместо `EXPECTED_BASELINE_OBSERVATIONS_PRESENT`; исходный результат зонда сохранён, проверка обёртки исправлена. В настоящем клиенте исходной v10 воспроизведено наложение/обрезка меню при 1280×720 и Auto scale3.

## Миграция и правило двух оград

Номера выведенных типов зарезервированы, не переиспользуются. Registry-алиасы сохранены только для чтения старых предметов и экземпляров; Creative и актуальная галерея их не предлагают. Принудительного обхода всех чанков нет: мигрируются только загруженные корни, сохраняются UUID, положение и совместимые типизированные данные. Заблокированное размещение откладывается с диагностикой, не уничтожается.

| Старый предмет или состояние | Актуальный результат |
|---|---|
| 90008 `builder_tool` | 90009 `composite_builder`, тот же count и совместимый NBT, имя и прежние числовые режимы |
| 90013–90017 `prototype_wall_skin_2/3/4/5/7` | Чётный сохранённый rotation 0/2/4/6 → 90002; нечётный 1/3/5/7 → 90012 |
| Старый 90002 с нечётным rotation | 90012 в том же диагональном направлении, без ответвлений |
| Старый 90012 с чётным rotation | 90002 в том же ортогональном направлении |
| 90018/90019 `prototype_ladder_art_1/2` | 90006, художественный variant0; остальные совместимые свойства и приватные роли SourceClone сохраняются |

Для предмета без сохранённого угла диагональный тип использует диагональное исходное направление, остальные выведенные ограды — ортогональное. Версия миграции корня 1 записывается только вместе с успешной транзакцией. В сундуках и выпавших предметах работает миграция чтения ItemStack; в инвентаре есть дополнительная ленивая проверка.

Правило для новых оград: ровно два пользовательских исполнения — обычное соединяемое с ортогональным поворотом и самостоятельный диагональный столб. У столба соединений нет в обе стороны, в том числе с vanilla wall/fence/pane. Нормальные соединения других соседей сохраняются. 90011 этим правилом не переделан.

## Объекты и сохранённые границы

90003 разрешает размещение любых блоков в выступающей пересекающейся области, но не перезапись настоящего занятого корня. Защита других препятствий, инвентарей, живых сущностей и границ мира остаётся. Коллизия движения не отключена.

У RP-объектов убраны только надписи рендера. CustomName, названия предметов/каталога/HUD, имена фонарей и NPC не стираются. Новые RP-объекты не должны получать визуальные nameplate над моделью.

90006: свободная неподдержанная диагональная лестница имеет коллизию игрока; между двумя действительными монтажными опорами её нет. Добавление/удаление опор, высота и поворот пересчитывают состояние. SourceClone сохраняет согласованную исходную физику и приватную пару; 91069/91086 не заменены этой реализацией.

Обычный клик/разрушение RP проверяет реальные составляющие физики, а при намеренном отсутствии физики — части визуальной геометрии. Декоративный габарит/область удобного выбора инструмента не увеличивают ordinary reach. На сервере пакет RP дополнительно проверяет реальный прицел, препятствия, права и штатную дальность сущностей: Creative6, остальные режимы3; для блоков Creative5/Survival4.5. Другие сущности и vanilla-дальность не изменены.

Занятость анимации отдельна для каждого экземпляра и основана на реальном клипе. Повтор OPEN/TOGGLE/PULSE отклоняется, не накапливается; предусмотренное безопасное CLOSE может ожидать. Сохранены задержка рычага 70 тиков, деревянные ворота 32 и RP-лестница 48. 91094 остаётся однократным импульсом, 91088 — статичным. Для 91030 и 91013 базовая посадка определяется нижней точкой их исходной модели; ручная высота и её сброс относительны этой базе. Другие RP не сдвинуты.

## Галерея и фактическая проверка

Галерея содержит 103 актуальных типа: 11 архитектурных, 69 RP-объектов, 18 настоящих NPC, четыре неразмещаемых RP-предмета и 90009 в рамках. Ещё 18 экземпляров составляют стенд функций: всего 121 экспонат. NPC сохраняются с NoAI и PersistenceRequired, не заменены яйцами. Все 121 UUID найдены в действительно сохранённых chunk/entity NBT; выведенных архитектурных типов нет.

Платформы построены по действительной горизонтальной физике, при её отсутствии — визуальному габариту. По каждой стороне добавлены два блока с округлением наружу; между ближайшими краями соседних платформ два блока. Рычаги имеют сохранённые связи с тремя настоящими целями, лампы — A↔B/A↔C, средняя стендовая клетка скрывает собаку. Есть примеры трёх монтажных плоскостей, высоты, обоих вариантов оград и свободной/поддержанной лестницы.

Первый вход обеспечивает vanilla datapack: Creative, выдача 90009 и точка `[0.5,64,-5.5]`. Читы включены в level.dat. Рабочий сохранённый мир не требует генератора или QA-мода. Серверное повторное открытие с текущим SHA завершилось штатным exit0; чтение диска подтвердило 103 типа/121 UUID, Creative и allowCommands1. ZIP выдачи упакован полностью: 24 файла, исключён только `session.lock`. CRC и SHA256 каждого распакованного файла совпали. Настоящее повторное открытие распакованной копии с ordinary JAR из папки выдачи также завершилось exit0, после сохранения найдены все 121 UUID. SHA256 ZIP: `ffafb1986e291a1db0f266dbb18383499535a9671dd175129a7e399831ec9a3e`.

147 обязательных native GameTests и 21 проверка транзакций прошли на Java17; 14 прицельных тестов тоже прошли. В прицельном наборе 13 сценариев повторяют затронутые проверки полного набора, один новый проверяет именно обычные предметы 91030/91013: нижнюю точку исходной модели на поверхности, все восемь углов, смещение .25, сброс и типизированное сохранение UUID/Pos без двойного применения. Всего 148 различных серверных сценариев, не 161. Отдельно прошёл `BuilderUndoChecks` для ограниченного двадцатью записями журнала и конфликтов чужого редактирования. Эти тесты не являются проверкой мыши/GUI человеком. Точные клиентские наблюдения находятся в `reports/REVIEW_90009_CLIENT_INPUT_OBSERVATIONS.json`. Исторические отчёты v10 не используются как PASS новой сборки. Предупреждение об отсутствующем optional ReachEntityAttributes в минимальном профиле не стало обязательной зависимостью и не помешало обычному запуску.

На отдельном ordinary-сервере из распакованного ZIP, без QA и клиента, публичные команды `bb diagnostics start`, `status`, `mark` и `export` действительно записали 60.0357086с и 1201 серверный тик. Сеанс автоматически завершился с `AUTO_DURATION_EXPIRED`; метка сохранена, ошибок0, реальный ZIP проверен по CRC и содержит хеш точного JAR. Клиентские пакеты0 и явно `NOT_MEASURED_NO_CLIENT_BATCHES`: это не доказательство клиентской кнопки, связанного client ZIP или сравнения нагрузки. Сами отчёты и диагностический ZIP включены в evidence выдачи.

## Незакрытые проверки

Актуальный остаток: полный return/independence/reentry трёх клеток; остальные случаи рычагов/ANY/ALL; OP4 события; unloaded/cooldown фонарей; отдельный сервер с клиентом и два настоящих игрока; полный набор GUI1280/1920; геометрия, движение, reach, busy spam и сравнительная нагрузка. Модификаторы с колесом требуют ручного ввода: автоматизация не удерживает их вместе с прокруткой. По последнему указанию пользователя игровые проверки завершены, Minecraft сохранён/закрыт, Computer Use сброшен. Подготовлен точный маршрут `docs/REVIEW_90009_VISIBLE_CHECKS.md`. Полная пользовательская сборка, ресурс-пак и Kappa не тестировались; совместимость с ними не объявляется доказанной.

Резервная копия старого мира перед установкой обязательна. При отказе миграции сначала сохранить диагностический отчёт и проверить причину, не удалять проблемный корень. Не накладывать второй RP JAR поверх combined-мода. Итоговый статус должен учитывать все оставшиеся обязательные проверки, а не только успешную компиляцию.
