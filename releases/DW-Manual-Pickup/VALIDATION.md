# Проверка Manual Pickup 1.0.0

Дата: **1 ноября 2026 года**. Целевая версия подтверждена по текущему реестру
сборки DreamWalker (`.local/modpacks/CURRENT.json`) и отдельным инвентарям
клиентских и серверных модов: **Minecraft 1.20.1 / Fabric**, в обоих наборах
присутствует **Fabric API 0.92.12+1.20.1**.

## Среда и команды

Windows, JDK 17, Gradle 8.10.2, Fabric Loom 1.6.12,
Fabric Loader 0.16.10, Yarn 1.20.1+build.10, Fabric API 0.92.12+1.20.1.
Все файлы сборки, зависимости и тестовые миры находятся под `D:\DreamWalker`.
Проверки запускались после `Assert-Workspace.ps1` и `Initialize-Environment.ps1`.

```powershell
gradle -p DW-Manual-Pickup build sourceZip --offline --max-workers=1
gradle -p DW-Manual-Pickup compileClientqaJava runGametest --max-workers=1
gradle -p DW-Manual-Pickup runClientqa sourceZip --offline --max-workers=1
```

## Результаты

**Сборка: PASS.** Выпущен remapped JAR для установки в Fabric, отдельно
`-sources.jar` и полный ZIP проекта, включая исходники тестовых драйверов.

**Настоящий GameTest-сервер: 10/10 PASS.** Проверены:

1. Отсутствие автоподбора стоя и при удержании приседания.
2. Только ближайший стак за запрос; состояние приседания сохраняется.
3. Обычные горизонтальные и вертикальные границы области подбора.
4. Задержка подбора и ограничения владельца предмета.
5. Заполненный инвентарь без потери предметов.
6. Частичный подбор одного стака без затрагивания второго и без дублирования.
7. Пустой запрос не сохраняет разрешение на будущий подбор.
8. Раздельные разрешения для двух игроков.
9. Серверный лимит запросов отдельно для каждого игрока и его обновление.
10. Запрет подбора наблюдателю.

Машиночитаемый результат: [gametest-results.xml](evidence/gametest-results.xml).

**Настоящий клиент Minecraft со встроенным сервером: PASS.** Тестовый драйвер
создаёт отдельный мир и подаёт синтетические события GLFW в настоящие
`Keyboard.onKey` и `Mouse.onMouseButton`. Подбор идёт через обычное Fabric-соединение
и серверный обработчик; проверяются инвентарь и состояние приседания на сервере.
Для основной проверки это не прямой вызов функции подбора из теста.

Подтверждены стояние без подбора, первое нажатие Shift, 15 событий автоповтора без
дополнительного подбора, отпускание и повторное нажатие, сохранение приседания
на клиенте и сервере, Shift в инвентаре, переназначение приседания на свободную
клавишу и кнопку мыши, наблюдатель на реально подключённом игроке, переключение
приседания одним нажатием и подбор как при включении, так и при выключении
переключаемого приседания.

Итог: [pickup-client-qa.txt](evidence/pickup-client-qa.txt).
Кадр завершившегося сценария: [pickup-qa.png](evidence/pickup-qa.png).
Тестовый клиент автоматически закрыт после проверки.

**Артефакты: PASS.** Проверены целостность ZIP/JAR, Java class major 61 (Java 17),
версия и зависимости в `fabric.mod.json`, наличие remapping/refmap,
отсутствие тестовых модов внутри устанавливаемого JAR и наличие исходников
обоих тестовых драйверов в ZIP. См. [artifact-inspection.json](evidence/artifact-inspection.json)
и [SHA256SUMS.txt](SHA256SUMS.txt).

## Границы проверки

Игровые проверки проведены в отдельной Fabric dev-среде с этим модом и Fabric API.
Весь текущий клиентский/серверный модпак целиком не запускался; отдельный
многопользовательский прогон с подключёнными клиентами на выделенном сервере
не выполнялся. Устанавливаемый remapped JAR проверен структурно; игровые тесты
исполняют те же исходники через dev runtime Fabric Loom.

Область поиска воспроизводит ванильную `PlayerEntity.tickMovement`, включая
транспорт; перенос вещей выполняет ванильная `ItemEntity.onPlayerCollision`.
Имена и контракты сверены с [Yarn 1.20.1+build.10](https://maven.fabricmc.net/docs/yarn-1.20.1+build.10/net/minecraft/entity/ItemEntity.html);
настройка GameTest следует [Fabric GameTest API](https://github.com/FabricMC/fabric/blob/1.20.1/fabric-gametest-api-v1/src/main/java/net/fabricmc/fabric/api/gametest/v1/FabricGameTest.java).
