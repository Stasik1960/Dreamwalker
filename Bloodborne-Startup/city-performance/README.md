# Bloodborne v22.1 City Performance

Клиент больше не включает служебные `composite_cell` в списки BlockEntity для отрисовки штатным рендерером DreamWalker. Геометрия, коллизии и данные владельцев по-прежнему доступны игровым системам. Проверка матрицы камеры сохраняет исходные допуски для пакетного рендера и обходится без двух временных массивов на объект.

При загрузке секции сервер ищет осиротевшие части только тогда, когда палитра содержит рецепт, которому действительно нужна проверка корня. Самостоятельный статический блок уже содержит корень в собственном состоянии.

На исходной карте анализ палитр нашёл 13 380 секций со статической архитектурой. Из них 4 333 (32,4%) можно пропустить на этом этапе. Это 17,75 млн обращений к ячейкам за один полный обход всех сохранённых секций обоих измерений. Для проверки подсчёта используется `audit_section_scans.py`.

## Сборка

`package.py` компилирует три mixin под Java 17 и добавляет их к точному релизу `v22-bloodborne-bush-restoration-editing-fix.1`. Скрипт проверяет SHA-256 исходного JAR и побайтовое совпадение всех его записей, кроме метаданных Fabric. На вход нужны JDK 17+, Python 3.11+, Minecraft 1.20.1 intermediary, Fabric Loader 0.16.10, Sponge Mixin 0.8.7, MixinExtras 0.5.0 и JOML из окружения Fabric.

```text
python package.py Editing-Fix.jar City-Performance.jar --dependency minecraft-intermediary.jar --dependency fabric-loader.jar --dependency sponge-mixin.jar --dependency mixinextras.jar --dependency joml.jar
```

## Проверка

`run_client_qa.py` запускает один и тот же автоматизированный маршрут из трёх неподвижных ракурсов на копии переданного мира. Скрипт использует подготовленный профиль Fabric с `bb-editing-client-qa.jar`. `run_server_qa.py` открывает отдельную копию карты в Fabric dedicated server, проверяет указанные блоки в сохранённых измерениях и ждёт штатного сохранения.
