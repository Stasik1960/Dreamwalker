# Как создавать и настраивать языки DW Languages

Этот гайд относится к **DW Languages 0.1.0**. Ниже описан синтаксис, который реализован в моде. Некоторые возможности оригинальных Gen и SCA² сюда не входят.

## 1. Где редактировать

На сервере откройте:

```text
config/dw_languages/languages/orc.json
config/dw_languages/languages/elf.json
```

Это рабочие настройки. Файлы в `src/main/resources/languages/` репозитория — встроенные примеры для первого запуска; правка там не меняет конфиг уже работающего сервера.

1. Сделайте копию редактируемого файла вне папки `languages` либо с расширением `.bak`. Две копии `.json` с одинаковым `locale` вызовут ошибку загрузки.
2. Откройте файл в текстовом редакторе, например VS Code или Notepad++.
3. Сохраните изменения в UTF-8.
4. Выполните `/lang reload` от администратора.
5. Выберите язык и проверьте речь с игроком, который его **не знает**. ГМ, администратор и сам знающий язык отправитель увидят оригинал.

Изменения не перезаписываются при перезапуске. Примеры создаются только при отсутствии всей папки `languages`. Ошибка при `/lang reload` оставляет предыдущий набор языков действующим; исправьте файл и повторите команду. Перед перезапуском исправьте ошибочные JSON: при некорректных настройках старт языкового мода завершится ошибкой.

## 2. Полный пример

Можно сохранить этот файл как `dwarf.json`, выполнить `/lang reload`, затем `/lang add Steve dwarf`. Игрок выбирает `/lang dwarf`.

```json
{
  "locale": "dwarf",
  "name": "Дварфский",
  "enabled": true,
  "unicode_normalization": "NFC",
  "salt": "dwarf-v1",
  "categories": {
    "C": "ptkbdgmnr",
    "V": "aou",
    "R": "rl",
    "S": "ptk",
    "Z": "bdg",
    "M": "mn"
  },
  "syllables": ["CVC", "CRVC", "CV"],
  "max_syllables": 3,
  "rewrite_in": {},
  "rules": [
    "S/Z/V_V",
    "[sm]//_#"
  ],
  "orthography": {
    "aa": "â",
    "oo": "û"
  },
  "exceptions": ["Minecraft", "Стив"]
}
```

Следующие фрагменты в гайде показывают отдельные поля. Их нужно подставлять внутрь существующего объекта, а не добавлять второй JSON-объект в конец файла.

## 3. Что означают поля

Это **ключи JSON**, а не игровые теги. Названия ключей пишутся точно как в таблице, с тем же регистром.

| Поле | Что задаёт | Как редактировать |
| --- | --- | --- |
| `locale` | Уникальный код языка для команд и знаний игроков | Например, `orc`, `elf`, `dwarf`. Начинается с маленькой латинской буквы; далее маленькие латинские буквы, цифры, `_`, `-`. До 32 символов. |
| `name` | Название в сообщениях: `[Дварфский]` | Можно писать по-русски. До 64 символов, без квадратных скобок, `&`, `§` и управляющих символов. Скобки мод добавляет сам. |
| `enabled` | Включён ли язык | `true` или `false`, без кавычек. По умолчанию `true`. |
| `unicode_normalization` | Обработка одинаково выглядящих символов Unicode | Оставьте `"NFC"`. Также поддерживается `"NFD"`, разделяющий букву и диакритику. |
| `salt` | Дополнительная строка для получения постоянного словаря | Например, `"orc-v1"`. Смена строки меняет генерацию слов. Если поле отсутствует, используется `locale`. |
| `categories` | Наборы букв, из которых собирается речь | Объект вида `"V": "aeiou"`, `"C": "ptkbdg"`. Обязательное поле. |
| `syllables` | Шаблоны, по которым собираются слоги | Массив строк: `["CV", "CVC", "CRV"]`. Обязательное поле. |
| `max_syllables` | Верхний предел числа слогов в слове | Целое число от 1 до 8. По умолчанию 4. |
| `rewrite_in` | Простые замены после генерации, перед звуковыми правилами | Объект замен, например `{"sh": "š"}`. Можно оставить `{}` или убрать поле. |
| `rules` | Последовательные звуковые изменения | Массив строк с правилами. Можно оставить `[]` или убрать поле. |
| `orthography` | Последние замены для написания результата | Например, `{"š": "sh", "aa": "â"}`. Можно оставить `{}` или убрать поле. |
| `exceptions` | Исходные слова, которые не нужно преобразовывать | Например, `["Minecraft", "Стив"]`. Сравнение без учёта регистра. Можно оставить `[]` или убрать поле. |

`locale`, `name`, `categories` и `syllables` обязательны. Коды `off`, `common`, `list`, `reload`, `add`, `del` зарезервированы. Имя файла само по себе код языка не задаёт: команда использует `locale`.

**У существующего языка обычно меняйте `name`, категории и правила, сохраняя `locale`.** Знания и выбранный язык игроков привязаны к коду. После переименования кода новый язык нужно выдать заново. Смена `salt`, категорий, шаблонов или правил может изменить уже знакомые игрокам иностранные слова.

## 4. Как получается иностранное слово

Мод выполняет шаги в таком порядке:

1. Исходное слово определяет постоянную последовательность выборов с учётом `locale` и `salt`.
2. Из `categories` и `syllables` собирается новое слово.
3. Применяются замены `rewrite_in`.
4. Применяются строки `rules` сверху вниз.
5. Применяются замены `orthography`.
6. Восстанавливаются заглавная первая буква или написание целиком заглавными.

**Правила работают с уже сгенерированным словом.** Например, `a/o/_` меняет `a` в иностранном слове. Это не инструкция заменить русскую «а» в исходном сообщении.

При неизменных настройках одно исходное слово даёт одинаковый результат независимо от фразы и перезапуска сервера. Это генерация вымышленной речи; поле для ручного словаря вида «мясо → gruk» в этой версии не предусмотрено.

## 5. Категории: что такое C, V, R и другие буквы

```json
"categories": {
  "C": "ptkbdgmn",
  "V": "aeiou",
  "R": "rl"
}
```

| Обозначение | Обычное назначение | Значение в примере |
| --- | --- | --- |
| `C` | Согласные | Одна из `p`, `t`, `k`, `b`, `d`, `g`, `m`, `n` |
| `V` | Гласные | Одна из `a`, `e`, `i`, `o`, `u` |
| `R` | Плавные согласные | `r` или `l` |
| `S`, `Z` | Две соответствующие группы для замен | Например, глухие `ptk` и звонкие `bdg` |
| `F` | Отдельная группа гласных | Например, `ie` |
| `M` | Группа для удвоения или других правил | Например, `mn` |

Назначение букв условное: мод не знает, что `V` обязана содержать гласные. Вы сами определяете каждый используемый набор. Имя категории — **одна заглавная латинская буква A–Z**; `Vowels` или русская `С` вместо латинской `C` не подходят.

Каждый символ набора — отдельный вариант. `"C": "sh"` означает выбор между `s` и `h`, а не единый звук `sh`. Для диграфа можно использовать одну букву, например `š`, и затем `"š": "sh"` в `orthography`.

Используйте строчные буквы внутри наборов. Допустима кириллица, например `"C": "кгртбдмн"`, `"V": "аоу"`; имена категорий остаются латинскими. Для букв с ударениями удобнее готовые символы `á`, `ë`, `š`, чем отдельные комбинируемые знаки.

Выбор равномерный по позициям строки. Повторение буквы повышает её частоту: в `"V": "aaou"` шанс выбрать `a` составляет половину. В категориях для поштучных замен лучше не повторять буквы: соответствие определяется по первой позиции найденной буквы.

## 6. Шаблоны слогов и длина

```json
"syllables": ["CV", "CVC", "CRV"],
"max_syllables": 4
```

При категориях из предыдущего раздела:

| Шаблон | Структура | Возможные слоги |
| --- | --- | --- |
| `V` | Гласная | `a`, `o` |
| `CV` | Согласная + гласная | `ka`, `mu` |
| `CVC` | Согласная + гласная + согласная | `kat`, `mog` |
| `CRV` | Согласная + `r/l` + гласная | `kra`, `plo` |
| `CVCC` | Гласная между одной и двумя согласными | `gakt`, `munt` |

Шаблон выбирается отдельно для каждого слога. Повтор шаблона в массиве повышает его частоту: `["CV", "CV", "CVC"]`. Строчная буква внутри шаблона вставляется буквально: `CVn` всегда заканчивается на `n`. Все заглавные буквы шаблона должны быть объявлены в `categories`.

Число слогов зависит от длины нормализованного исходного слова: длина делится на 3 с округлением вверх, затем ограничивается `max_syllables`. При `NFC` обычное слово длиной 1–3 буквы даёт один слог, 4–6 — два, 7–9 — три. Это предел числа **слогов**, а не букв результата.

Для более мягкого звучания начните с `CV`, `V`, `CRV` и согласных `lmnsfv`. Для более грубого — с `CVC`, `CVCC`, `CRVC` и `kgrtdbm`. Это настройки звучания, а не встроенные режимы мода.

## 7. Как читать правила

Общий вид:

```text
X/Y/L_R
```

«Заменить **X** на **Y**, если слева **L**, а справа **R**». Само окружение не заменяется. Пустые `L` и `R` означают отсутствие ограничения с соответствующей стороны.

| Запись | Значение |
| --- | --- |
| `a/o/_` | Заменить `a` на `o` везде |
| `k/g/V_V` | Заменить `k` на `g` между двумя гласными |
| `s//_#` | Удалить `s` в конце слова |
| `/j/_kt` | Вставить `j` непосредственно перед `kt` |
| `k/s/#_` | Заменить `k` на `s` в начале слова |
| `u/o/_#` | Заменить `u` на `o` в конце слова |

**Не вставляйте пробелы внутрь правил для красоты.** Пишите `k/g/V_V`, а не `k / g / V_V`: пробелы не игнорируются.

Примеры далее показывают результат применения правила к условному **уже сгенерированному** слову. Отправка этого слова в чат сначала запустит генерацию и поэтому не обязана дать такой же результат.

### Основные обозначения

| Символ | Где применяется | Значение |
| --- | --- | --- |
| `_` | В окружении | Место совпадения; ровно один `_` в каждом окружении |
| `#` | В окружении, вне `[]` | Слева — начало слова, справа — конец |
| `V`, `C` и другие категории | В цели и окружении; особый порядок в замене | Одна буква из объявленного набора |
| `[ie]` | В цели или окружении | Любая одна из перечисленных букв |
| `(C)` | Только в окружении | Необязательная часть: присутствует либо отсутствует |
| `…` | Только в окружении | Любое количество символов, в том числе ноль |
| `²` | После категории в цели; в замене | Повтор той же буквы / предыдущего элемента |
| `\` | Вся правая часть замены | Перевернуть найденный фрагмент; в JSON записывается как `\\` |

### Замены и удаления

```json
"rules": [
  "k/g/V_V",
  "[sm]//_#"
]
```

При `V=aeiou` первое правило превращает `aka` в `aga`. Второе удаляет конечные `s` или `m`: `tamos` → `tamo`, `taram` → `tara`. Пустая замена между двумя слешами означает удаление.

### Вставки

```json
"rules": [
  "/j/_kt",
  "/a/#_",
  "/n/_#"
]
```

Это вставка `j` перед `kt`, добавление `a` в начало и `n` в конец. Вставляется буквальная строка: для случайной согласной используйте генерацию слогов, а не `/C/_` — такая вставка категории не поддерживается.

### Поштучные замены категорий

```json
"categories": {
  "V": "aeiou",
  "S": "ptk",
  "Z": "bdg"
},
"rules": ["S/Z/V_V"]
```

| Исходная буква из S | Буква с тем же номером из Z |
| --- | --- |
| `p` | `b` |
| `t` | `d` |
| `k` | `g` |

Так `apa` → `aba`, `ata` → `ada`, `aka` → `aga`. Это **не случайный выбор из Z**. Если набор замены короче, буквы без соответствующей позиции удаляются. Например, при `Z=bd` буква `k` в подходящем окружении исчезнет.

Можно добавить обычные буквы к замене: `S/Zh/_` даёт `p` → `bh`, `t` → `dh`, `k` → `gh`. Для нескольких категорий в одной цели и замене соответствия берутся по порядку их появления, а не по совпадению названий. Для понятности лучше разбивать сложную замену на отдельные правила.

### Перестановка — метатеза

```json
"rules": ["nt/\\/_V"]
```

После чтения JSON две обратные косые черты становятся одним символом `\`. Правило переворачивает `nt` перед гласной: `anta` → `atna`. Если цель длиннее, переворачивается весь найденный фрагмент.

### Удвоение и сокращение двойной буквы

При `"M": "mn"`:

```json
"rules": ["M/M²/_"]
```

`m` превращается в `mm`, `n` — в `nn`.

Обратный вариант:

```json
"rules": ["M²/M/_"]
```

`mm` превращается в `m`, `nn` — в `n`; сочетание `mn` остаётся прежним. Это два альтернативных примера: если поставить оба подряд, второе правило отменит удвоение первого. Используйте именно знак `²`, а не обычную цифру `2`.

### Необязательная часть окружения

При `C=ptkbdg`, `F=ie`:

```json
"rules": ["u/o/_C(C)F"]
```

Меняет `u` на `o`, если справа одна или две согласные, затем `i` или `e`: `uti` → `oti`, `upti` → `opti`. Вложенные скобки не поддерживаются.

### Список и дальний просмотр

```json
"rules": [
  "k/s/_[ie]",
  "S/Z/_…V"
]
```

Первое меняет `k` перед `i` или `e`. Второе меняет букву из `S` на соответствующую из `Z`, если где-нибудь справа есть гласная из `V`. Для второго нужны объявленные `S`, `Z`, `V`.

В `…` используется **один символ многоточия**, не три точки `...`. В списке можно использовать категорию, например `[VR]`, если обе объявлены. Границу `#` внутрь списка не помещайте: `[dt#]` в этой реализации не означает «d, t или конец слова».

### Исключение из правила

Добавьте после третьего слеша ещё одно окружение:

```text
X/Y/L_R/исключение_окружение
```

Пример при `F=ie`:

```json
"rules": ["k/s/_F/#s_"]
```

Заменяет `k` на `s` перед `i/e`, **кроме** позиции сразу после `s` в начале слова. Получается `akie` → `asie`, но `skie` остаётся `skie`. Здесь исключение содержит слева `#s`, справа — пустую строку.

## 8. Порядок правил

```json
"rules": [
  "a/o/_",
  "o/u/_"
]
```

Слово `kat` пройдёт цепочку `kat` → `kot` → `kut`. Если поменять строки местами, получится `kot`: правило `o/u/_` уже прошло к моменту появления `o`.

Каждое правило делает один проход по входному для него слову. Вставленный этим правилом текст не обрабатывается им заново в бесконечном цикле. Совпадения цели обрабатываются без перекрытия; для сложных случаев с перекрывающимися фрагментами лучше использовать несколько простых шагов.

Если категория есть в `categories`, но её буквы не встречаются в сгенерированном слове, правило ничего не изменит. Например, объявление `S=ptk` само по себе не добавляет `p/t/k` в речь: они должны появиться из используемых шаблонов и наборов либо предыдущих замен.

## 9. rewrite_in и orthography

```json
"rewrite_in": {
  "sh": "š"
},
"rules": ["š/s/_#"],
"orthography": {
  "š": "sh"
}
```

Условное сгенерированное `asha` станет `aša`, звуковое правило его не изменит, а финальная замена вернёт `asha`. Слово `ash` станет `aš`, затем `as`.

Оба поля выполняют **буквальные замены**, последовательно в порядке записей. Это не регулярные выражения и не синтаксис `X/Y/L_R`: ключ — точная строка, значение — строка замены. Все вхождения заменяются. Для удаления задайте пустое значение `""`.

`rewrite_in` применяется к результату генерации, а не к исходному русскому слову. `orthography` выполняется после всех звуковых правил; категории в ней не раскрываются. Для замены `š` на `sh` пишите пару `"š": "sh"`, а не строку `"š|sh"`.

## 10. Исключения и регистр

```json
"exceptions": ["Minecraft", "Стив", "Берген"]
```

Эти исходные слова останутся как написаны. Исключения относятся к отдельным словам, не фразам. `Стив` не означает автоматически `Стива` и `Стиву` — нужные формы добавьте отдельно.

Пробелы и пунктуация сохраняются. Отдельные числа, обычные ссылки с `http://` или `https://`, упоминания `@Steve`, метки `#tag` и коды форматирования не превращаются в иностранные слова. Слово с цифрами, например `город2`, может преобразовываться целиком.

Для преобразуемых слов сохраняется первая заглавная буква и режим ВСЕМИ ЗАГЛАВНЫМИ. Произвольный смешанный регистр вроде `пРиВеТ` по буквам не воспроизводится. Если правила полностью удалили слово, мод выведет `…`.

## 11. Как не сломать JSON

| Правильно | Частая ошибка |
| --- | --- |
| `"name": "Оркский"` | Одинарные или типографские кавычки вместо `"` |
| `"enabled": false` | `"false"` строкой вместо логического значения |
| `"max_syllables": 4` | `"4"` строкой вместо числа |
| `["CV", "CVC"]` | Нет запятой между строками или лишняя запятая после последней |
| `"rules": []` | Удалены скобки массива |
| `"orthography": {}` | Использован массив вместо объекта |
| `"nt/\\/_V"` | Одиночная неэкранированная обратная косая черта внутри JSON |

- Весь файл — один объект `{ ... }`.
- Между полями и элементами массива ставятся запятые, после последнего — нет.
- Ключи и строковые значения заключаются в двойные кавычки.
- Пишите JSON без комментариев. `//` **внутри строки правила**, например `"s//_#"`, — допустимая часть правила удаления.
- Не дублируйте ключи в одном объекте и `locale` в разных файлах.
- `C`, `c`, латинская `C` и кириллическая `С` — разные символы.
- Не рассчитывайте на произвольные дополнительные поля: например, `dropoff`, `weights`, `dictionary`, `gen` и `sca` не управляют этим модом. Используйте поля из раздела 3.

## 12. Ограничения текущей версии

| Настройка | Ограничение |
| --- | --- |
| Файл языка | До 256 КБ |
| Категории | 1–26 категорий; по 1–128 символов в наборе |
| Шаблоны | 1–32 шаблона; длина каждого 1–16 |
| `max_syllables` | 1–8 |
| Звуковые правила | До 128 строк; длина каждой до 128 |
| Каждый объект простых замен | До 128 пар; ключ 1–32 символа, значение 0–32 |
| Преобразованное слово | До 256 символов на проверяемых этапах |

Полного синтаксиса SCA² и произвольных регулярных выражений нет. В частности, не используйте запись дегеминации `m//²`, разделитель глосс `‣`, правила с `→` вместо `/`, вложенные необязательные группы и генераторные конструкции в шаблонах вроде `C(V)` или `[CV]`. Для сокращения двойной буквы используйте `M²/M/_`; для необязательного слога задайте отдельные варианты шаблонов.

Практичный порядок настройки: сначала `categories` и `syllables`, затем несколько звуковых правил, затем `orthography`. После каждого небольшого изменения выполняйте `/lang reload` и проверяйте одну и ту же подборку слов через незнающего язык персонажа.
