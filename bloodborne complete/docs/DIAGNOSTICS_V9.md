# Диагностика тестовой сборки V9

Подробная запись выключена при обычном запуске. Управление записью и снимками требует прав оператора уровня 2. Диагностика не даёт права редактировать объект.

```
/bb diagnostics start
/bb diagnostics start 60
/bb diagnostics start 60 id 90010
/bb diagnostics start 60 object
/bb diagnostics start 60 object <UUID>
/bb diagnostics start 60 area 16
/bb diagnostics status
/bb diagnostics mark невидим после установки
/bb debug проваливается в пол
/bb diagnostics snapshot упираюсь при подъёме
/bb diagnostics stop
/bb diagnostics export
```

Без длительности запись продолжается 60 секунд и автоматически останавливается. Допустимая длительность — от 1 до 600 секунд. Фильтр `object` без UUID использует объект под прицелом; `area` задаёт область радиусом от 1 до 128 блоков вокруг оператора в текущем измерении. Снимок можно сделать без активной записи. Диагностическое действие строительного инструмента также сохраняет снимок без изменения объекта. Общие события входа, загрузки чанков и сохранения помечаются отдельно от событий выбранного объекта.

Серверный экспорт хранится в папке `dreamwalker-diagnostics` текущего запуска. Клиент сохраняет свой ZIP в папке `diagnostics` текущего игрового профиля при остановке или окончании сеанса. Серверный и клиентский файлы связывает UUID сеанса. Для проверки удалённого сервера нужны оба файла. Сервер не может прочитать локальный клиентский ZIP. Штатные журналы ошибок сохраняют причину, объект и счётчик повторов; обычный отказ установки остаётся событием.

Отчёт содержит ограниченный журнал операций, пометки, снимки, измерения и сведения о среде, включая SHA256 реально загруженного JAR. Полный NBT не записывается. У буферов указаны вместимость, число сохранённых и отброшенных записей. Квантили относятся к указанной сохранённой выборке; среднее и число наблюдений могут охватывать весь сеанс. Если измерений нет, это явно указано.

В клиентском ZIP файл `local-timings.json` хранит до 64 окон замеров и до 128 групп по типу, чанку и участку кода; каждая группа сохраняет до 512 исходных выборок. Число наблюдений и потерь указано отдельно. Эти данные включают замеры, не поместившиеся в сетевой пакет. Окна, итоговые группы и последний частичный интервал описывают пересекающиеся выборки: складывать их как независимую нагрузку нельзя. Полный состав модов остаётся в `runtime.json`; сетевые пакеты содержат краткие сведения о версии, SHA и процессе. Файл `placement-render-acknowledgements.json` сохраняет фактические клиентские модельные цепочки, когда они были наблюдены.

Интервал между показами кадров включает ожидание и синхронизацию. Время подготовки рендера на CPU не измеряет GPU. FPS не позволяет вычислить точный процент нагрузки отдельного блока. Таймеры общих запросов к нескольким объектам помечены как общие; они не приписывают всю стоимость одному типу. Байты собственных измеряемых сетевых каналов не включают весь трафик Minecraft, чанков и DataTracker. В интегрированном мире клиент и сервер используют один процесс Java, поэтому общие память, кэши и паузы GC нельзя складывать.

Команды и смысл данных описаны здесь; результаты фактических запусков и затраты записи приведены в `DIAGNOSTICS_V9_REVIEW.md` и `RP_DIAGNOSTICS_V9.md`, с SHA проверенного JAR и ссылками на первичные отчёты. Отсутствующие измерения и незавершённые проверки обозначены явно. Само наличие этого документа не подтверждает прохождение игровых проверок.
