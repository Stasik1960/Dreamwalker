# Фонари 91063 и линии — prototype.5

Обычный ПКМ открывает меню именно нажатого RP-фонаря. Оно показывает имя источника и только явно настроенные исходящие назначения, каждое один раз. Имена линий и технические UUID не выводятся в меню игрока. Список имеет страницы, прокрутку и полные имена в подсказках. Меню не приостанавливает integrated-мир. Задержка повторного перехода видна в секундах; сервер остаётся источником истины. Ошибка объясняется, правильное меню можно открыть вновь. Esc закрывает меню без выбора, а во время ожидания отправляет отмену серверу.

В строительном инструменте раздел «Фонари» подключается root-контроллером через LampEditor. Оператор уровня2 сначала выбирает исходный экземпляр, затем добавляет один или несколько назначений. Ненастроенные фонари регистрируются через этот интерфейс с изменяемым именем; консольный UUID не обязателен. Новая связь по умолчанию двусторонняя. Выбор «Только от источника» изменяет только эту пару в выбранной линии. Если обратный путь остался по другой явно заданной линии, адаптер сообщает это. Участие в линии не создаёт маршруты между всеми её узлами. Разрыв направления/пары затрагивает только указанную линию; удаление всей линии требует подтверждения в меню. Отмена выбора не удаляет созданные связи.

Сервер проверяет OP2, тип hunterlamp и досягаемость выбранного источника/нового назначения. Источник удерживается в ограниченном серверном выборе30 минут, чтобы игрок мог пройти к нескольким назначениям; выбор относится к UUID экземпляра, не типу/месту. Невыгруженный текущий экземпляр либо ранее подтверждённый выбор необходим для изменения. Подставленный далёкий новый фонарь не регистрируется. Это не новый способ обхода разрешений инструментом. Карта состояния имеет страницы по64 связи и явный полный счётчик; данные для root-формы не являются самостоятельным изменением мира.

Сохранение `bloodborne_rp_lamps.dat` использует Schema2: прежние Nodes/Routes сохранены как совместимый список исходящих маршрутов, дополнительно записаны Lines и Connections с устойчивыми UUID и двумя направлениями. Schema1 V9 импортируется в «Старые маршруты V9» без массового превращения направленных маршрутов в двусторонние. Имена/UUID/направления нескольких линий сохраняются. Пределы256 узлов,128 линий и65536 парных записей позволяют сохранить весь прежний разрешённый V9 граф; прежний лимит4096 был бы недостаточен для старых графов. Новые настройки не переиспользуют UUID удалённого экземпляра.

Фактическое положение зарегистрированного фонаря обновляется при движении/монтажном смещении и загрузке сущности. Хранятся точные X/Y/Z и BlockPos для чанка. При переходе используются UUID и текущее положение найденного экземпляра. Безопасное прибытие сохраняет прежние проверки четырёх боковых мест, жидкостей/опасностей, опоры, свободного объёма, живых сущностей и границы мира. Неподходящее место не выдаётся за успешный телепорт. Освещение и respawn в этой ревизии не изменяются.

Для выгруженного назначения выдаётся временный ticket только небольшому району целевого чанка: максимум9 tickets на запрос,64 ожидающих запроса,200 серверных тиков ожидания. Синхронного принудительного getChunk в обработчике пакета нет. При успехе, отказе, Esc, disconnect, удалении участника и остановке сервера tickets освобождаются. Перемещение назначения во время ожидания переносит ticket без продления исходного срока. Удалённая лампа отличается от ещё загружающейся; загруженный чанк без сохранённого UUID после ожидания даёт отдельную причину. Выгрузка не удаляет связи.

Стабильный API для общего инструмента:

- `LampEditor.selectSource(player, entityUuid)` → `Result(success, reason, view)`.
- `LampEditor.edit(player, Request)`; поля Request: action, sourceLampEntity, destinationLampEntity, lineName, lampName, bidirectional, confirmed. Последний параметр необязателен и по умолчанию false. source=null использует серверный выбор. Новое CONNECT получает bidirectional=true от обычной предустановки GUI.
- Действия: REGISTER, RENAME, CONNECT, SET_DIRECTION, UNLINK, CREATE_LINE, RENAME_LINE, DELETE_LINE, CANCEL. Для UNLINK true удаляет пару; false — только source→destination. DELETE_LINE требует confirmed=true.
- `LampEditor.view(player, entityUuid[, page])` возвращает node, lines, connections, outgoingNames, connectionTotal/page/pageCount. UUID в запросе — UUID RP-сущности; nodeUuid — отдельный внутренний идентификатор узла.
- `LampService.open(player, clickedLamp)` — обычный ПКМ; `entityMoved(lamp)` — обновление исходного экземпляра после монтажа; `cancelTravel(player)` — открытие другого инструмента отменяет ожидание, сохраняя cooldown.

Старые OP2 команды `/bbrp lamp register/rename/remove/list/route` сохранены; старые link/route управляют только совместимой направленной линией V9. Дополнительные команды: `lamp select`, `lamp menu`, `lamp line create/rename/view`, `lamp line connect/direction/unlink <entityUUID> <"имя линии"> [both|oneway]`, `lamp line delete <"имя линии"> confirm`. Команды не заменяют обязательную обычную работу визуального инструмента и меню назначения.

Диагностика записывает регистрацию/переименование, монтажное положение, линию/направление, открытие меню, ожидающий/успешный/отклонённый переход и удаление. Нормальная задержка/небезопасное место — REFUSED, не ошибка повреждения данных. Оpaque token и полный NBT в журнал не попадают; malformed сохранение/пакет получает ограниченную причину. Подробная запись остаётся выключенной по умолчанию.
