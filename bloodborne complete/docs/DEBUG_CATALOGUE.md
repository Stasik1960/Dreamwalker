# Временный каталог типов для повторной проверки

Каталог `src/architecture/resources/bloodborne_dw/debug_catalogue.json` содержит 107 замороженных временных номеров: 7 архитектурных пользовательских типов, 94 типа RP-сущностей, 4 семейства RP-предметов и 2 технических инструмента. Каждый номер состоит из пяти цифр; `finalId:null`. Это номер типа, а UUID остаётся идентификатором конкретного экземпляра. Ориентация, состояние, профиль BASE/ALT и художественный вариант используют один номер типа. Архитектурные registry IDs сохранены, включая `prototype_double_door`, временное имя которого — «Входная дверь».

RP-сущность и её предмет установки/яйцо имеют один номер. Техническая ячейка составного объекта показывает принадлежность основному корню и его UUID, а опора исходной лестницы — владельца пары. Технический свет лампы относится к типу `hunterlamp`; отсутствующий в нём UUID не выдумывается.

`DebugCatalogue.name(Identifier, Text)` и `itemName(ItemStack, Text)` добавляют `[90001]` к стандартному имени. `appendTooltip(Identifier, List<Text>)` и `itemTooltip(ItemStack, List<Text>)` прямо отмечают номер как TEMP. RP переопределяет только стандартное имя сущности `getDefaultName()` и стандартное имя предмета; `CustomName`, UUID, registry ID и typed NBT не меняются. Имена RP берутся из сохранённой исходной локализации. Номер не записывается в NBT.

`DebugCatalogue.debug(ServerCommandSource)` вызывает независимую инспекцию для `/bb debug`. Она выбирает ближайшую доступную RP-сущность в 6 блоках с учётом преграды, затем блок/составной объект. Для сущности выводятся фактические registry ID, UUID, положение, yaw/pitch, RP-состояние, границы физики и выбора. Для составного объекта выводятся основной корень, нажатый носитель, владелец, state, BASE/ALT, активные объёмы, вертикальные авторские объёмы и реальные cached fragments из `CompositeRuntime.instance(...).cells()`. Горизонтально mounted остекление учитывается отдельно. Мировые bounds являются только справочной границей, а не физическим заполнением AABB. Также выводятся число ячеек и кандидаты при перекрытии. Команда не подменяет пользовательские имена.

Подключение к общим entrypoints и архитектурным предметам выполняет основной агент. Минимальная ветка команды: `if (operation.equals("debug")) return DebugCatalogue.debug(source);` до блочного raycast. `initialize()` можно вызвать заранее; все методы сами читают неизменяемый каталог при первом обращении.

`tools/prepare_debug_catalogue.py` проверяет совпадение с уже замороженными назначениями при повторном запуске. `tools/audit_rp_debug_presentation.py` сравнивает 30 исходных RP-файлов с исходным ZIP и неизменяемым архивом V7: 24 файла байтово равны оригиналу, остальные 6 отличаются от V7 только указанными presentation hooks. Ранее принятые два обработчика сохранения исходного NBT и `SourceLegacyPayload` не изменены; 707 ресурсов полного RP JAR байтово равны предоставленным. Исторический `RP_SOURCE_INTEGRATION.json` относится к V7 до этой проверки.

Два новых native GameTest проверяют полноту/уникальность каталога, имена/tooltip и сохранность CustomName, typed item/entity NBT и UUID. Изолированная компиляция Java17 прошла; результат нового полного native прогона фиксируется отдельно основным агентом. Сами номера являются TEMP, окончательная пользовательская приёмка не объявлена.
