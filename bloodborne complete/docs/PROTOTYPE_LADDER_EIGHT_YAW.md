# Ladder eight-pose adaptation

The same `bloodborne_dw:prototype_ladder` identity now has inherited horizontal `facing` plus a `diagonal` flag: NORTH false/true = 0°/45°, EAST = 90°/135°, SOUTH = 180°/225°, WEST = 270°/315°. Variant, BASE/ALT and water properties give **96 ordinary** states. An explicit `source_clone` installation flag adds 96 source-assembly states for a total of **192**; its separate fixed-backing/art compensation contract is described in `SOURCE_LADDER_ASSEMBLY.md`. Ordinary item placement always clears that technical flag. No art variants or final numeric IDs are added.

Original `wood_ladder_02`, `_03`, `_04` JSON, texture bytes, authored nested rotations, UV and element coordinates remain unchanged apart from identifier rebasing. The blockstate JSON maps diagonal and cardinal states to the same source model. Client `DiagonalBakedModel` wraps only the diagonal final baked blockstate model and applies one 45° transform around the cell center, after the already baked cardinal transform. It rotates positions and normals, keeps UV/color/light/tint/sprite fields, and exposes diagonal faces without cardinal neighbor culling. Its cache is per wrapped model and resets naturally on resource reload. ALT replacements use this same final transform.

Rendering may retain original small overhangs. Ordinary collision and selection use a thin source section, rotated and clipped to the one root cell. Source installations preserve the original invisible climbing section's measured 3/16 depth. Odd poses use at most 32 strips; empty corners are real physics/selection gaps. Adjacent decorated blocks are preserved and do not reserve the ladder through a bounding-square overlap test. The existing climbable tag identifies both ordinary and source-installed ladder states.

Cardinal poses need the actual touching backing face. Diagonal poses need both touching backing directions; NORTH+diagonal uses SOUTH and WEST, with the other poses rotated accordingly. Each required face patch is compared with the real collision boxes reaching the support block boundary. Suitable stair back faces work without a full-cube requirement. Half-height slab side faces do not cover a full-height ladder section and are unsupported. Removing either required diagonal backing drops one art-preserving item. An unloaded support is not silently deleted by a neighbor update.

Ordinary placement selects the nearest of eight player-yaw poses. A diagonal pose with only one backing fails; it does not silently substitute a different diagonal. Cardinal placement retains the original clicked-wall fallback when the desired cardinal face is unavailable. Pick/drop retains variant and profile, while a new placement recomputes yaw and water. Failed placement and builder edits preserve original item count and NBT. Shared builder dispatch calls `step45` and validates changes of either facing or diagonal; eight steps return to the exact initial state.

`PrototypeLadderGameTests` now checks all 96 palettes, actual item placements, support and unrelated neighbor behavior, picks/drops, profile toggles, climb detection, source-shaped collision and diagonal corner ray gaps. The earlier resource report is retained as `reports/PROTOTYPE_RESOURCES_CARDINAL_HISTORY.json`; historical runtime reports must remain distinct from new verification results. Client appearance and shader acceptance still require the shared client verification pass.
