# Окна первого набора

Статус: **предложение прототипов, не принятая серия и не массовая миграция**. Используется исходный `bbmc_v15_resource (1).zip`; геометрия, UV, faces и authored pivots сохранены. Числовые ID не назначены. Регистрация и жизненный цикл принадлежат общему composite adapter; `architecture/window/WindowPrototypes.java` содержит только ключи этих двух объектов.

`bloodborne_dw:prototype_wood_window` сохраняет три исходных элемента `wood_window`. Состояние `open=false` — точная исходная поза с углами боковых частей −22.5°/+22.5°. Центральный элемент остаётся неподвижным. В предложенном `open=true` боковые элементы получают дополнительный поворот −45°/+45° вокруг собственных pivots `[-8,0,7]` и `[24,0,7]`; результирующие углы −67.5°/+67.5°. Эта открытая поза не содержится в исходном ресурспаке.

Центральный элемент — непрозрачная панель: все 512 пикселей её UV-области имеют alpha=255. Он сохраняет тонкую физическую преграду в обоих состояниях. Движение боковых панелей меняет их физические области и доступ сбоку, но не создаёт проход через неподвижный центр. Коллизия повёрнутых панелей представлена узкими консервативными полосами шириной до одного model unit, а не сплошным AABB всего окна.

`bloodborne_dw:prototype_thin_window` — неподвижное остекление. `_01`, `_02` и `_03` сохраняются как формы одного registry ID. У `_01` обе faces используют одинаковый рисунок; `_02` имеет другой north UV. `_03` использует UV `_02`, но исходная плоскость сдвинута по Z на −4 units и имеет intrinsic yaw −45° вокруг `[8,9,8]`. Поэтому `_03` нельзя объявлять просто повернутым `_01`. Дополнительный intrinsic yaw не запекается: сохранённая модель уже содержит −45°.

У каждого объекта есть восемь глобальных ориентаций с шагом 45°; вращение применяется ко всему объекту один раз поверх сохранённой исходной позы. Оно не создаёт новые пользовательские ID. Исходный north transform для базовых окон — blockstate yaw=180; обычные source повороты сохраняют north=180/east=270/south=0/west=90. Нестандартные source selectors `_03` записаны отдельно в отчёте и не заменяются этим обобщением.

Обе исходные faces тонкого окна сохранены без cullface. PNG, связанные `.mcmeta` и emissive companions копируются побайтно в собственный namespace. Рендер — CUTOUT с теми же текстурами, без обязательного исходного пакета и без добавления зависимости для прозрачности. ALT wrappers изначально наследуют BASE и позволяют адресную замену ресурсов; отсутствие ALT artwork не выдаётся за новый дизайн.

Физическая коллизия, selection и essential placement mask описаны отдельно. Essential mask содержит только root. Визуальные/физические области не являются разрешением удалять соседние стены или ограды. Общий adapter обязан сохранять native state/BE при наложении service geometry и отклонять конфликт root без частичной установки. У деревянного окна предложена нижняя опора, включая подходящие неполные shapes. Source thin window не имеет доказанной нижней опоры и пересекает соседнюю кирпичную стену; окончательное правило монтажа остаётся PENDING_REVIEW.

В исходном клиенте Forge 1.18.2 получен отдельный реальный физический эталон: `reports/SOURCE_PHYSICS_CLIENT_ACTUAL.json`. Исходные wood/thin window сохраняют collision/outline своих ванильных stairs carriers; центральное движение через исходное деревянное окно ограничилось 1.199999988 м вместо запрошенных 3 м. Тонкая физика предлагаемого composite window является изменением для review, а не утверждением, что carrier physics исходной карты уже имела такую форму. Открывание боковых элементов также остаётся явным предложением. Эталон не считается ручной или визуальной приёмкой прототипов.

Воспроизводимые средства: `tools/prepare_window_assets.py`, `tools/test_window_assets.py`; свидетельство импорта — `reports/WINDOW_ASSET_PROPOSAL.json`. Офлайн проверка не доказывает click с обеих сторон, item placement/pick/drop, сохранение, очистку частей или видимость обеих faces в игровом клиенте. Для этого нужны отдельные runtime GameTests и обычный итоговый JAR. До этих проверок runtime/client статусы — NOT_RUN.
