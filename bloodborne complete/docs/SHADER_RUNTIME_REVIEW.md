# Isolated Kappa runtime review

The shader check uses the supplied `Kappa_v5.2.zip` and
`Kappa_BB.zip (1).txt` in a fresh full-client profile. The settings are copied
byte-exact under Iris's required `<selected ZIP filename>.txt` sidecar name.
Only the new isolated profile receives `config/iris.properties`; original
downloads and the user's installation remain unchanged.

`prepare_shader_profile.py` disassembles the exact supplied Iris1.7.6 JAR to
verify the configuration keys and sidecar lookup. The supplied42 settings all
match shader source declarations and allowed values. This preparation proves
neither compilation nor active rendering.

The explicit marker generated by `prepare_shader_client_marker.py` enables an
optional QA-only public-API reflection check. Ordinary nonshader markers do not
load or require Iris. The first ready integrated-world tick records Iris's frame
counter; the final observation requires a larger counter, the exact selected
pack, a present pack, enabled shaders, no fallback, an actual
`IrisRenderingPipeline`, a nonnull shader map and `skipAllRendering=false`.
All42 values are independently read from registered live shader options and
compared with the marker derived from the supplied settings. Equivalent numeric
spellings such as `2.00` and `2.0` are recorded and accepted as the same value.

`shouldOverrideShaders` is recorded at the client tick without asserting true.
The exact Iris bytecode returns true only while rendering the world with the
main target bound, so false outside that render phase is valid. Likewise, the
`Creating pipeline` log appears before construction; it alone does not prove
that shaders survived construction. Constructor failures explicitly return a
`VanillaRenderingPipeline` and log shader disabling. Evidence is
`reports/IRIS_1_7_6_PIPELINE_BYTECODE.txt`.

After the process stops, `verify_shader_client.py` verifies the production hash,
all109 selected supplied mod bytes, Iris classes and metadata, shader ZIP and
original settings, explicit marker, live pipeline/options/counter, full console
and normal integrated save/exit. It rejects shader load/compile/link errors,
disable/fallback messages and fatal process errors. Iris may reserialize the
staged configuration or settings after loading; their final hashes are recorded
separately while original bytes and all live effective values are checked.

Successful exercised pipeline construction and rendered frames cover this
derived scene and visited dimension. They do not prove every optional shader
program or unvisited dimension compiled. Manual screenshots, Creative UI,
lighting/art/shadow fidelity and source-shader visual equivalence remain
`NOT_RUN` or pending user review.

Reproduce the explicit marker:

```powershell
python tools/prepare_shader_client_marker.py --shader-pack 'C:/Users/vakir/Downloads/Kappa_v5.2.zip' --shader-settings 'C:/Users/vakir/Downloads/Kappa_BB.zip (1).txt'
```

After the recorded ordinary client run completes, reproduce the independent
audit using its wrapper and exact production JAR:

