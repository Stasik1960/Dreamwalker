# Отдельная сцена для review первого набора

`tools/prepare_first_set_scene.py` воспроизводимо создаёт `tools/first_set_scene_input.json` и `tools/first_set_scene_commands.json`. Подготовка файлов не запускает игру и не пишет мир. QA addon `src/review` собирается отдельным `remapReviewJar`; он не входит в production JAR.

Input описывает 68 цельных объектов семи registry families, объединённых в шесть требуемых групп: двойная дверь; деревянное/тонкое окна; лестница; стенка; дерево; крыша. Размещаются 3 двери, 2 деревянных окна, 3 настоящие формы тонкого окна, 2 крыши, 2 дерева по 18 visual parts, 32 wall modules (восемь материалов, по три low и одному tall), 24 лестничных модуля (3 artistic variants × 8 global orientations). Деревья стоят близко для общего service volume; оригинальный native chest между ними хранит 7 diamonds. Есть отдельные RP tree1 и hunterlamp.

Addon читает только `review-scene-input.json` текущего QA run directory. Он требует `FRESH_FLAT_ISOLATED_WORLD_ONLY`, flat generator, ожидаемое имя `isolated-smoke-world`, координаты ограничены X/Z ±96, Y 63..100. Он не заменяет занятые roots, не вычищает AABB и не запускается повторно при существующем output. Foundation fill ограничен уровнем 63. Все composite roots создаются через атомарный `CompositeRuntime.place`, вместе с корректными UUID и owned helper contributions. Стенки и лестницы размещаются обычным `Item.useOnBlock` от unspawned offline QA ServerPlayer; проверяются yaw и расход ровно одного предмета. Это не ручной gameplay.

`review-scene-output.json` записывает действительное состояние каждого root, профиль, UUID, helper/foreign overlay counts, количество visual parts и побайтно эквивалентный native chest NBT. Ошибка authoring не считается успешным server smoke. `tools/run_final_server.py --scene-input tools/first_set_scene_input.json --extra-mod <review-qa.jar> --commands-file tools/first_set_scene_commands.json --report <отдельный-report.json>` копирует addon input только в новый run directory и прикрепляет его результат к отдельному отчёту. При сборке обычного игрового мира после authoring требуется удалить QA addon и заново открыть/сохранить эту сцену с единственным production JAR и выбранными dependencies.

Начальная точка: `(0,64,0)`. Первый ряд образцов расположен на Z=8, стены на Z=22, крыши на Z=26, деревья на `(24,64,32)` и `(26,64,32)`, лестницы на Z=48. RP control entities: tree1 `(40,64,35)`, hunterlamp `(3,64,3)`. Сцена и открытая поза створок остаются предложением для review; массовая генерация/замена исходного города не выполняется. Текущий authoring guard разрешает только новый flat fixture; перенос ограниченных source components потребует отдельного явного input и проверок исходных cells.

Подготовка и Java17 compile PASS. Actual scene authoring, чистое production reopening и client visual/manual acceptance пока `NOT_RUN`.
