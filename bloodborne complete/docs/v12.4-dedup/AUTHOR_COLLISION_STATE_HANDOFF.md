# Авторские коллизии после объединения новых типов в V12.4

Это дополнение относится только к объектам, перенесённым после исходной V12.
Оригинальные объекты V12, их registry ID, состояния и исключения не изменяются.
Основной [контракт импорта](../COLLISION_IMPORT_HANDOFF.md) остаётся обязательным;
этот документ поясняет новые соответствия состояний для следующего импорта.

Авторский `dreamwalker-collisions.json` для этой работы не предоставлен.
Авторские коллизии не применялись. В текущем коде `CollisionPack` и
`CollisionReplacements` по-прежнему являются parser и точным хранилищем данных;
они сами не подключают замены к движению игрока. Упрощённая рабочая физика новых
объектов и её контур не означают, что авторский экспорт уже встроен.

Перед следующим импортом зафиксировать итоговый commit, SHA-256 combined JAR
и SHA-256 экспорта. Сопоставления читать из **того же итогового JAR**, который
будет установлен клиентам и серверу:

| Ресурс JAR | Что определяет |
| --- | --- |
| `bloodborne_dw/imported-type-aliases.json` | `groups`: основной ID и скрытые совместимые регистрации; `mappings`: точное старое состояние → новое состояние, поворот и локальный сдвиг |
| `bloodborne_dw/imported-stair-types.json` | Какие новые типы являются ступенями с соединениями, а какие — приставными лестницами |
| `bloodborne_dw/imported-stair-legacy-art.json` | Неизменяемый список проверенных исходных визуальных частей старых новых ступеней; не содержит физических коллизий |
| `bloodborne_dw/composite/*.json` | Модель, render pose и текущие простые формы конкретного нового типа |

Номер вида `93028` удобен для таблицы владельца, но ключ экспорта — полный
`registryId`. Имя ванильного носителя в пути не доказывает материал объекта:
в ресурспаке его текстура могла быть заменена.

## Ступени: одно поле `variant` кодирует половину и угол

Для новых типов `ImportedStairBlock` направление и форма являются состояниями
одной регистрации и одного предмета. Независимых мировых свойств `half`,
`shape` и `facing` у этих блоков **нет**. Их смысл определяется таблицей:

| Мировой `variant` | Половина | Форма |
| --- | --- | --- |
| `"0"` | нижняя | прямая |
| `"1"` | нижняя | внутренний левый угол |
| `"2"` | нижняя | внутренний правый угол |
| `"3"` | нижняя | внешний левый угол |
| `"4"` | нижняя | внешний правый угол |
| `"5"` | верхняя | прямая |
| `"6"` | верхняя | внутренний левый угол |
| `"7"` | верхняя | внутренний правый угол |
| `"8"` | верхняя | внешний левый угол |
| `"9"` | верхняя | внешний правый угол |

В старом общем StateManager диапазон `variant` остаётся `0..15`, чтобы читать
сохранённые палитры без потери старых чисел. После преобразования V12.4 новые
ступени используют только `0..9`; числа `10..15` не являются ещё шестью
законченными формами ступеней.

`rotation` — строковое мировое значение `"0".."7"`, шаг 45°. Для ступеней
верхняя часть направлена на восток при `"0"`, юг при `"2"`, запад при `"4"`,
север при `"6"`. Существующие положения 45° (`1/3/5/7`) сохраняются;
автоматические углы для диагонального соседства не вычисляются.

`connections="auto"` означает изменение угла по соседним ступеням с той же
половиной. Новая обычная установка использует этот режим.
`connections="manual"` сохраняет перенесённую статическую форму старого
экземпляра, в том числе изолированный угол. Shift + ПКМ пустой рукой переводит
такой экземпляр в `auto` и вычисляет его текущую форму. Этот режим не создаёт
отдельный рабочий тип. Если авторская замена зависит от `connections`, это
нужно явно записать в согласованном selector; не наследовать её автоматически
на второй режим.

Только `93028`, `bloodborne_dw:source_stairs_polished_deepslate_stairs_bottom`,
имеет дополнительное мировое `trim="false"/"true"`. Это обычная или сохранённая
форма с небольшими декоративными пластинами прежнего `90980`. В descriptor
render poses `0..9` — обычные, `10..19` — с пластинами. **Render pose `10` не
равен мировому `variant="10"`:** правильное состояние — `variant="0"`,
`trim="true"`. Для остальных новых материалов свойства `trim` нет.

Оба вида 93028 доступны одним обычным предметом: в AUTO Shift + ПКМ пустой
рукой переключает накладки. У MANUAL-экземпляра первое действие включает
AUTO, а следующие переключают накладки. Авторский импорт должен учитывать
новое точное состояние после этого атомарного действия.

У предмета копирования могут быть человекочитаемые строки `half` и `shape`
в `BlockStateTag`. Это дополнительные сведения предмета, не независимые
поля мирового BlockState. Не подставлять их вслепую в selector редактора.
Фактическая мировая форма определяется `variant` после миграции.

Для точного сохранения исходных UV установленные старые ступени получают
строковый NBT-ключ `ImportedStairLegacyArt`, например
`bloodborne_dw:source_bamboo_stairs|2`. Он выбирает только заранее проверенную
строку `oldRegistryId|oldVariant` из таблицы итогового JAR. Произвольный путь
модели в NBT запрещён. Таблица сохраняет исходные модели, текстуры, профили,
повороты частей и UV; нормализация положения компенсирует `rotationDelta`,
включая все восемь поворотов и локальный `SourceShift`.

Это только художественная настройка экземпляра/предмета, а не новое поле
BlockState и не selector физики. Она не меняет 200 канонических простых
физических форм и контуров. Исходные части выбираются лишь при совпадении
основного registry ID, функционального `variant` и `trim`. Пока AUTO сохраняет
ту же форму, UV старого экземпляра сохраняются. После автоматического
перехода к другому углу отображается полная каноническая форма этого угла;
ключ остаётся сохранён и снова применяется при возвращении исходной формы.
Копирование и обычная установка сохраняют только проверенный художественный
ключ, не UUID, связи или частные настройки прежнего экземпляра. Стандартный
новый предмет из Creative использует канонические модели без этого ключа.

Не включать `ImportedStairLegacyArt` в контракт авторских коллизий автоматически.
Если автор намерен различать физику двух художественных профилей одного
точного мирового состояния, существующая схема не делает их разными
selector: это требует отдельного согласованного расширения и consumer.

## Приставная лестница

Основной `90586`, `bloodborne_dw:source_hold_ladder_02`, имеет мировое
`height="one"/"two"`. `one` использует pose/`variant="0"`, `two` — pose/
`variant="1"`; при нормализации `height` определяет итоговый `variant`.
Скрытый прежний `90587`, `bloodborne_dw:source_hold_ladder_03`, преобразуется
в основной тип с `height="two"`. Поворот, установленный локальный сдвиг,
вертикальное размещение и подъём сохраняются. Лестницу-ступени и приставную
лестницу не смешивать по похожему материалу.

## Новые типы с банками поз

Некоторым объединённым декоративным типам нужно более 16 поз. Наличие банка
определяется `groups[].poseCount > 16` в актуальном manifest, а не списком
зашитых ID. Их render pose вычисляется так:

`pose = 16 * art_bank + variant`.

Например, pose `18` кодируется мировыми `art_bank="1"`, `variant="2"`.
`art_bank` имеет технический диапазон `0..7`, но законченные состояния
ограничены конкретным `poseCount`. Не импортировать все 128 комбинаций только
потому, что StateManager допускает их. Правило банкинга не заменяет отдельное
кодирование `trim` ступеней выше.

## Старый экспорт и канонический экспорт — разные исходные состояния

Экспорт содержит `source.commit` и `source.release`. По ним сначала установить,
в какой ревизии и по какому каталогу редактировались состояния. Одного совпадения
основного registry ID недостаточно: числовой `variant` существующего основного
ID после объединения может иметь новый смысл.

В сохранениях и предметах V12.4 есть служебный NBT-маркер
`ImportedTypeVersion: 1`. Он позволяет игре отличить уже преобразованный
экземпляр от старого. Это **не** новое обязательное поле selector Collision
Studio. Для авторского экспорта происхождение устанавливается по исходной
ревизии и явной таблице импорта; не дополнять selector этим маркером без
согласованной схемы и consumer.

Если экспорт сделан по старой ревизии, найти точную строку
`oldRegistryId + oldVariant` в `mappings`, затем применить `newRegistryId`,
`newVariant`, `properties`, `rotationDelta` и `sourceShift`. Если экспорт уже
канонический, повторно применять старое соответствие нельзя. Неизвестный
вариант, удалённый объект или неоднозначная исходная ревизия — отдельная
строка «требует решения», а не выбор первого похожего объекта.

Примеры из таблицы новых функциональных лестниц:

| Старый ID и состояние | Основной ID и состояние | Преобразование |
| --- | --- | --- |
| `90323`, `source_brick_stairs_inner`, старый `variant=0` | `90322`, `source_brick_stairs`, `variant=2`, `connections=manual` | нижний внутренний правый угол, поворот и исходная опора сохранены |
| `93029`, `source_stairs_polished_diorite_stairs_bottom`, старый `variant=0` | `93028`, `source_stairs_polished_deepslate_stairs_bottom`, `variant=0`, `trim=false`, `connections=manual` | та же видимая прямая форма |
| `90980`, `source_stairs_dark_prismarine_stairs_bottom`, старый `variant=0` | `93028`, `source_stairs_polished_deepslate_stairs_bottom`, `variant=0`, `trim=true`, `connections=manual` | сохранены декоративные пластины |
| `90587`, `source_hold_ladder_03`, старый `variant=0` | `90586`, `source_hold_ladder_02`, `variant=1`, `height=two` | высокая приставная лестница |

В примерах короткие пути имеют namespace `bloodborne_dw:`. Это примеры, а не
полная таблица: остальные старые варианты могут иметь другой угол и поправку
поворота. Полные соответствия брать из manifest итогового JAR.

`rotationDelta` добавляется к прежнему повороту по модулю 8.
`sourceShift` задан в блоках в канонической локальной системе объекта;
он не является координатой `center` экспортного коллайдера в модельных
единицах. Миграция поворачивает прежний локальный сдвиг на отрицательный
`rotationDelta`, затем прибавляет `sourceShift`. Для авторских коробок отдельно
проверить переход от старой локальной системы к канонической, включая ZYX,
origin, отражение и монтаж. Простое переименование registry ID не доказывает,
что коробки остались на прежнем месте.

Если два старых экспортных состояния сходятся к одному точному каноническому
selector, но имеют разные авторские наборы коллайдеров или сидений, это
конфликт. Не выбирать последний и не складывать наборы. Составить конкретную
пару ID/состояний и получить решение владельца; независимые однозначные
состояния продолжать импортировать.

## Точность selector и проверки следующего импорта

Мировые свойства новых composite-блоков сериализуются строками: `variant`,
`rotation`, `profile`, `open`, `connections`, `height`, `trim`, `art_bank`.
Но selector Collision Studio — самостоятельная точная схема: строка `"false"`
не равна boolean `false`, число `2` не равно строке `"2"`. Согласовать поля
и их типы по экспорту и consumer. Не заменять selector полным BlockState,
не добавлять отсутствующие поля, не вводить wildcard и не переносить BASE → ALT
или закрыто → открыто без явно соответствующей строки.

Для новых ступеней отдельно проверить обе половины, все пять форм, четыре
кардинальных поворота и сохранённые 45°; обычное изменение соседей должно
выбирать замену для **нового** точного состояния. Для `93028` проверить оба
`trim`, для приставной `90586` — обе высоты и поставленные друг над другом
лестницы, для банков — каждую реально импортированную позу.
Изменения состояния, масштаба, монтажа и сдвига должны сбрасывать player-shape
кэш и обновлять поиск пространственных кандидатов.

Сохранять упрощённые исходные коллизии состояний, не перечисленных в экспорте.
Сохранить ранее заданный простой контур новых блоков: проходимым объектам —
один понятный прямоугольник для наведения. Авторский `players_only` импорт
сам по себе не даёт права глобально менять NPC-физику, занимаемые клетки,
правила опоры и выделение.
Не объявлять импорт завершённым без реального движения игрока и проверки
сохранения/повторного входа с одинаковым JAR на клиентах и сервере.

Для оригинальной V12 продолжает действовать исходный контракт, включая
запрет восстановления удалённых `90013–90017`, `90018/90019`, пустую физику
угловой `90006` и специальные правила занятой корневой клетки `90003`.
