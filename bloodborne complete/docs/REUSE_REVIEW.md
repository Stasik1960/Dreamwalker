## Минимальный подтверждённый subset

Заимствуются **контракты и алгоритмы**, а не набор исходных классов со всеми зависимостями. Для prototype достаточно generic координат/форм (`LogicalTransform`, cell clipping/preflight `GeometryRuntime`), sorted persistent ownership (`ArchitecturePartBlockEntity`), strict resource chain and visual-only cache (`LogicalVisualModels`, generation-scoped часть `BloodborneClient`). Renderer helpers берутся только если новые доказанные модели реально выходят за native JSON возможности. Door, seat, lantern attachment, whole-owner compatibility и исторические grid palettes не подключаются заранее.

Новый source set `src/architecture/java/dev/dreamwalker/bloodbornedw/runtime` содержит `ObjectGeometry`, `ObjectInstance`, `CellSnapshot`, `TransactionCore`, `TargetResolver`. В нём нет Minecraft imports, встроенных palettes, пятиричных ID или чужих registry. `CellSnapshot.BlockData` защищает mutable maps/byte arrays копированием. Snapshot BE payload и bindings разделены на уровне интерфейса; будущий adapter обязан сохранить **все** исходные BE поля и сериализовать ownership совместимо.

## Свежие проверки и ограничения

На Java **17.0.20.1** выполнены **18/18** dependency-free transaction checks после компиляции JDK 21 с `--release 17`: whole placement/removal, foreign NBT, shared hit choice/root insertion, injected partial write и notification failures, stale plan, UUID reuse, unloaded owner, support guards, ALT без физического изменения, entity movement, chunk boundary, rotation hook, owner capacity, dimension isolation, obsolete membership и immutable payload. Команда Gradle: `transactionCheck`; main: `dev.dreamwalker.bloodbornedw.runtime.TransactionChecks`. Эти tests не являются проверкой Fabric adapter или in-game действий.

Свежий запуск восьми прежних Python modules: **49 tests**, **46 PASS, 2 FAIL, 1 ERROR**. Все три несоответствия принадлежат `test_contract_v2`: ожидаются 47 семейств вместо 49, отсутствует retired `o_dead_tree_planter`, прежняя fixture ожидает старую rejection classification. Этот модуль не входит в текущие `build.gradle check` tasks. Ошибки сохранены как stale historical fixture; они не замаскированы успешным новым core и не объявлены новой ошибкой source palette. Old projects не исправлялись.

Minecraft adapter для multi-cell transactions **не подключён**. `writeSilently` должен действительно подавлять neighbors/callbacks и побочные drops до commit, exact snapshots должны включать NBT/ownership/воду/ticks, применение и уведомления должны идти на server thread. Byte-for-byte rollback state не отменяет уже отправленные сторонним callback сообщения или spawned entities; до доказанного adapter эти обещания не считаются проверенными. Небольшой native one-cell ladder prototype не требует helpers и не притворяется выполнением этого adapter.

Отдельно обнаружено: все **34** установленные `minecraft:beehive[honey_level=1]` в исходной карте имеют рядом ванильную лестницу с противоположным facing на плоскости декоративной модели. Оригинальный pack меняет `textures/block/ladder.png` на **полностью прозрачный** 16×16 RGBA PNG (75 bytes; alpha=0 всех pixels), не меняя vanilla ladder model/blockstate. Следовательно, исходное строение использует видимую beehive-модель и соседнюю невидимую нативную физическую лестницу. Новый LadderBlock в прежней beehive-клетке требует опору именно в клетке той соседней лестницы, которая не solid: **все 34 same-anchor замены не проходят native support contract**. Подробные координаты/состояния/opacity SHA: `../reports/LADDER_SOURCE_CONTEXT.json`, воспроизводимая read-only команда `python -B -X utf8 tools/audit_ladder_context.py`. Текущая offline Ladder-only fixture не считается успешной игровой миграцией. Для переноса пары нужна доказанная единая принадлежность, явный pivot/translation и новый support contract; ни соседние клетки, ни источник не изменены этим аудитом.

Новый каталог и геометрия спорных объектов ещё требуют исходных доказательств и контрольной игровой приёмки. Полный город, полный пятизначный каталог, массовые ALT/WorldEdit, graphical comparison, packaged new JAR lifecycle, два клиента и нагрузка пользовательской сборки отмечаются отдельно, без переноса старых PASS.

## Официальная API-база

Использованы Yarn **1.20.1+build.10**: [World](https://maven.fabricmc.net/docs/yarn-1.20.1+build.10/net/minecraft/world/World.html), [LadderBlock](https://maven.fabricmc.net/docs/yarn-1.20.1+build.10/net/minecraft/block/LadderBlock.html), [ModelPredicateProviderRegistry](https://maven.fabricmc.net/docs/yarn-1.20.1+build.10/net/minecraft/client/item/ModelPredicateProviderRegistry.html). Дополнительно прочитан локально разрешённый Fabric API source `fabric-object-builder-api-v1 11.1.5+e35120df77`: его registry принимает `ClampedModelPredicateProvider`; поэтому item variant predicate — `variant/2.0`, а не 0/1/2.

Подробные hashes/read evidence: `RUNTIME_BASIS.json`. Все выводы о дефектах callback/rollback являются code-review выводами; их воспроизведение в packaged new Fabric JAR отмечается отдельно.
