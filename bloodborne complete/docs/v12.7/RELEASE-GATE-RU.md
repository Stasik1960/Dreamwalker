# Приёмка и публикация V12.7

Эта страница описывает условия; она не является результатом проверки.
Родительский исполнитель создаёт `acceptance.json` после финальной сборки и
настоящих клиентских/серверных проверок. Порядок: промежуточный commit исходников,
сборка combined JAR, итоговые тесты, принятие доказательств, упаковка, публикация.
При последующем изменении исходников, JAR или принятого доказательства приёмка
и соответствующие проверки обновляются. Ранние FAIL сохраняются как история.

Упаковщик `tools/package_v127_release.py` ожидает JSON:

- `status: "PASS"`, точный `productionJarSha256`, `productionSourceCheckpoint`,
  `baselineCommit`, итоговые `counts` и пустой `currentUnresolvedTestFailures`.
- `evidence`: именованные записи с `path` относительно проекта либо локальным
  абсолютным путём в нём и `sha256`; при упаковке каждый файл проверяется снова.
- `checks`: отдельные PASS для `build`, `gameTests`, `nativeClient`,
  `nativeServerSaveReopen`, `resources`, `manualPlacement`, `worldEdit`,
  `fullConversionPlan`. Специальные пределы проверки отражаются в значении и
  содержимом доказательства, а не скрываются за общей успешной сборкой.
- `checks.physicalMouseKeyboard: "NOT_RUN"`; GUI Blockbench также NOT_RUN, если
  действительно не запускался. `fullOriginalWorldConverted: false` и
  `authorCollisionExport: "NOT_SUPPLIED_NOT_APPLIED"`.

Тест маленького автономного потока конвертации может быть PASS, тогда как
полный оригинальный мир остаётся PREPARE_ONLY/NOT_RUN по указанию владельца.
`fullConversionPlan=PASS` означает отсутствие неразрешённых видимых исходных
ячеек, привязанный поток/исполняемый путь и проверенную маленькую копию;
он не означает уже конвертированную оригинальную карту.

Финальный Blockbench ZIP сверяется с `visual-export/final-delivery-audit.json`.
Runtime plan требует `PASS_COMPLETE_SOURCE_PLAN`, ноль известных видимых gaps,
оба исходных SHA и правильные контрольные суммы всех потоков. Исходные ZIP
повторно хэшируются. Все архивы читаются потоками; проверяются CRC и SHA каждой
записи. Папка `releases/Dreamwalker-BB/v12.7-final` создаётся один раз; прежние
релизы и промежуточная папка после ошибки не перезаписываются и не удаляются.

```text
python tools/package_v127_release.py --validate-only
python tools/package_v127_release.py
python tools/publish_v127_release.py
```

Последняя команда по умолчанию выполняет только preflight. Публикация уже
разрешена владельцем в задании, но запускается родительским исполнителем после
просмотра итоговых файлов:

```text
python tools/publish_v127_release.py --publish
```

Она не делает force push, не заменяет существующий чужой тег/ассет и не
перенумеровывает объекты. Сначала проверяет принятую поставку и неизменность
кода, публикует обычную ветку/неизменяемый тег, создаёт draft GitHub Release и
загружает файлы потоками. Повторный запуск восстанавливает уже законченные
загрузки по имени/размеру/SHA; повреждённый или конфликтующий ассет останавливает
публикацию для разбора. После загрузки draft открывается, каждый публичный
ассет скачивается потоком и сверяется по SHA. Результат сохраняется в
`build/v127-release-publication.json`.

Учётные данные берутся из Git credential helper только в память процесса.
Токен не записывается в файлы, командную строку, отчёт или URL; публичное
скачивание выполняется без Authorization. API используются по
[документации GitHub](https://docs.github.com/en/rest/releases/assets).
