# WorldEdit и блоки Dreamwalker BB

Встроена необязательная интеграция с WorldEdit для Fabric. В настоящем сервере Minecraft 1.20.1, Java 17 проверен WorldEdit `7.2.15+6463-5ca4dff`; без WorldEdit обычный запуск мода сохраняется. Проверки используют официальный Fabric Adapter, настоящего Actor, Parser и EditSession.

Существующие пятизначные номера каталога можно применять в паттернах и масках. Например, после выделения области:

```text
//set 90031
//replace 90031 air
//replace 90031,93233 air
```

Номер выбирает рабочий тип мода. Для обычных модовых блоков доступны их зарегистрированные состояния; RP-объекты устанавливаются через специальный внутренний носитель и сохраняют параметры при копировании целого объекта. Ванильные и чужие блоки проходят штатный путь WorldEdit.

У составного объекта выбор его служебной ячейки удаляет или заменяет целого владельца. Другие владельцы и нативный блок в той же ячейке сохраняются при селективной операции. Undo возвращает исходный UUID, параметры, связи и использованные личные/общие лимиты команд; команды при восстановлении не исполняются. Clipboard создаёт независимый UUID, сохраняя вид и настройки.

Для связанных конструкций согласование действует в пределах одной EditSession и одного смещения вставки. Если скопирован только один член, ссылки на нескопированные объекты остаются их действительными UUID. Когда в этой же операции вставляются остальные члены, внутренняя связь скопированной конструкции заменяется ссылками на их новые UUID. Исходная конструкция не изменяется. Повторная запись служебных ячеек не создаёт лишних событий и не сбрасывает счётчики; сохранённое ожидающее событие имеет один устойчивый номер. После завершения сессии нескопированные внешние связи сохраняются внешними.

Проверено в `tests21`: 127 PASS, 0 FAIL, 0 SKIP, включая три настоящие проверки WorldEdit — составной блок, типизированный RP-объект и связанная конструкция из двух дверей и рычага. Последняя отдельно проверяет частичное копирование, полное согласование, личные/общие счётчики, одну очередь событий и повторную запись helper-ячейки. Числовое редактирование compact-ячеек не создаёт block entity. Контракт памяти WorldEdit проверен на 972 375 состояниях и 1 071 типе, со сравнением упорядоченных Guava Table views и идентичности штатных состояний.

Точные SHA XML, журналов и типизированных доказательств находятся в [worldedit-native-validation.json](worldedit-native-validation.json). Предыдущий реальный FAIL и его причина сохранены в [worldedit-linked-baseline.json](worldedit-linked-baseline.json). Проверенный исходный checkpoint — `d44c8d6f96f0546758532c6eb36213d1866e76e6`, SHA JAR на момент прогона — `cd5236cb01252357d24d7323479adeaaf3b174da52764e95f8e86279675f3bd7`.
