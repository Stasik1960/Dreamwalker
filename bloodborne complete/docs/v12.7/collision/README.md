# Авторские коллизии после V12.7

Встройка через исполнителя по экспорту редактора остаётся возможной для всех
зарегистрированных строительных блоков и размещаемых RP-объектов. Экспорт автора
не предоставлен, замены не применялись. Действующий consumer внешних коллизий
подключается отдельно во время конкретного проверенного импорта; parser/provider
без такого подключения не является применением.

Оригинальная [инструкция](../../COLLISION_IMPORT_HANDOFF.md) сохранена побайтово.
Актуальные ID, состояния, банки поз, совместимые алиасы, представления compact и
типизированный RP-флаг собраны в [target-map.json](target-map.json).
Его полный статус требует `PASS_ACTUAL_NATIVE_BINDINGS`: таблица обогащается
снимком настоящих зарегистрированных StateManager из native GameTest, а не только
наличием JSON. Снимок формируется тестом
`actualCollisionImportRegistryPropertySnapshot` и сохраняется как
`v127-collision-registry-properties.json` в изолированном тестовом мире.

```text
tools/audit_v127_collision_targets.py --native-snapshot build/<actual-test-world>/v127-collision-registry-properties.json
```

Числовые подписи — зарезервированные номера каталога, не Minecraft raw registry
numbers. В редакторе и экспорте нужны точный registry ID и точный типизированный
selector. Палитра Minecraft хранит значения свойств строками, но это не означает,
что все selector поля Studio тоже строки. Старые RP `Open` и `DogsVisible` —
boolean; у 90006 `variant`, `profile`, `diagonal` — строки. Не добавлять весь
BlockState в selector и не угадывать типы остальных полей до чтения экспорта.

У новых банков `logicalPose = art_bank × 16 + variant`. Полные таблицы поз и
действительные диапазоны свойств позволяют однозначно связать прежний/новый ID
и его вид. Номера не перенумеровывались и не переиспользуются. Состояния,
снятые с рабочего каталога, могут существовать ради сохранений; удалённые
регистрации и исключённые варианты не возвращать по старому каталогу редактора.

`legacyPoseCorrespondence` сохраняет точные старые pose-сопоставления, скомпонованные
через V12.7, и отдельно новые копии поз V12.4. При разборе старого экспорта учитывать
версию экземпляра и эти rotationDelta/sourceShift/properties; не применять
преобразование повторно к уже канонической позе. Ненулевой `art_bank` обозначает
текущую полную позу, а не прежнее значение `variant` по его младшим четырём битам.

`BbAltVisual` — новый визуальный boolean RP, NBT BYTE. Прежние selector не
изменять молча: явно сопоставить им BASE (`BbAltVisual=false`). Для ALT требуется
отдельное авторское состояние; автоматическое наследование BASE → ALT запрещено.
Сам новый оттенок физику не меняет.

Точные непрозрачные кубы карты имеют два представления одного типа:
`compact=false` с прежним UUID/NBT владельца и `compact=true` как нативная
палитра без отдельного BE. Их внешний вид и pose совпадают. Будущий player-only
consumer должен охватить оба пути движения игрока, включая нативную палитру.
NPC, установка блоков, опоры и общая occupancy-геометрия сохраняются. Ручное
редактирование высоты материализует только выбранную компактную ячейку в
обычный объект; это не массовая смена представления карты.

Для DW-барьера сохранить проходимость всех сущностей кроме игроков и особые
правила наложения; для DW-света — отсутствие физических коллизий и свет14.
Угловая 90006 по-прежнему без физических коллизий. 90013–90017 и 90018/90019
не восстанавливать. Правила 90003, исходной V12, дверей и разовых привилегий
конвертации/no-collide не менять при импорте player-only коллизий.

Ограничение parser512 моделей/32768 состояний на проект/16MiB — размер одного
частичного проекта, а не запрет на ID. Если экспорт больше, разобрать его на
проверенные части и явно объединить применяемые записи. `register(pack)`
заменяет целый provider; последовательная регистрация отдельных файлов без
объединения потеряет предыдущие записи.

При импорте сохранить source hashes, точную таблицу применённых/отклонённых ID
и selector, OBB с ZYX, деление размера/центра на16 без повторного отражения X,
instance scale/rotation/mount/shift и отдельные сидения. Проверить игру,
открыто/закрыто, BASE/ALT, compact/owner, сохранение, повторный вход и одинаковые
данные клиента/сервера. Отсутствующий selector означает сохранение прежней
физики, а явно reviewed пустой набор — намеренное отсутствие player коллизии.
