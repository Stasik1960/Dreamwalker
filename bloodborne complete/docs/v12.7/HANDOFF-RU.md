# Dreamwalker BB V12.7: продолжение с другого устройства

Репозиторий: [Stasik1960/Dreamwalker](https://github.com/Stasik1960/Dreamwalker),
ветка `codex/bb-v12-tool`. После публикации используйте неизменяемый тег
`bb-v12.7-final`; точный commit и SHA-256 combined JAR находятся в
`release-manifest.json`. База этого этапа —
`0c985dc28e4a38900cce3055ddb5658a71ed95e5`; оригинальная V12 —
`821de077917f696a13600e900a244ffc05230c2f`.

Эта инструкция сама по себе не объявляет проверки успешными. Итоговые статусы,
реальные количества, JAR и доказательства связывает `acceptance.json`.
Упаковщик отказывается работать, пока обязательные проверки не имеют PASS и
их контрольные суммы не соответствуют текущим файлам. Пока acceptance отсутствует
или имеет иной статус, ревизия остаётся промежуточной.

## Состояние задачи и границы следующего запуска

В текущем этапе галерея не создаётся. Полная оригинальная карта **подготовлена
для будущей явной команды владельца**, а не конвертируется автоматически.
Не запускайте полный импорт по одному факту наличия этого документа.
Не изменяйте исходные ZIP. Все операции выполняются над отдельной производной
копией под `bloodborne complete/build/`.

Оригинальные объекты V12, их основной вид, ID, состояния и механика защищены.
Для прежних ALT, визуально совпадавших с BASE, допускается только уже сделанное
цветовое расширение, прямо затребованное владельцем. Номера не перенумеровываются
и не переиспользуются. Старые регистрации клонов остаются скрытыми переходниками
с точным соответствием состояний. Не возвращайте удалённые повреждённые,
ванильные и намеренно исключённые варианты.

На исходном устройстве действует локальный режим C:. Миграция на E: приостановлена
владельцем; старые копии не являются основанием продолжать перенос. На другом
устройстве сначала прочитайте его актуальные AGENTS.md и ограничения хранения;
абсолютные пути исходного компьютера переносить не нужно.

## Файлы поставки

- Combined JAR — рабочий мод; требует Minecraft 1.20.1, Java 17, Fabric Loader
  0.16.10, Fabric API 0.92.9+1.20.1 и GeckoLib 4.4.9. Исходный ресурспак не нужен.
- `*-sources.jar` и `*-full-source.zip` — исходники, ресурсы и инструменты сборки.
  Полный архив сохраняет каталог `bloodborne complete/`; кеши, миры, галереи и
  большие промежуточные проекции исключены.
- `Dreamwalker-BB-V12.7-New-Blockbench-Assets.zip` — редактируемые проекты новых
  объектов, точные модели и зависимости. Оригинальная V12 исключена. Отдельный
  GUI Blockbench не считается проверенным без соответствующего результата.
- `Dreamwalker-BB-V12.7-Original-Conversion-Plan.zip` — сжатые потоки нативных
  палитр, отдельных владельцев, целых конструкций и типизированных сущностей.
  Распаковать `v127-runtime-conversion/` в `bloodborne complete/build/`.
- `verification.zip` — финальные отчёты, XML GameTests и принятые доказательства.
  `SHA256SUMS.txt` и `ARCHIVE-CONTENTS.json` проверяют файлы и содержимое архивов.
- `ORIGINAL-INPUTS.json` — неизменяемые ссылки и SHA-256 исходных ZIP. Эти ZIP
  повторно не включаются в архив исходников.

## Получение исходников и входных данных

```text
git clone --branch bb-v12.7-final https://github.com/Stasik1960/Dreamwalker.git Dreamwalker
cd Dreamwalker/bloodborne complete
```

При работе в PowerShell используйте `Set-Location -LiteralPath '.../bloodborne complete'`.
Входные архивы должны находиться относительно корня репозитория здесь:

| Вход | Путь | SHA-256 |
| --- | --- | --- |
| Мир v16 | `Bloodborne-Blocks/reference-inputs/bbmc-v15-v16/bbmc_v16_map.zip` | `39e83f2941b768fd2ae9f84d8f57dc76aec78bd926dc5e38eab3059251d2bb08` |
| Ресурспак v15 | `Bloodborne-Blocks/reference-inputs/bbmc-v15-v16/bbmc_v15_resource.zip` | `29b31e3744af5794ae95ebe4c5474e3b70dfb08c143355bce815c08ceef09a36` |

Проверьте SHA-256 перед любым анализом. Оригинальные ZIP открываются только для
чтения. На другом компьютере подходят обычный Python 3.11+ с NumPy и Pillow и
Java 17. Инструменты полной конвертации используют пути относительно исходников.

Обычная сборка: `gradlew.bat --no-daemon build compileGametestJava` на Windows;
`./gradlew --no-daemon build compileGametestJava` на других системах. Сначала
сохранить промежуточный commit, затем собрать, затем провести итоговые игровые
проверки. Не объявлять успешную сборку игровым PASS.

## Полная конвертация после отдельной команды владельца

Сначала прочитать `conversion/full-conversion-plan.json`,
`conversion/full-conversion-known-gaps.json`, отчёты по исходным сущностям и
`source-removal-coordinates.jsonl.gz`. Последний файл содержит измерение,
координаты, исходное состояние и причину удаления. Непрозрачные неизвестные,
системные и удалённые владельцем объекты не подменять придуманными моделями.
Подтверждённые исходные пропуски и намеренные исключения перечислять отдельно
от ошибок мода. У особо спорных мест запросить решение по точным координатам/ID.

Готовый поток принимается только при `PASS_COMPLETE_SOURCE_PLAN` и
`knownVisibleGaps=0`. Если файл или исходники изменились после публикации, план
пересоздаётся: сначала `tools/v125_map_index.py`, затем
`tools/v127_prepare_full_conversion.py --plan build/v127-full-conversion.sqlite`,
затем `--export-runtime build/v127-runtime-conversion`. Это чтение исходного ZIP
и подготовка данных, а не запись мира. Не запускать генераторы дополнительных
поз или перезаписывать модели при обычном повторном импорте принятой ревизии.

Офлайн-подготовка отдельной копии выполняется отдельным инструментом. Без
`--execute` он только проверяет план; параметр записи добавляется лишь после
явной команды владельца:

```text
python tools/v127_stage_full_conversion.py --plan build/v127-full-conversion.sqlite --runtime build/v127-runtime-conversion --output build/v127-derived-original --execute
```

Если подготовленная SQLite на исходном устройстве называется
`build/v127-full-conversion-first.sqlite`, укажите именно её. Имя файла не
заменяет проверку его SHA и манифеста. Подготовка должна завершиться маркером
`dw-derived-copy.json` со статусом
`PASS_DERIVED_COPY_PREPARED`, UUID операции и исходными SHA. До первого запуска
Minecraft устанавливаются нативные палитры, очищаются клетки отложенных
владельцев/поглощённых частей и исходные сущности, чтобы неизвестные старые
регистрации не потерялись при чтении. Их одобренное типизированное содержимое
сохраняется в отдельном потоке установки; координаты удалений сохраняются.

Автор конвертации собирается **отдельным временным модом**; его entrypoint
отсутствует в combined JAR:

```text
python tools/build_v127_conversion_addon.py --production-jar build/libs/dreamwalker-bb-fabric-1.20.1-0.1.0-v12.7-final.jar --output build/v127-conversion-author-final
```

Установить `JAVA_HOME` на Java 17. На этом устройстве процессы Java запускает
родительский исполнитель по очереди; `--prepare-only` генерирует Gradle init без
старта Java. Результат —
`build/libs/dreamwalker-v127-full-conversion-author-1.2.7.jar`, привязанный к SHA
точного рабочего JAR. Не устанавливать этот временный мод в обычную игру.

`tools/run_v127_full_conversion.py --help` показывает переносимый запуск.
Указать подготовленный мир и поток под `build/`, свежую папку сервера,
combined JAR, author JAR, Fabric API, GeckoLib, официальный Fabric server launcher
для Minecraft 1.20.1/Loader 0.16.10 и Java 17. Только после команды владельца
добавляется `--authorize-full-conversion`. `--fixture-only` ограничен небольшим
отдельным тестовым миром и не конвертирует оригинал. Сервер слушает localhost;
игроков в частично преобразованном мире быть не должно.

Импорт идёт ограниченными порциями: обычные владельцы, целые конструкции,
типизированные сущности. Для каждого владельца временно загружается его
занимаемая геометрия, используется штатная атомарная транзакция и точный UUID.
Пересечение исходных коллизий разрешается только внутри этого первоначального
действия. Привилегия не записывается в предмет, NBT мира или тип блока. После
разрушения обычная повторная установка снова проверяет коллизии.

Каждые 1024 объекта сохраняются мир и устойчивый курсор. `dw-conversion-checkpoint.json`
привязан к UUID операции, JAR и манифесту; `--resume` продолжает эту же операцию,
а уже установленные экземпляры проверяются по UUID/состоянию. При ошибке мир
сохраняется, остановка и исходная строка записываются в
`dw-conversion-errors.jsonl`/`dw-conversion-result.json`. Не удалять эти файлы ради
повторного запуска. Для контролируемой остановки создать в целевом мире
`dw-conversion-stop.request`; после разбора причины убрать его вручную перед
продолжением. Оригинальные правила игры восстанавливаются после завершения или
контролируемой остановки; их исходные значения также переживают checkpoint.

Статус `PASS_RUNTIME_CONVERTED_REOPEN_REQUIRED` означает выполненную запись,
**не** завершённую приёмку. Убрать временный author JAR и маркер запуска; открыть
производную карту на чистом сервере и клиенте с рабочим модом. Проверить сохранение
и повторное открытие, исходные позиции/вид, двери, физику, свет и отсутствие
сохранённого разрешения на наслаивание. Зафиксировать PASS/FAIL/NOT_RUN раздельно.

## Память и последующие авторские коллизии

Статичные одноклеточные состояния, для которых проверены геометрия, UV,
прозрачность и простая физика, используют `compact=true`: обычную палитру чанка
без отдельного UUID/BlockEntity. Этот режим не включается автоматически для
всего ID и не изменяет прежние ручные экземпляры `compact=false`. Подвижные двери,
большие конструкции и функциональные объекты сохраняют владение.

Для новой производной карты журнал владельцев включается по чанкам до первой
установки. В памяти удерживаются загруженные журналы, снимки физики и индекс
загруженных RP; выгруженные данные освобождаются. Типизированные payload/формы
внутри shard разделяются словарями. Подготовка, упаковка и публикация читают
данные потоками; не создавать списки десятков миллионов клеток. Команды `all`
также проходят сохранённые чанки последовательно и убирают временные билеты.
Наблюдаемые JVM значения и пределы измерения находятся в принятых отчётах;
полный RAM всего ещё не конвертированного города нельзя объявлять измеренным.

Экспорт Collision Studio в этом этапе **не предоставлен и не применялся**.
Контракт: [COLLISION_IMPORT_HANDOFF.md](../COLLISION_IMPORT_HANDOFF.md), актуальные
ID/состояния: [collision/README.md](collision/README.md) и `collision/target-map.json`.
Для будущей замены нужны точные registry ID и типизированный selector, а не
только пятизначная подпись. Проверить оба представления `compact=false/true`,
BASE/ALT, открыто/закрыто, поворот, SourceShift и монтаж. Сохранить исключения
90006, 90003 и правила DW-барьера/света. Не снимать ограничения формата редактора
и не реконструировать авторскую физику из картинки.

Минимальный запрос в новом чате после готовности владельца:

> Прочитай `bloodborne complete/docs/v12.7/HANDOFF-RU.md` и принятую ревизию
> `bb-v12.7-final`. Теперь разрешаю полную конвертацию оригинальной карты v16
> по подготовленному плану в отдельную копию. Сохрани внешний вид, разовое
> первоначальное наслаивание, координаты удалений и ограничения исходной V12.
> После конвертации проверь рабочим модом сервер, клиент, сохранение и повторное
> открытие; передай карту и отчёт.
