# Память таблиц переходов состояний

Пользователь отдельно разрешил оптимизацию памяти исходных V12. Это исключение относится к внутреннему хранению таблиц, а не к моделям, текстурам, ID, значениям свойств, поведению или физике.

Снимок настоящего retained heap перед оптимизацией находится в `build/v127-validation/tests4/startup-retained-heap-histogram.txt`. Он содержит 915730 Guava ArrayTable, 915741 двумерных Object-массивов, 20328821 ImmutableMapEntry. Размеры соответствующих классов — 43,96 МБ, 35,81 МБ и 487,89 МБ; одномерных Object-массивов — 546,32 МБ. Это **весь** снятый JVM heap, а не точная атрибуция каждого массива этому моду. Следующий запуск с WorldEdit дополнительно увеличил давление на память; его отдельный снимок не смешивается с первым.

`CompactStateTransitions` сохраняет тот же Table-контракт, но общие неизменяемые списки строк, домены значений и порядок активных столбцов разделяются между состояниями. У каждого состояния остаётся массив слотов собственных доменов свойств. Обычно это около28 ссылок вместо72 для четырёх свойств; точные суммы записываются в `metrics()` и нативный отчёт. Значения остаются **теми же** объектами BlockState — другие состояния и палитры не создаются.

Guava ArrayTable считает существующими все комбинации строк и столбцов, даже если значение null. Новая реализация сохраняет эту особенность, Cartesian size, null-ячейки, порядок row/column/cell/value, equality/hash, живые views и прежние исключения. Допустимые `put` / Entry.setValue также сохранены. Редкая запись ненулевого значения в чужой домен использует небольшой overflow, выделяемый только при такой записи. Обычный Minecraft `.with` не создаёт его.

При `State.createWithTable` обрабатываются только классы Block из пакетов `dev.dreamwalker.bloodbornedw` и `dev.dreamwalker.bloodbornerp`. Отдельный проход после регистрации ограничен точными namespace `bloodborne_dw` / `bloodborne_rp` и охватывает наши обычные экземпляры класса vanilla Block. Остальные регистрации не оптимизируются этим проходом. Неизвестный формат исходной таблицы или слишком большой домен сохраняет прежнюю таблицу; исключения не скрываются как «пустое состояние».

Перед отбрасыванием каждой исходной ArrayTable проверяются все её ячейки, включая null, точная ссылка каждого соседа, порядок доменов и size. Общие пулы ограничены, используют только Property/Comparable-значения и никогда не координаты мира или UUID экземпляров.

Нативный `CompactStateTransitionsV127GameTests` независимо строит граф из фактического StateManager каждого зарегистрированного блока наших namespace и проверяет каждый `.with` каждого состояния. В проверку входят исходные V12, их стены/лестницы, новые источники, скрытые переходники и служебные блоки. Второй тест сравнивает Guava и новый Table на отсоединённых копиях: порядок, null, views, equality/hash и мутации. Тест не меняет таблицы реальных состояний. Статус PASS в этом документе не заявляется до реального результата родительского запуска.
