# Совместимость старых мебельных экземпляров: отдельная проверка сохранения

Основной JAR остаётся замороженным main7, SHA256 `2cf96fbe771bb44bba4e4e8f320ed65a8bc0a8ffe7a8149b07fbd9ec691592c1`. Новый отдельный класс `ReviewV10AliasCompatibilityBootstrap` активируется только при наличии строгого `review-v10-alias-input.json`. Первоначальная версия скомпилирована в QA19; последующее расширение сохранения старых ItemStack подготовлено для отдельной QA20 и пока **не скомпилировано**. Фактические процессы этого нового стенда ещё **NOT_RUN**; ожидающие команды сохранены в `tools/review_v10_alias_server_commands.json`. Прежние QA19 план и metadata сохранены побайтово в `reports/input-history/V10_ALIAS_QA19_*_PRE_INVENTORY.*`.

AUTHOR создаёт два независимых экземпляра каждого старого EntityType: `furniture_3/4/5/6/7/8/9`. Их registry остаётся старым. UUID, имя, позиция, поворот, Open/Locked, Scale, VerticalOffset, исходный список Links и полная typed `SourceLegacyPayload.Original` различаются между экземплярами и сохраняются. Стенд занимает семь X-позиций от −42 до 0, ряды Z=16.875/24.875, Y=64.125/64.5. Только явно объявленные площадки 5×5 заменяются на STONE. Временно форсируются 30 объявленных чанков; исходные флаги возвращаются перед окончательным сохранением.

REENTER запускается другим серверным процессом на побайтовой копии фактически сохранённого AUTHOR. Проверяется наличие всех 14 исходных UUID и полное равенство перечисленных typed полей. Команда `bb debug` выполняется с точным лучом игрока на каждом экземпляре. Проверяется canonical TEMP и выбранный canonical model identifier, а также canonical Pick с именем и предметными настройками. Это серверная проверка выбора модели; фактические клиентские квады/пакеты этим стендом не подтверждаются.

AUTHOR также сохраняет семь ItemStack NBT со старыми `*_placer` registry ID, разными именами/Open/Locked/Scale и typed opaque metadata. REENTER читает их из фактического journal schema2 через `ItemStack.fromNbt`, проверяет полное typed равенство повторной сериализации и реально вызывает `ItemStack.useOnBlock` с обычным ItemUsageContext. Каждый создаёт canonical EntityType с новым UUID, пустыми собственными Links и сохранёнными предметными Open/Locked/Scale/именем. Старые UUID/Links/opaque metadata остаются в исходном held stack и не копируются на новый объект/Pick. Старые permanent14 не удаляются. Для сравнения Creative удаления создаётся отдельный временный экземпляр старого EntityType; он и новый canonical удаляются через реальный DamageSource игрока с проверкой обычного точного луча. Проверяются ноль item drops и отсутствие изменения всех 14 постоянных экземпляров. Временные проверки расположены в рядах Z=48/60.

Третий процесс загружает результат REENTER только с основным модом и зависимостями, без QA-дополнения/маркера. После нормального сохранения независимый `verify_review_v10_alias_saved.py` читает entity-region NBT и сохранённый inventory journal во всех трёх мирах и проверяет старые registry, все UUID, typed поля, opaque Original, семь старых ItemStack, отсутствие дедупликации и утечки временных объектов. Девять синтетических негативных тестов самого офлайн-верификатора проходят; они не считаются фактическим Minecraft PASS.

Эти мебельные типы не являются поддержанными целями механизмов. Активные связи, команды или маршруты им не приписываются; сохранение raw Links и opaque provenance проверяется отдельно. Оригинальная карта, пользовательские миры, основной код и текущий ordinary client harness не изменяются. Весь фактический запуск ожидает отдельного GO после завершения клиентских измерений.
