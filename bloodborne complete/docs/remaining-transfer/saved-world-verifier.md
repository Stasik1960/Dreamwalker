# Проверка сохранённого отдельного тестового мира

`tools/verify_remaining_saved_world.py` только читает новый тестовый мир под
`bloodborne complete/build/`. Карта v16, галерея и reference worlds запрещены
guard-проверкой пути и условиями native plan. Скрипт не создаёт и не копирует мир,
не изменяет Anvil/NBT и не посылает игровых действий.

Запускать после остановки сервера. Снимок включает все фактические новые `source_`
корни, полные состояния блоков, resident UUID, типы NBT и точные хеши каждой
collision/selection/rootData contribution, служебные ячейки и persistent ledger.
Для каждого прочитанного файла записывается SHA256; повторное чтение в конце
отклоняет мир, меняющийся во время проверки. Номер и SHA256 combined JAR сверяются
с native plan.

Хешируются все файлы мира, которые копирует штатный `run_v11_server.py`, включая
level/player/entity metadata; `session.lock` исключён одинаково в обоих инструментах.
Это позволяет доказать происхождение отдельного нового server run при reopen.

Первый снимок проверяет установленные planned `root` и `copyRoot`. Неустановленные
позиции помечаются `NOT_INSTALLED`; состояние без фактически установленного
планового объекта получает `NOT_RUN`. После настоящего перезапуска сервера и
повторной остановки `--compare` сравнивает все сохранённые новые объекты, UUID,
typed contributions и помощники с первым снимком. Изменение времени мира и
Anvil timestamps не означает изменение объекта.

Параметры запуска через `Guard.ps1 -Mode Operation`:

```text
tools/verify_remaining_saved_world.py --world <остановленный-мир-под-build> --plan <native-plan.json> --output <снимок-под-build-вне-мира>
tools/verify_remaining_saved_world.py --world <тот-же-мир> --plan <тот-же-native-plan.json> --output <второй-снимок> --compare <первый-снимок>
```

Для штатного `run_v11_server.py --world-copy` второй мир имеет новый путь. В этом
случае добавить `--verified-copy-report <JSON-второго-сервера>`. Принимается только
успешно остановленный сервер с проверкой точной копии: исходный путь равен миру
первого снимка, новый путь равен `run_directory/isolated-smoke-world`, SHA и размеры
всех скопированных входов совпадают с первым снимком, источник сохранился, combined
JAR одинаков. Native plan также должен быть одним неизменным файлом. Иное сравнение
разных путей отвергается. Семантика сравнивается после настоящего reopen; мировой
таймер и player metadata могут измениться, но исходная точная копия доказана хешами.

Дополнительный offline localhost отчёт может отдельно квалифицировать ровно три
строки ошибки получения публичного ключа Mojang: `Yggdrasil Key Fetcher`,
`AuthenticationUnavailableException` и `SocketTimeoutException: Connect timed out`.
Исходный strict отчёт сохраняет `FAIL`; доступность внешней аутентификации также
остаётся `FAIL`. Новый verifier самостоятельно проверяет SHA исходного отчёта и
полного console log, отсутствие любых дополнительных исключений, exit 0 и нормальное
сохранение, фактические `online-mode=false` / `server-ip=127.0.0.1`, точный SHA JAR,
15 реальных read-only rejoin случаев с прежними UUID/поворотом/open и неизменность
всех оригинальных process/copy полей. Это узкое исключение относится только к
локальному сохранению и повторному открытию мира; общий strict критерий не ослаблен.

Фактический final4 снимок до и после reopen: **PASS**, 15 корней, 94 служебные/ledger
ячейки, 2291 прочитанный chunk, 23 проверенных входных файла. Typed состояния, UUID
и contributions совпали точно. Отчёты: `build/remaining-transfer/native-final-4/`
`saved-before.json` и `saved-after.json`. Combined SHA:
`9797fb4bb4b6c4103b60b994fb0c4ad4f88c46bc7a19de42eb596e7f0c57e117`.

Скрипт не выводит `PASS` для native placement, pick, use или break на основании
NBT. Эти проверки требуют отдельно записанных игровых действий. `PASS` относится
к проверке сохранённой структуры либо равенству снимков; факт перезапуска
подтверждается отдельным процессным отчётом сервера.

`--self-test` проверяет типы, UUID, отклонение повреждённых cuboids, независимость
от порядка ключей compound и полный NBT roundtrip owner contribution в памяти.
Он не читает и не создаёт мир. Результат сохраняется в
`saved-world-verifier-selftest.json`.
