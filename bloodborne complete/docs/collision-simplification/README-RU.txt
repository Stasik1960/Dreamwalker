Упрощение базовой физики новых объектов V12.2

Область изменения: только 1045 оставшихся объектов source_, добавленных после
V12, 1802 варианта и 1803 позы с учетом единственной пары open/closed. Удаленные
source_jungle_trapdoor_bottom/open не обрабатываются и не восстанавливаются
импортером. Их номера остаются зарезервированными.

Базовые 28225 физических боксов заменены 1936 крупными прямоугольными боксами:
1441 поза — один параллелепипед; 145 прежде проходимых поз остались без физики;
208 поз настоящих лестничных модулей сохранили два или три крупных объема
полублочных ступеней. Еще девять поз относятся к явно рассмотренным исключениям:
арочным проемам, двум лестницам с площадкой, двум вертикальным лестницам,
горшку азалии и двум состояниям складывающегося объекта warped_gargoyle.
Число боксов любой позы и любого из восьми поворотов не превышает трех.

Внешний вид, модели, текстуры, UV, части, исходные смещения, варианты, ID,
предметы, профиль BASE/ALT и структурные резервы сохранены. Прежнее поведение
выделения и picking сохраняется отдельным путем, описанным ниже.
Проходимость не определяется названием ванильного носителя: растительный
носитель может содержать каменную модель. В частности grass_block — настоящий
грунтовый куб с dirt/grass-текстурами, поэтому остается твердым; его плоская
трава не создает препятствий. У азалии твердый только горшок, листва проходима.

Для каждого поворота простой объем ограничен фактическими преобразованными
вершинами модели. Это исключает повторное расширение AABB для модели с
внутренним поворотом 45 градусов и дополнительным поворотом предмета.
Полная геометрия свечей, складок, веток, орнамента и наклонных элементов в
физической форме не повторяется. Восемь простых списков в JSON — альтернативные
состояния, а не восемь одновременно действующих форм.

Для узкой одноклеточной стрельчатой арки при поворотах 45/135/225/315 градусов
твердым остается только верхнее завершение. Обычные осевые боксы двух стоек
иначе перекрывают проход для игрока шириной 0.6 блока. У высокой широкой арки
warped_gargoyle в этих поворотах стойки уменьшены до вписанных осевых квадратов.
Это намеренное разрешение частичного проникновения в видимую модель ради
сохранения прохода, без мелких наклонных коллайдеров.

Обрезка сравнивает шесть внешних граней общей физической формы с исходной
корневой ячейкой [0,1] по каждой оси. Внешняя грань обрезается, только если
расстояние ее выступа строго меньше 0.5 блока. Выступ ровно 0.5 и более
сохраняется. Сравнения выполняются после поворота, вертикального смещения и
SourceShift экземпляра. Порог сравнивается строго, без полосы допуска около
0.5. Кардинальные sin/cos приводятся к точным -1/0/1. Длинные объекты не
ограничиваются одним кубом.
Разбиение большого бокса по нативным ячейкам Minecraft — формат хранения одной
непрерывной формы, а не мелкая ступенчатая имитация наклона.

Две импортированные вертикальные лестницы hold_ladder_02/03 имеют отдельную
зону подъема. Она учитывает yaw, MountY, VerticalMount и SourceShift; root UUID
должен совпадать с живым владельцем. Поиск идет только среди соседних ячеек.
Зона подъема не становится физической преградой или областью выбора. Старые
prototype/RP-лестницы продолжают использовать прежние ветки кода.

Новая ветка CompositeSpec явно включается simplePhysicalCollision=true только
для registry bloodborne_dw:source_*. При отсутствии маркера действует прежняя
физика V12. Распределение исходного JSON selection использует прежний путь
независимо от маркера; фактическое прицеливание твердых новых объектов отдельно
получает прежнюю форму из оригинальных списков, как описано ниже.

На уровне игровых VoxelShape новые физические списки соединяются обычными
VoxelShapes.cuboid/union без прежнего расширения до сетки 1/16 блока. В ячейках
с несколькими владельцами старые вклады проходят прежнюю растеризацию отдельно,
новые — точное соединение. Проверки высоты опоры также выбирают путь по владельцу.
Проверка пересечения с сущностями использует точную форму только для одиночного
нового входящего объекта; прежние объекты и неизвестные пакетные операции
сохраняют прежнюю ветку. Нативная форма ванильного носителя и выделение остаются
прежними. Статическая эквивалентность старых веток проверена отдельно в
runtime-old-path-equivalence.json; игровая проверка приведена в общем отчете.

Прежние прицеливание, выделение и picking новых объектов сохраняются отдельно
от упрощенной физики. В старом runtime они для твердых объектов фактически
использовали список collision, а не одноименное поле selection. Поэтому точные
исходные списки из immutable default-physical-before.jsonl.gz упакованы в
отдельный imported-legacy-outlines.json.gz только для выделения. Незарегистрированные
spec без нового маркера применяют прежние CompositeSpec/CompositeSourceShift:
это сохраняет yaw, mount, SourceShift и старую растеризацию прицельной формы.
Например, центральный луч у source_potted_fern по-прежнему попадает в дно
полого горшка на y=0.25, хотя простой физический бокс заканчивается на y=0.375.
Подробные формы этого архива никогда не используются для движения или опоры.
JSON selection, физические дескрипторы и визуальные данные не изменены этой
доработкой. Provenance архива приведен в legacy-outline-retention.json.

Авторский экспорт Collision Studio отсутствует и не применялся. Эти простые
формы — базовая физика, не реконструкция авторских коллизий. Точные registry ID,
типы свойств selector, состояния, localOrigin и преобразования экземпляров
сохранены для дальнейшего импорта по COLLISION_IMPORT_HANDOFF.md. Provider
CollisionReplacements без готового экспорта не активируется.

Подробное доказательство: policy-report.json; исходные физические списки и SHA
дескрипторов до изменений: default-physical-before.jsonl.gz. Эти файлы не заменяют
игровую проверку. Статусы и игровое evidence приведены в общем отчете ревизии.
