Состав полного архива исходников

Папка bloodborne complete содержит Gradle wrapper, build.gradle, settings.gradle,
gradle.properties, весь src (включая conversion и gametest), tools и текстовые
данные docs. Новые, ещё не зарегистрированные в Git файлы включаются по
фактическому файловому дереву. Подготовленные source-plan.sqlite, runtime/*
и decision-frequency-proof.json лежат в build/v1271-city-preparation.
Проверенные серверные файлы Minecraft/Fabric лежат в build/v1271-server-bootstrap;
Fabric API, GeckoLib и компиляционный WorldEdit — в build/release-dependencies.
Там же сохранена копия уже существовавшего eula=true как
accepted-eula-evidence.txt; новых условий архиватор не принимает.

Полный архив исходников отличается от стандартного Gradle *-sources.jar:
последний удобен для чтения кода, но не содержит весь набор инструментов и
подготовку города. Исходный ZIP мира и ZIP ресурс пака в архив исходников
не дублируются. Их проверенные привязки сохранены в манифестах:

Fabric API 0.92.9+1.20.1; GeckoLib 4.4.9; mclib 20;
WorldEdit 7.2.15 используется при компиляции существующего интеграционного кода.

Из папки bloodborne complete:
gradlew.bat --offline --no-daemon -Pworldedit_api_jar=build/release-dependencies/worldedit-mod-7.2.15.jar build

Для offline нужны уже заполненные Gradle/Loom кэши: они не включены в ZIP.
На чистом компьютере следует убрать --offline для загрузки зафиксированных
зависимостей. Основной JAR собирается из включённых src/resources; генерацию
подготовки города с нуля запускать не требуется. Исходники идентифицированы
манифестом хешей, поскольку базовый Git HEAD не содержит все новые файлы.
Независимая чистая повторная сборка с доказательством побайтового равенства
JAR не выполнялась; детерминированная упаковка исходников сама этого не доказывает.

Проверки исходников и нативных моделей

В архив также включены актуальные Java/Python исходники нативного QA из
build/final-city-fixes/observer и XML фактического окончательного GameTest run.
Тесты проверяют обычную установку всех предлагаемых предметов, ALT и лимит
радиуса 300, сохранение состояний, физику/оптику невидимых и fallback-носителей.
Включены исходная валидная reference-r2 проба моделей v15 и окончательная
проба 156 моделей для финального JAR. Путь/хеш/число тестов сохранены в
манифесте источников. Тестовое дополнение не входит в игровой основной JAR.
Если проверка моделей выполнена на JAR до отдельного изменения клиентского
кэша, её исходный SHA и SHA окончательного JAR записываются раздельно.
Проверка переносится только на доказанно неизменные ресурсы моделей и нативные
классы носителей: nativeProofCompatibilityReport подтверждает побайтовое
равенство этих компонентов. Это не означает, что предыдущий клиентский запуск
использовал окончательный JAR. Выгрузка чанков, кэш и производительность должны
проверяться отдельно на окончательной сборке.
Пути QA-конфигураций сохранены с текущего компьютера; после распаковки в другой
каталог их следует заменить перед повторным запуском QA. Это не влияет на
сборку основного мода из обычного src. Общий итог нативного сравнения и FPS
читается в отдельном окончательном отчёте выпуска.

Последовательность полной конвертации (следующая операция)

1. Проверить основной JAR и три SHA256 подготовки выше. Сохранить исходные
   ZIP неизменными. Работа сейчас привязана к C:, перенос на E: приостановлен.
2. Собрать отдельный author JAR с привязкой к этому основному JAR:
   tools/build_v127_conversion_addon.py --production-jar <основной JAR>
     --output <проект>/build/v1271-conversion-author-final
     --offline --worldedit-api-jar <проект>/build/release-dependencies/worldedit-mod-7.2.15.jar
   Перед запуском задаётся JAVA_HOME17; каталог --output должен быть новым.
   Результат: build/libs/dreamwalker-v127-full-conversion-author-1.2.7.jar.
3. tools/stage_v1271_city_conversion.py --output <проект>/build/v1271-derived-city
   сначала выполняется без --execute для проверки; затем с --execute создаёт
   новую производную копию. Подготовленная SQL не пересоздаётся. Исходный ZIP
   читается при копировании самого мира, но не изменяется.
4. tools/run_v127_full_conversion.py получает все явно указанные пути:
   --derived-world <проект>/build/v1271-derived-city
   --runtime-plan <проект>/build/v1271-city-preparation/runtime
   --source-plan <проект>/build/v1271-city-preparation/source-plan.sqlite
   --source-style-policy <проект>/docs/v12.7.1/conversion/source-style-policy.json
   --runtime-directory <проект>/build/v1271-city-conversion-server
   --production-jar <основной JAR>
   --author-jar <проект>/build/libs/dreamwalker-v127-full-conversion-author-1.2.7.jar
   --fabric-api <проект>/build/release-dependencies/fabric-api-0.92.9+1.20.1.jar
   --geckolib <проект>/build/release-dependencies/geckolib-fabric-1.20.1-4.4.9.jar
   --server-launcher <проект>/build/v1271-server-bootstrap/fabric-server-launch.jar
   --server-bootstrap <проект>/build/v1271-server-bootstrap
   --accepted-eula-file <проект>/build/release-dependencies/accepted-eula-evidence.txt
   --java-home <Java17> --heap-gb 4 --timeout-hours 24 --authorize-full-conversion
5. После результата конвертации нужен повторный запуск с основным модом без
   author, проверка сохранения/загрузки, освещения и реального города. Обычная
   игровая установка не должна содержать author или тестовые QA дополнения.
   Исходный ресурс пак используется как эталон; изображения блоков мода уже
   включены в основной JAR. Возобновление --resume допустимо только с теми же
   JAR, планом, манифестами и операцией.

Все каталоги вывода должны быть новыми и находиться внутри build текущего
проекта. Нельзя использовать старые defaults v12.7 для --source-plan и
--source-style-policy: в примере выше явно указаны исправленные данные v12.7.1.

Для текущего рабочего проекта есть готовый инструмент копирования:

Без --execute он только проверяет и записывает рецепт. Вывод размещается в

SHA выше, фактический JAR по финальному readiness, привязку author к основному
JAR и каждый файл после копирования.
Он не запускает Java и не создаёт производную карту. JSON отчёта
docs/v12.7.1/conversion/converter-input-copy.json содержит точный массив
аргументов следующего запуска с этими локальными путями. Саму команду конвертации
инструмент не выполняет. Вариант с --author-jar применяют после отдельной сборки
author; для неё доступен уже проверенный WorldEdit в donor mods выше.

Совместимость исходных блоков

Скрытые совместимые состояния сохраняют старую архитектуру без возвращения
лишних стилей в творческий каталог. Проверены исходные fallback-модели,
включая пустые multipart-состояния: пустое исходное изображение не подменяется
выдуманной геометрией; его физика сохраняется невидимым штатным носителем.
56 исходных typed block-entity записей сохранены: 53 как неисполняемые архивные
данные владельцев, 3 у оставленных ванильных блоков. Это сохраняет исходные
данные, но не обещает не реализованный модом GUI/лут преобразованных контейнеров.
Команды и исходные автоматические callbacks не выполняются при подготовке.
