# Проверочный этап, не готовый мод города

Название: `dreamwalker-bb-fabric-1.20.1`, version `0.1.0-prototype.1`, mod ID `bloodborne_dw`, provides `bloodborne_rp`. Все 707 исходных полных RP-ресурсных файлов сохранены; существующие RP registry/NBT и Java-код не переписывались. Архитектура и RP находятся в разных source trees. Сейчас реализован один экспериментальный самостоятельный тип — вертикальная лестничная секция с тремя художественными вариантами. ID `prototype_ladder` временный: пятизначные ID **не закреплены**, чтобы не нарушить требование сортировать полный каталог по реальным экземплярам.

Состав изолированной проверки: объединённый JAR, Fabric API `0.92.9+1.20.1`, GeckoLib `4.4.9`, Java 17 и Fabric Loader `0.19.5` (версия подтверждена в вашей установленной сборке). Standalone RP и старый Complete исключены. 122 файла `mods.zip` содержат дубли; полный тестовый профиль выбирает 109 JAR, из них 83 подходят dedicated-серверу. Все выбранные/исключённые версии и SHA есть в `reports/MODSET_PROFILE.json`. Это отдельная тестовая установка, исходная папка `dw` не изменялась.

В сцене `Prototype-new-placement-scene.zip` находятся четыре ориентации лестницы, три варианта, обычные ванильные блоки, RP-дерево и фонарь. Координаты точки входа `-2 64 0`, основной столб — `0 64 0`, дополнительная стена — `-4 64 -3..3`, фонарь — `6 64 3`. Мигрированный исходный город в этой сцене отсутствует: она создана отдельно для нового строительства.

Проверка пользователем:

1. Создать отдельную Fabric 1.20.1 установку указанного состава. Из распакованного JAR не нужен исходный bbmc ресурспак. В рабочий мир ничего не копировать.
2. Распаковать сцену в отдельную папку `saves`, войти в Creative и открыть группу `Dreamwalker: прототипы`. В ней три варианта лестницы и инструмент строителя. Двери/окна остальных источников ещё не представлены готовыми предметами.
3. Обычным предметом поставить секции на вертикальной стене во всех четырёх направлениях и сделать вертикальный стык. Пройти/пролезть через стык без полёта. Проверить вид с обеих сторон, вблизи и под косыми углами, рядом с обычной стеной.
4. Средней кнопкой скопировать секцию, проверить художественный вариант при повторной установке. Разрушить и поставить снова. При уничтожении опоры ожидается один предмет секции с сохранённым вариантом.
5. Правой кнопкой инструмента повернуть секцию; при отсутствии новой опоры она должна оставаться целой. Shift+правая кнопка переключает BASE/ALT. Лестница должна сохранять форму/коллизию и выбранный вариант.
6. Отдельный `ALT-example.zip` показывает красный тестовый материал для варианта 0 и замену модели варианта 1 моделью исходного варианта 2. В BASE эти изменения не действуют. Без примера ALT использует родительскую BASE-модель без missing model, сохраняя выбранный профиль.
7. Проверить RP-дерево/фонарь рядом с архитектурой и стандартный вид ванильных камня/досок. Фонарь этой тестовой сцены не объявляется готовой сетью путешествий.

Реализованные команды только экспериментального типа: `/bb debug`, `/bloodborne debug`; `/bb rotate`, `/bloodborne rotate`; `/bb visual get|base|alt|toggle`, то же под `/bloodborne`. Нужен игрок с правами уровня 2 и объект под прицелом. Глобальные команды, фильтры ID, выгруженные чанки и WorldEdit пока **NOT_IMPLEMENTED**. Диагностика не притворяется полным каталогом: final ID PENDING; фактическое ALT-переопределение ещё не определяется динамически.

Автоматические проверки: 18 core transaction cases; 10 Fabric GameTests, включая 48 real BlockItem placements, 960 соседских изменений, 24 реальных удалений опоры, art NBT и collision/climbable; 12 RP regression checks; пять проверок ID ledger. Dev GameTests проверяют серверную технику и не заменяют установку из Creative UI, реальное движение клиента или два клиента.

Обычный конечный remapped JAR прошёл отдельный dedicated запуск/сохранение/завершение с минимальным и 83-модовым профилями. Минимальный клиент загрузил ресурсы; полный клиент загрузил копию сцены. Оба захвата игрового окна Windows Graphics Capture завершились timeout; управляемая визуальная проверка, FPS и ручные действия остаются NOT_RUN. Клиенты тестов затем были завершены; их сохранения не используются как финальный мир. Копия сцены получена из нормально сохранённого отдельного сервера.

`Source-coordinate-fixture.zip` сохраняет небольшие исходные участки вокруг лестницы, акациевой двери, окна и RP-фонаря с исходными chunk payloads. Для полного исходного эталона ему требуется Minecraft 1.18.2 Forge с оригинальным Bloodborne и исходным ресурспаком. Это тестовое извлечение, не обрезка основного поставляемого мира. Архив `Ladder-only-coordinate-fixture.zip` — **диагностическая непригодная к приёмке same-anchor попытка**, а не рабочая миграция: все 34 декоративные секции связаны с соседней невидимой vanilla ladder, и правило опоры/переноса точки установки ещё не реализовано. Не устанавливать его как преобразованный город.

Остальные обязательные прототипы, составные owners/helpers, функциональные двери/створки, конфликты с чужой стеной, полный каталог, финальная нумерация, основной мир и галерея не готовы. Реальные исходные дефекты и вопросы адресованы в `reports/SOURCE_DEFECTS.md`, `reports/RESOURCE_AUDIT_USED_DEFECTS.json`, `reports/RP_MIGRATION_DRYRUN.json`. Исключений без решения пользователя нет. Следующий этап — закрыть спорные source assemblies и отсутствующие авторские ресурсы, закончить весь первый набор и получить игровую/визуальную приёмку до массовой генерации.
