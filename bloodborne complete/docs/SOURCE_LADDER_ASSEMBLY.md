# Source ladder assembly

This is a bounded first-set source installation, using the existing `bloodborne_dw:prototype_ladder` identity. It does not assign a numeric catalog ID or migrate the complete map. Ordinary placements retain all 96 eight-yaw, water, art and profile combinations. The explicit `source_clone` installation flag doubles the total blockstate schema to 192; it is never copied into normal picked/dropped items or ordinary placements.

The original source contains **34** recognized honey-level-1 beehives paired with an adjacent visually invisible vanilla ladder: 28 NORTH art cells with SOUTH climbing cells, and six WEST art cells with EAST climbing cells. The two honey-level-0 cap cells are independent source cells and are not claimed or removed. `LADDER_SOURCE_ANCHOR_CONTRACT.json` checks all **1360** actual authored vertices, including intrinsic element rotations and zero-depth planes. Moving an ordinary ladder directly into the climbing cell gives the wrong visual pose. The installed clone instead receives a 180° turn of the already cardinal-baked art, then a canonical local translation `[0,0,1]` in block units rotated by its physical facing. The optional 45° wrapper runs after both transforms. All original source vertices then match in world coordinates to within `1e-8` at the initial cardinal pose. UV and texture bytes remain unchanged.

The climbing root replaces only the recognized original vanilla ladder cell. Its initial collision and selection depth is the measured original **3/16** block, preserving the original climbing cell and direction. The owned invisible backing replaces only the recognized source beehive cell and retains its measured full-cube collision and selection. These shapes are documented in the actual original Forge1.18.2 integrated-client observation at `[177,33,-1108]` and `[177,33,-1107]` in `SOURCE_PHYSICS_CLIENT_ACTUAL.json`. The full backing cube is an explicit legacy physics role of this installation. It is not ordinary new-build ladder support and has no independent inventory item.

The backing remains at its fixed original cell when the ladder rotates. No new full cube is added during a 45° turn. A turn needs the real touching support faces appropriate to the new physical yaw; any second support must already exist in the terrain. The source visual compensation follows the ladder's yaw, while the climbing collider follows physical yaw alone. A turn may therefore be refused when the original installation has only its single backing wall. The whole installed pair has one UUID, root, fixed-backing coordinate and opaque original typed metadata. Both static block entities persist these values and have no ticker. Original bee data is provenance only and is not executed as a new beehive.

Pick from either part returns one normal art-preserving ladder item. Breaking/replacing either verified same-owner role cleans up its counterpart and yields one such item; a stale helper UUID cannot delete a replacement root. Root replacement uses the old callback blockstate for the drop because the world palette can already contain the replacement when the callback runs. The source-specific `PlayerBlockBreakEvents.BEFORE` guard checks the complete pair and permissions before native survival breaking; an ambiguous UUID pair cancels that break. Foreign terrain, cap cells and typed cap metadata are preserved. Placement/rotation/install preflight checks loaded cells, world bounds, permissions, current source state, exact typed source NBT, actual support and entity collision. Failed installation rolls both touched cells back to their snapshots. No bounding-box clearance deletion is performed.

Initialization is `SourceLadderRuntime.initialize()` immediately after the main ladder block registration. The existing ladder client model-bake callback calls `SourceLadderClient.wrap(model,id)` before the diagonal wrapper, avoiding ambiguous ordering between model-loading hooks. Shared commands/builders resolve any source part with `resolveRoot(BlockView, BlockPos)` and delegate installed edits to `edit(World, root, before, next, player)`.

The source-port API is `install(ServerWorld, Installation, PlayerEntity|null)`. `Installation` contains the original visual and physical coordinates, exact original blockstates, exact live typed `createNbtWithId()` payloads (or null when absent), frozen source art index, profile and optional UUID. It returns `Result(committed, reason, owner)`. A null player is the explicit trusted source-port path; interactive callers pass a player. `remove(ServerWorld, anyPart, player, drop)` and `resolveRoot` verify the complete UUID pair. The runtime rejects honey-level-0 cells and incorrect source/physical orientation before any write.

`SourceLadderGameTests` independently checks source-pair shape equality, typed metadata/save roundtrip, climbing, whole-owner pick/drop/cleanup, cap preservation, real shared builder turns, refused unsupported turns, stale plans, denied edits and stale-owner safety. All seven source-assembly tests pass coordinated Attempt11, including real chunk save/unload/reload with strict typed provenance and complete UUID pairing. Bounded source authoring, production-only reopening and persisted no-op replay v4 also pass with normal exit0; the independent saved-world report separately checks owned masks/art/provenance and foreign data. The earlier ladder-only fixture remains a diagnostic historical artifact, not a playable migration. Geometry, server and saved-data checks do not certify client visual/manual acceptance.
