# Диагностика RP: область и проверка

Основание — полный пользовательский запрос из `reports/user-diagnostics-request-2026-10-08/request.txt`, SHA256 `22c4ae75e6ec2d2d50e47461e41c9655c39e16c548a17d10cc742126b6895f93`. Серверный журнал/сессии/экспорт принадлежат `DwDiagnostics`, клиентская запись — `DwClientDiagnostics`; ниже описаны только RP-точки измерения и событий.

Обычный RP-предмет передаёт точный использованный ItemStack, руку и грань из ItemUsageContext. Успешный spawn записывает `place / COMMITTED`, TEMP типа, UUID нового экземпляра, raw registry, канонический asset, выбранный yaw и компенсированный origin. Физическое пересечение, занятая native-ячейка, недостаточные права, дальность, границы и незагруженный чанк дают обычное `REFUSED` с причиной. Они не попадают в журнал ошибок. Программное размещение без ItemUsageContext явно помечено отдельно.

События RP охватывают изменение DogsVisible, масштаба, блокировки, open/close, проверенный поворот, удаление, начало/окончание32-tick импульса wood_gate и окончание deployment лестницы. Удержание/offhand/locked/in-flight отказ не меняет прежнюю механику. Таймерные промежуточные тики не создают покадровый журнал. Чтение источника сохраняет прежние typed NBT, UUID/CustomName/Links и существующие fallback-правила; отдельные ошибки объясняют неверные типы, недекодируемый UUID или некорректную SourceLegacyPayload. В событиях нет полного NBT, travel-token или содержимого сетевого буфера.

Серверные интервалы `rp.placement`, `rp.geometry_rebuild`, `rp.server_state_tick`, `rp.persistence_read/write` и `rp.mob_tick_including_ai` измеряются только в активной сессии, с ограниченной выборкой1/32. RP entity-измерения передают точный UUID в фильтр. Это elapsed wall nanoseconds выбранных вызовов, а не полная стоимость всех объектов. Mob tick включает работу super/AI и собственное состояние; он не отделяет стоимость каждого vanilla goal. Вложенные интервалы нельзя складывать как независимые расходы.

Клиентская запись содержит действительно запрошенные и разрешённые resource IDs модели/текстуры/анимации, класс фактически полученного Gecko baked model и число его верхних bones, а также наблюдаемые DogsVisible/ladder/gate состояния. Выбор записывается при изменении, с ограниченным weak-cache1024 экземпляров. Если сервер прислал подтверждение именно этого UUID в текущей сессии, цепочка включает его operation/sessionId и настоящий heldItem/heldTypeId. Для уже загруженного объекта без такого подтверждения используется `ITEM_NOT_OBSERVED_FOR_LOADED_ENTITY`: предмет установки не выводится из предполагаемого имени placer. Разрешённый resource ID и baked geometry не означают ручную визуальную приёмку или измерение GPU.

Клиентские animation/bone-pose и object/mob-render submission интервалы имеют ограниченную выборку1/16 и UUID-фильтр. Рядом с elapsed wall interval записывается `.thread_cpu` только если JVM действительно предоставляет current-thread CPU time. Интервалы не измеряют GPU, кадр целиком или долю просадки FPS.

Сеть измеряется на собственных `bloodborne_rp:lamp_list` и `bloodborne_rp:lamp_travel` в точке фактического чтения/отправки: число bytes — полезная нагрузка канала, без packet framing/IP/остальных модов. Стандартные EntityTracker/metadata packets и весь трафик сервера этой RP-правкой не измеряются. Повреждённая длина/структура собственного протокола получает дедуплицированную ошибку; секретный token не записывается.

Read-only показатели: `RpObjectIndex.metrics(World)` — только загруженные custom-geometry экземпляры данного мира, без сканирования/загрузки чанков; `RpObjectGeometry.cacheMetrics()` — общий JVM source-geometry cache; `LampService.diagnosticMetrics()` — серверные context/cooldown/pending counts без token. Cache hit/miss counts не являются измерением памяти в bytes. Client/server values общего JVM cache нельзя складывать.
