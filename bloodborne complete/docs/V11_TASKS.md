# Актуальные задачи V11

Все перечисленные пользовательские правки уже присутствовали в выбранной базе.
В V11 сохранены их реализации, удалён редактор и устранён дополнительный дефект
изоляции 90012. Проверки относятся к конкретному JAR новой ревизии; окончательные
результаты находятся в выпуске, а не в исторических отчётах V10.

| Требование | Состояние реализации |
|---|---|
| Полное удаление отладочного инструмента | 90008/90009/wall_builder, GUI, input mixins, выделение, undo, редакторские пакеты и recorder удалены. Сохранён только `textures/item/composite_builder.png`. |
| 90002 обычная ограда, без диагонали и требования нижней опоры | Сохранено; варианты 90013–90017 исключены из предлагаемых типов, старые данные мигрируют. |
| 90012 только диагональный неизменяемый столб | Сохранено; не соединяется с wall/fence/pane. В V11 также исключён из WALLS tag, чтобы соседняя калитка не меняла высоту. |
| 90003 размещение любых блоков в его геометрии | Это `prototype_roof`, не дерево 90005. Блоки разрешены в остальных ячейках, физика игрока сохранена. Корневая ячейка занята — исключение явно подтверждено пользователем. |
| У RP объектов нет надписей над ними | `hasLabel=false`; имена в сохранениях сохранены, обычные NPC имена не стираются. |
| 90006: коллизия диагонали без боковых опор | Сохранено; между двумя действительными боковыми опорами проходима. 90018/90019 скрыты и мигрируют в 90006. |
| Исторический третий визуал 90020 | Сохранён отдельный window03 с историческими UV; не копия 90010. |
| Обычное взаимодействие по физике и обычной дальности | Сохранены narrow-phase части, препятствия и native reach; редакторская расширенная область/выбор удалены. Для декоративных объектов без физики остаются их реальные визуальные части. |
| Нельзя прерывать анимацию повторным действием | Сохранён серверный busy-флаг отдельно для каждого экземпляра, сбрасывается после клипа. |
| 91030 и 91013 правильно устанавливаются на поверхность | Сохранено размещение по нижней точке модели; typed Pos/UUID/offset не смещаются повторно при чтении. |
| Новая галерея | Все предлагаемые текущие предметы и настоящие NPC; размер по коллизии +2 со всех сторон; точные промежутки 2 блока; без редакторского стенда. |

Нереализованных исходных правок по коду не выявлено. Ниже остаются задачи игровой
приёмки, которые нельзя объявлять закрытыми только по компиляции/серверному тесту:

- [ ] Полный ручной обход всех визуалов, включая NPC и оба профиля ресурсов.
- [ ] Реальный подъём/проход на диагональной 90006 с двумя опорами и без них.
- [ ] Клики в пустоты моделей, края дальности, препятствия в Survival и Creative.
- [ ] Повторные действия во время клипа, сохранение и вход с открытым объектом.
- [ ] Два реальных игрока и нагрузка в большой сцене; прежние synthetic players
  такими проверками не считать.

При обнаружении проблемы начальной синхронизации открытого RP объекта проверить
`onTrackedDataSet(OPEN)`: клиент может начать переходный клип при загрузке, тогда
как сервер уже восстановил устойчивое состояние. Это гипотеза для приёмки,
не подтверждённый дефект. Не менять сохранения/анимации вслепую.

Все прежние задачи GUI90009, его клавиш, undo и записи диагностики закрыты удалением
соответствующего функционала; их проверки не переносить в новую приёмку.
