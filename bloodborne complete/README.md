# Dreamwalker BB Fabric — кандидат V11.3

Minecraft **1.20.1**, Fabric Loader **0.16.10+**, Java **17**.
Обычный мод объединяет архитектуру Dreamwalker BB и сохранённый Bloodborne RP.
Версия: `0.1.0-v11.3`; база: `codex/bb-v10-90009-fix`.
V11.3 собрана: 42 GameTest без ошибок и 21 core test прошли. Новый тест 90006
проверяет обычную установку предметом, отсутствие угловой коллизии во всех
контекстах и в старых сохранённых данных, сохранение прямой коллизии и outline.
Ручной подъём больше не является требованием. Новая галерея 120 экспонатов
готова; проход неподвижной сцены с двумя настоящими клиентами завершён:
659,5 секунды, 13 191 тик, 20,00 TPS и штатное сохранение/exit0.
Это проверка смены ракурсов и обычного use двери; FPS и боевой AI NPC не измерялись.
Файлы опубликованного кандидата V11.2 сохраняются отдельно без замены.

В V11 полностью удалены редактор 90009, legacy инструмент 90008, wall_builder,
меню/клавиши/undo/расширенное выделение и запись диагностики. Сохранён только
PNG иконки. Миграции оград/лестниц, UUID и типизированные данные объектов,
обычная физика/наведение, механизмы и маршруты фонарей сохранены.

В V11.3 по запросу пользователя убрана коллизия только угловой 90006 независимо
от боковых опор; прямой вариант сохранён. Прежнее требование подъёма угловой
лестницы отменено. Пользователь ответил на три запроса проверки сообщениями о
невозможности двигаться и повторном застревании. Последняя проверка C285 не
принята, несмотря на 42 GameTest и 21 core test; три отдельных измеренных
прогона удержания клавиши этим не подтверждены.
Тест с mock игроком, прямой установкой блоков и ручным циклом `travel` не
подтверждал обычный клиентский путь движения.

В V11.2 уже открытый RP объект при загрузке получил исходную позу без лишнего
клипа; настоящий переход запускается при дальнейшей смене OPEN. Начальная
синхронизация, два настоящих клиента, reach, препятствия, пустоты и busy двери
проверены в игре на указанной версии V11.2. Эти результаты сохраняются с её SHA.
Завершён статический обзор 480 native кадров всех экспонатов в BASE/ALT и
18 дополнительных крупных кадров BASE. Затем на V11.3 завершены четыре новых
крупных native ракурса 91007: сзади видны голова, тело и лапы собаки, с западной
стороны — тело и ноги. Прежняя неопределённость видимости снята; северный ракурс
по-прежнему перекрыт дверцей и прутьями.

Текущий каталог: 11 архитектурных типов, 69 RP объектов, 18 NPC и 4 обычных
предмета; также предлагаются 18 яиц призыва. Галерея включает все 102 предмета
каталога и 18 настоящих NPC, всего 120 отдельных экспонатов. Удалённые варианты
не предлагаются; скрытые legacy registrations используются для чтения старых
миров. 90003 — кровельный модуль, 90005 — дерево.

Новые JAR и ZIP галереи V11.3 находятся в
[`releases/Dreamwalker-BB/v11.3`](../releases/Dreamwalker-BB/v11.3), комплект
опубликован. Сохранённые файлы исторического кандидата V11.2 находятся в
[`releases/Dreamwalker-BB/v11.2`](../releases/Dreamwalker-BB/v11.2).
ZIP распаковывается в `saves`; отдельный мод автора галереи игре не нужен.
Точные координаты и варианты представлены в `gallery-manifest.json`.

Нужны Fabric API **0.92.9+1.20.1** и GeckoLib **4.4.9**. GeckoLib уже включает
mclib20; отдельный JAR mclib не нужен. Для обычной игры используйте
один combined JAR; отдельный `bloodborne-rp` одновременно не устанавливайте.

Обычные команды настройки сохранены: `/bbrp object ...`, `/bbrp lamp ...`.
Обычные двери, рычаги и фонари работают через свои взаимодействия. Создание
нового GUI вместо удалённого редактора в эту ревизию не входит.

Активная структура:

- `src/architecture` — блоки, физика, транзакции, совместимость и механизмы.
- `src/rp` — объекты, NPC, оружие, фонари и ресурсы.
- `src/gallery` — отдельный автор галереи, не включается в production JAR.
- `src/gametest` — небольшой актуальный набор серверных проверок.
- `tools` — только текущие средства запуска/галереи и NBT/ресурсные утилиты.
- `docs` — [план](docs/V11_PLAN.md), [сверка веток](docs/V11_BRANCH_REVIEW.md),
  [реализация и оставшаяся приёмка](docs/V11_TASKS.md).

Старые V9/V10 материалы доступны в истории Git и базовой ветке. Их не нужно
восстанавливать в активное дерево для обычной сборки и проверки.

```powershell
$taskJdk = 'Абсолютный путь к JDK17'
$env:JAVA_HOME = $taskJdk
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" build
# По необходимости после изменений игровой логики:
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" -Pgametest_run_name=v11-check runGametest
# Только для пересоздания галереи:
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" remapGalleryJar
```

На данной машине процессы проекта запускаются через
`C:\Users\vakir\CodexControl\Guard.ps1 -Mode Operation`, проверки диска —
`-Mode Check`. Работа находится на C:, прежний перенос на E: остаётся на паузе.
