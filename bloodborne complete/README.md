# Dreamwalker BB Fabric — V12.7

Minecraft **1.20.1**, Fabric Loader **0.16.10**, Java **17**.
Текущая ревизия объединяет Dreamwalker BB и Bloodborne RP в один combined JAR.
Установка: [INSTALL-RU.txt](docs/v12.7/INSTALL-RU.txt). Продолжение полной конвертации
с другого устройства: [HANDOFF-RU.md](docs/v12.7/HANDOFF-RU.md).

В V12.7 расширены инструмент BB и BASE/ALT, добавлены `/bb no-collide`,
DW-барьер 93230, невидимый свет 93231 и числовые ID для WorldEdit. Оптимизированы
таблицы состояний, клиентские модели и хранение владельцев. Новые модели вынесены
в отдельный архив Blockbench. Верхние босс-полоски NPC мода отключены.
Общий новый рабочий каталог содержит 541 тип; старые номера сохранены.

Финальные проверки и SHA сборки публикуются в
[acceptance.json](docs/v12.7/acceptance.json) и [итоговом отчёте](docs/v12.7/FINAL-REPORT-RU.md).
Последняя серия с настоящим WorldEdit: **129 PASS / 0 FAIL / 0 SKIP**.
Нативный клиент проверил BASE/ALT, 17 кадров, сохранение и повторное открытие;
малый конвертер исходной схемы 2975 сохранил UUID/NBT и все 35 правил мира.
Перед публикацией ещё обязательны запуск копии существующей галереи и оценка
её FPS/времени кадров/памяти. До этой приёмки JAR остаётся кандидатом.
Оригинальная карта **подготовлена для конвертации по отдельной команде**;
полная конвертация в этой ревизии не запускалась. Новая галерея не создаётся;
игровая проверка использует отдельную копию галереи V12.6.
В плане подходящие ванильные блоки используются для доказанно закрытого
наполнения; видимые авторские поверхности сохраняют свои модовые модели.

## Историческая база V12

Minecraft **1.20.1**, Fabric Loader **0.16.10+**, Java **17**.
Один мод объединяет архитектуру Dreamwalker BB и Bloodborne RP.
Версия: `0.1.0-v12`; исходная база: `codex/bb-v10-90009-fix`.

V12 добавляет простой инструмент BB: сдвиг объекта на ±1 блок, особое действие,
небольшое окно команд с личным/общим лимитом и удаление связей. До шести рычагов
образуют постоянную ALL-связку; фонари 91063 образуют двустороннюю пару с обычным
ПКМ туда/обратно. Старые меню, пакеты и команды настройки фонарей удалены.
Подробное управление и права: [V12_TOOL.md](docs/V12_TOOL.md).

Сборка прошла **58 GameTest и 21 проверку транзакций**. Production SHA-256:

`baaf38ab7449c2336dff7f882ee26677002b99b046238160f5d8b8d87e23ddf6`

Функциональная native-приёмка **PASS: все 22 случая**, включая два реальных
клиента и сохранение/перезаход. Действия клиента дополнены запросами состояния
и серверными GameTest; точные доказательства и их границы:
[V12_ACCEPTANCE_RESULTS.md](docs/V12_ACCEPTANCE_RESULTS.md).
[Готовый комплект V12](../releases/Dreamwalker-BB/v12/README.md). Свежая галерея включает
все 103 предлагаемых предмета, включая инструмент, и 18 настоящих NPC:
**121 отдельный экспонат**. Подготовка карты и серверные тесты не заменяют
полный визуальный проход каталога; такой проход, FPS и боевой AI в V12 не заявляются.

## Установка и сохранения

Нужны Fabric API **0.92.9+1.20.1** и GeckoLib **4.4.9**. GeckoLib уже включает
mclib20; отдельный JAR mclib не нужен. Один и тот же combined JAR устанавливается
на сервер и клиенты; отдельный `bloodborne-rp` одновременно не устанавливайте.
Заменяйте предыдущую версию, не оставляя рядом два JAR этого мода.

ZIP галереи распаковывается в `saves`; мод автора галереи игре не нужен.
Координаты и варианты перечислены в `gallery-manifest.json`. Новый инструмент:
`/give @s bloodborne_dw:bb_tool`; в галерее также есть `/function dw_gallery:tool`.
Обычные команды `/bbrp object ...` сохранены. `/bb select <radius>` и `/bb none`
управляют радиусом особого действия инструмента и возвратом к одной цели.

UUID объектов, позиции, постоянные флаги рычагов, пары фонарей, команды и
потраченные лимиты сохраняются с миром. Перенос старых фонарей ограничен
отдельными взаимными парами: прежние односторонние/многоточечные сети больше не
действуют. Незавершённый выбор рычагов/фонаря сбрасывается при выходе или смене
режима. Полные правила сохранения и удаления описаны в инструкции инструмента.

## Совместимость внешних коллизий

Подготовлен data API чтения JSON/ZIP Collision Studio и явной регистрации проекта
по точному ID и состоянию. Он **не применяет коллизии автоматически**: текущая
физика не использует provider; активный consumer, автозагрузка config и сетевая
синхронизация ещё не подключены. ModelPacks game-export добавляет отдельные
объекты и отличается от replacement-export для встроенных объектов BB.
Совместная загрузка предоставленного production ModelPacks проверена на сервере,
клиентах A/B и при перезаходе с тем же SHA; внешние pack/override не устанавливались.
Контракт и этапы подключения: [V12_COLLISION_COMPATIBILITY.md](docs/V12_COLLISION_COMPATIBILITY.md).

Для разовой встройки авторского экспорта прямо в BB, без установки ModelPacks:
[инструкция для следующей ревизии и другого чата](docs/COLLISION_IMPORT_HANDOFF.md).

## Исходники и сборка

- `src/architecture` — блоки, физика, транзакции, инструмент и механизмы.
- `src/rp` — объекты, NPC, оружие, фонари и ресурсы.
- `src/gallery` — отдельный автор галереи; не включается в production JAR.
- `src/gametest` — актуальные серверные проверки.
- `tools` — средства запуска/галереи и NBT/ресурсные утилиты.
- `docs` — [задачи V12](docs/V12_TASKS.md), [план native-приёмки](docs/V12_NATIVE_ACCEPTANCE.md),
  [результаты](docs/V12_ACCEPTANCE_RESULTS.md).

```powershell
$taskJdk = 'Абсолютный путь к JDK17'
$env:JAVA_HOME = $taskJdk
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" build
# После изменений игровой логики:
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" -Pgametest_run_name=v12-check runGametest
# Только для пересоздания галереи:
.\gradlew.bat --no-daemon "-Dorg.gradle.java.home=$taskJdk" remapGalleryJar
```

На данной машине процессы проекта запускаются через
`C:\Users\vakir\CodexControl\Guard.ps1 -Mode Operation`, проверки диска —
`-Mode Check`. Работа находится на C:, перенос на E: остаётся на паузе.
Старые V9/V10 материалы доступны в истории Git и базовой ветке;
восстанавливать их в активное дерево для обычной сборки не требуется.
