# Задание Codex: применить коллизии игроков И блоков из Collision Studio

Пользователь вручную создал объёмы в трёхмерном редакторе для Dreamwalker BB Fabric V10. Прочитай этот документ и `dreamwalker-collisions.json` целиком. Реализуй применение данных в исходниках мода. Это запрос на реализацию, а не на повторную автоматическую генерацию коллизий из визуальной модели.

## Обязательная семантика

В точности заменить существующие коллизии движения игроков И ограничения установки блоков для каждой явно перечисленной пары `registryId + states[].key`. Одни и те же `colliders` используются обеими системами: `policy.scope = players_and_blocks`, schemaVersion 2. Не добавлять новые объёмы поверх старых. `colliders: []` удаляет авторские объёмы для игроков и блоков, `seats: []` удаляет сидения. Неупомянутые модели/состояния сохраняются. `reviewed: false` не отменяет экспортированные данные, но требует сообщить о незавершённой работе. Старые проекты v1 имеют прежнюю семантику; открытие и повторный экспорт в редакторе v3 явно переводит их на новую.

Объёмы ограничивают движение PlayerEntity и резервируют место при установке обычных блоков, размещении новых моделей/сборок и строительными инструментами V10. Проверять точное пересечение полного объёма ячейки размещаемого блока с OBB; касание границ допустимо. Для составных блоков (дверь, кровать, высокий цветок) проверить все занимаемые ячейки до любых изменений мира. Обратная проверка обязательна: модель нельзя ставить поверх уже существующих блоков/объектов. Проверки выполнять на сервере и предсказывать на клиенте. Смена состояния не должна разрешать пересечение блоков: отклонить переход и оставить прежнее состояние. Не удалять существующие блоки автоматически. Сидения НЕ резервируют объём и не являются коллизиями. Физику NPC/мобов/предметов, опоры и обновления соседей, форму выбора и визуальные ресурсы не менять. Команды /setblock, worldgen, поршни и прямые вызовы setBlockState требуют отдельной явной интеграции; обычные проверки placement не гарантируют их перехват.

Не переписывать `geo.json`, визуальные Minecraft JSON, текстуры, анимации, звук, registry IDs или старые алиасы. Коллизии принадлежат новой отдельной таблице runtime-данных. Версия визуальной модели не является версией коллизий. Не запускать массовую миграцию мира и не перепривязывать UUID объектов.

## Идентификация и состояния

Каталог построен из Git commit `d5d78282b5df3d274a49be8e5b947bedc6bf3ecc` репозитория `https://github.com/Stasik1960/Dreamwalker`, папка `bloodborne complete`, выпуск `dreamwalker-bb-fabric-1.20.1-review-v10`. В современной main эта папка может отсутствовать; сначала найти код соответствующего мода и сравнить ресурсы/контракт. `source` каждой модели содержит путь/отпечаток. При несовпадении хеша геометрии исследовать различие и явно отразить его; не считать данные автоматически подходящими иной модели.

Сопоставлять по registry ID и `selector`, не по русскому имени, номеру TEMP, порядку каталога или названию PNG. У RP `Open` / `DogsVisible` — данные entity. У составной архитектуры `variant`, `profile`, `open` — состояние основного объекта. У лестниц строковые `variant`, `profile`, `diagonal` нужно преобразовать к свойствам блока. У оград `north/east/south/west` равны `none/low/tall`, `up` — столб, `profile` — BASE/ALT, `rotation` равен 0 или 1 (канонические ориентации 0°/45°). Проверить реальные имена свойств в StateManager: `selector` описывает семантику, а не разрешает выдумывать отсутствующее свойство.

Обычные повороты всего установленного объекта — instance transform, а не новый тип. Для оград rotation 2/4/6 — повороты канонической rotation 0; 3/5/7 — повороты канонической rotation 1. Учитывать алгоритм `PrototypeWallModels` и повернутый порядок сторон: перед поиском канонической разметки привести состояние к локальному базису и после этого трансформировать объёмы. BASE/ALT и варианты разметки не связывать неявно. Для алиасов `models[].aliases` использовать канонические данные, сохранив возможность загрузки старых entity ID.

`authoringPose: true` / `animationClip` у добавленного вручную состояния не равен готовому состоянию игры. `pose.clip` и `pose.time` точно фиксируют авторскую позу, но не определяют игровой триггер. Если эта поза не сопоставима существующему runtime state, запросить только недостающую привязку у пользователя, продолжая реализацию остальных однозначных состояний. Для `import:` ID обязательно получить registry mapping, не угадывать по имени файла. `customAssets` / `importedGeometry` нужны для восстановления проекта и проверки позы, а не для автоматического добавления новых предметов или NPC.

## Координаты и повороты

`unitsPerBlock = 16`. Все числа в координатах и размере — единицы модели; делить на 16 перед использованием в мире. Базис редактора правый: +X вправо, +Y вверх, +Z к югу. `center` коллизии — центр параллелепипеда; `size` — полные длины сторон, не полуразмер. Начальный локальный box: `[-sx/2,+sx/2] × [-sy/2,+sy/2] × [-sz/2,+sz/2]`. Сначала повернуть его вокруг собственного центра, затем добавить center.

`rotation = [rx,ry,rz]` в градусах. Euler order `ZYX`: для column-vector `R = Rz(rz) · Ry(ry) · Rx(rx)`, вращение X, затем Y, затем Z. Положительный угол — правое правило руки. Это поворот авторского объёма, а не Bedrock bone rotation. Не менять знаки повторно.

RP геометрия в редакторе уже имеет GeckoLib mirror X: x = -bedrock x, bone/cube углы = [-bedrock rx, -bedrock ry, bedrock rz]. Отметки не нужно зеркалить ещё раз. Модель показана в нативных единицах до `asset.scale` / `objectScale`: применить их один раз к координатам и размерам, затем transform instance. Для текущего `CatalogObjectRenderer`: world rotation содержит Y = yaw - 90° и Z = pitch, origin = entity position. Сохранённые VerticalOffset/монтажные смещения учитывать согласно фактическому рендереру, без двойного прибавления.

Архитектура показана относительно root `[0,0,0]`, в каноническом состоянии facing и mount. Применить тот же mount/alignment, facing, диагональный поворот, profile pose и offset основного экземпляра, что использует renderer. `state.parts` в каталоге уже применяет offset и внутренние повороты деталей: **не применять их повторно к colliders**. Root pose transformation, дробное смещение экземпляра, wall / ladder mount и мировая позиция применяются один раз. Сравнить рендерер и новые объёмы при 0/45/90/180/270°.

## Точные повёрнутые объёмы

Поддержать произвольные rx/ry/rz. Не заменять наклонный OBB одним охватывающим axis-aligned Box: такой box заполнит пустые места вокруг наклонной детали. AABB допустим только для поиска кандидатов (broad phase). Для точного пересечения игрока использовать OBB / SAT либо эквивалентную точную геометрию; для перемещения — swept collision/continuous shape cast или устойчивый эквивалент с проверкой полного отрезка, а не только финальной точки. Не считать SAT проверки конечного положения достаточными против прохождения сквозь тонкие объёмы.

Текущие Minecraft VoxelShape — осевые. Если выбран grid approximation для интеграции с vanilla movement/step-height, согласовать точность с пользователем и не заявлять точное совпадение произвольных поворотов. Предпочтительнее отдельный player movement solver с narrow phase, определённым порядком разрешения контактов, обработкой опоры/шага и одинаковыми данными клиент/сервер. Не давать клиенту авторитетно устанавливать произвольные коллизии или mount.

Учитывать шаг игрока, прыжок, приседание, плавание/ползание, разные размеры pose, движение на элитрах/с высокой скоростью, телепортацию и выталкивание при переключении состояния. Выбрать явную политику переходов открытие/закрытие по существующей анимации; не смешивать геометрию closed и open без причины. Статические authored состояния применяются в соответствующей позе, промежуточное движение деталей требует сопоставления/преобразования либо отдельно заданной авторской позы.

## Сидения

Каждая запись — независимое место вместимостью ровно один игрок. `size` неизменно `[9.6,1.6,9.6]` (след 0.6 × 0.6 блока, толщина маркера 0.1 блока). Это маркер поверхности, **не дополнительная коллизия**. `surfaceCenter` — центр верхней поверхности; до rotation маркер занимает X/Z ±4.8 и Y [-1.6,0]. Именно surfaceCenter, а не центр маркера, является опорной точкой сидящего игрока.

ПКМ по поверхности: сервер выбирает ближайшее свободное место среди тех, чья реальная повернутая поверхность пересекается лучом игрока в допустимой дальности. Проверить dimension, chunk, разрешения взаимодействия, свободный путь и занятость. При нескольких местах одновременно могут сидеть разные игроки. Не сажать всех в центр модели. Каждое место идентифицируется парой owner UUID + state key + seat id. Стабильные ID сохранять.

Применить instance transform к поверхности и её осям. Локальное направление взгляда сидения — -Z. Использовать его мировой yaw; pitch/roll поверхности сохраняются и используются для маркера/положения. Minecraft PlayerEntity не получает визуальный roll автоматически: не выдавать это за реализованную наклонную позу игрока. Для слишком наклонной поверхности, если движок посадки не способен её поддержать, явно сообщить ограничение и согласовать поведение.

Можно использовать невидимую SeatEntity с mount. Её y-offset подобрать по фактическому `getMountedHeightOffset` / позе игрока: поверхность должна поддерживать нижнюю часть сидящего игрока, а не поднимать его на полный standing height. Проверить визуально. Shift — выход с поиском безопасного места; выход, смерть, отключение, смена измерения, разрушение объекта, закрытие двери или скрытие данного состояния освобождают seat и удаляют сиротскую entity. Защита от двух одновременных ПКМ — атомарное серверное резервирование места. Посадка не должна создавать world blocks или включаться в block placement/support checks.

## Где искать интеграцию в V10

`src/rp/java/dev/dreamwalker/bloodbornerp/object/RpObjectGeometry.java`, `RpObjectEntity.java`, `ObjectRegistry.java`, `RpObjectSelection.java`; `src/rp/java/.../client/CatalogObjectRenderer.java`, `CatalogEntityModel.java`; `src/architecture/java/dev/dreamwalker/bloodbornedw/composite/CompositeRuntime.java`, `CompositeShapeMixin.java`, `CompositeCellBlock.java`, `CompositeRootBlock.java`, `CompositeClient.java`; `architecture/PlacementPhysics.java`, `wall/PrototypeWallModels.java`, `ladder_source/SourceLadderBakedModel.java`, `architecture/mount/`.

Внимание: существующие physicalBoxes могут использоваться несколькими системами. Разделить применение: PlayerEntity movement и block/object placement теперь получают одни авторские объёмы, остальные потребители сохраняют прежние данные. Не делать объект физически твёрдым для всех сущностей и не ставить world-block placeholders. Для строительного инструмента V10 внедрить проверку перед атомарной транзакцией, включая составные объекты. AABB только отбирает кандидатов, окончательное решение принимает SAT по точным OBB.

## Проверка и передача

Проверить schema v2, конечность чисел, размеры и постоянный размер seat, уникальность state/seat IDs. Сохранить JSON как ресурс и добавить versioned reader. Проверить closed/open, BASE/ALT, наклонные тонкие OBB и свободные углы их AABB. Игрок сталкивается, моб/предмет проходит; установка блока внутри authored объёма запрещена, вне его разрешена, касание допустимо. Проверить обратную установку модели поверх блока/сборки, составные блоки, смену состояния без перекрытия и без удаления блоков, старые проекты, несколько сидений, освобождение mount и restart. Выполнить сборку и серверные/клиентские проверки. Явно указать фактически проверенное и ограничения, не считать ZIP редактора готовой реализацией в исходном V10.
