# Model Props — инструкция

Мод загружает обычные JSON-модели формата **Minecraft Java Block/Item** и их
PNG-текстуры с сервера. Каждая модель появляется как отдельный вариант
предмета во вкладке «Предметы-модели». Предмет не влияет на игровой мир, но
может проигрывать серверно-синхронизированные анимации и звуки действий.

## Установка

1. Установите Minecraft 1.20.1, Fabric Loader 0.16.14+, Fabric API
   0.92.6+1.20.1 и Java 17.
2. Положите JAR мода и Fabric API в `mods` на сервере и у всех игроков.
3. Один раз запустите сервер. Будут созданы папки и пример куба:

```text
config/modelprops/
├─ models/
├─ textures/
├─ animations/
├─ sounds/
└─ transforms.json
```

Каталог общий для всей установки сервера, а не отдельный для каждого мира.

## Как добавить модель

Самый простой способ — нажать **F7** в игре. Во вкладке «Модель и текстура»
выберите JSON модели и PNG, а во вкладке «Анимации и звуки» — необязательный
набор JSON-анимаций и Ogg Vorbis для нужных действий или клипов. JSON-анимации
можно выбирать повторно либо сразу несколько: меню объединит их клипы в один
набор и отклонит совпадающие имена клипов или конфликтующие назначения действий.
Одна кнопка **«Загрузить всё»** проверит и атомарно установит весь комплект.
JSON, PNG и OGG также можно перетащить в окно; имя файла OGG, например
`dance.ogg`, автоматически сопоставляется с клипом `dance`.

Выбранная PNG-текстура применяется ко всем граням кубической модели либо к
`layer0` у плоской модели. Если введённый ID уже занят моделью, добавленной
вручную, сервер сохранит её и подберёт свободный суффикс `_2`, `_3` и т. д.
Повторная загрузка модели, ранее добавленной через F7, обновит её. Загружать
файлы могут только операторы с уровнем прав 2. Если при обновлении не выбирать
новые анимации, прежний набор клипов сохранится. Невыбранные звуки также
сохраняются, пока их клипы остаются в обновлённом наборе.

Ручной способ также поддерживается. Положите JSON на сервер в
`config/modelprops/models`, а PNG — в `config/modelprops/textures`. Например:

```text
config/modelprops/models/mypack/chair.json
config/modelprops/textures/mypack/furniture/chair.png
```

В `chair.json` ссылка на текстуру будет выглядеть так:

```json
{
  "display_name": "Деревянный стул",
  "textures": {
    "0": "mypack:furniture/chair"
  },
  "elements": [
    {
      "from": [2, 2, 2],
      "to": [14, 14, 14],
      "faces": {
        "down":  { "uv": [0, 0, 16, 16], "texture": "#0" },
        "up":    { "uv": [0, 0, 16, 16], "texture": "#0" },
        "north": { "uv": [0, 0, 16, 16], "texture": "#0" },
        "south": { "uv": [0, 0, 16, 16], "texture": "#0" },
        "west":  { "uv": [0, 0, 16, 16], "texture": "#0" },
        "east":  { "uv": [0, 0, 16, 16], "texture": "#0" }
      }
    }
  ]
}
```

После копирования файлов выполните:

```text
/modelprops reload
```

Мод сам отправит JSON и PNG подключённым игрокам; отдельный хостинг ресурспака
не нужен.

## Анимации в стиле CPM

Model Props использует безопасный текстовый формат с ключевыми кадрами,
похожий по принципу работы на редактор CPM. Прямой импорт отдельной анимации из
`.cpmproject` невозможен: CPM связывает её с собственной моделью через
внутренние `storeID`. Поэтому в F7 выбирается JSON формата Model Props; готовый
пример находится в `examples/animation_example.json` исходного архива.
Файл `examples/animation_extra_example.json` можно выбрать вместе с ним, чтобы
сразу проверить объединение нескольких анимаций и меню F6.

При ручной установке объединённый файл кладётся в
`animations/<namespace>/<путь-модели>.json`, например
`animations/mypack/furniture/chair.json`.

Минимальный файл:

```json
{
  "format_version": 1,
  "clips": {
    "idle": {
      "duration_ms": 2000,
      "loop": true,
      "interpolation": "smooth",
      "tracks": {
        "root": [
          { "time_ms": 0, "position": [0, 0, 0] },
          { "time_ms": 1000, "position": [0, 1, 0], "rotation": [0, 8, 0] },
          { "time_ms": 2000, "position": [0, 0, 0] }
        ]
      }
    }
  }
}
```

Клипы с именами `idle`, `equip`, `swing`, `use`, `attack`, `custom`
автоматически назначаются соответствующим действиям. Другому имени клипа можно
назначить действие через объект `actions`, например `"custom": "dance"`.
Интерполяции: `step`, `linear`, `smooth`. Позиция задаётся в пикселях модели,
поворот — в градусах, масштаб — множителем `[1, 1, 1]`.

В одну модель можно добавить несколько таких JSON-файлов через F7. Итоговый
набор содержит до 32 клипов. Автоматические `idle`, `equip`, `swing`, `use` и
`attack` работают как раньше. Если ручной клип один, **F6** запускает его сразу;
если их несколько, **F6** открывает меню выбора анимации.

`root` двигает предмет целиком. Для отдельного куба добавьте в основной JSON
поле `"modelprops_id": "blade"` (также принимается `name`) и используйте трек
`blade`. Без имени элементы называются `element_0`, `element_1` и далее.

При ручной установке звук кладётся в
`sounds/<namespace>/<путь-ID>/<action-or-clip>.ogg`. Слеши внутри пути ID
кодируются как `%2F`: например, звук клипа `dance` для
`mypack:furniture/chair` находится в
`sounds/mypack/furniture%2Fchair/dance.ogg`. Меню F7 делает это автоматически:
кнопка «Звук» по кругу переключает стандартные действия и все найденные клипы.

Звуки должны быть **Ogg Vorbis** (не Opus), mono/stereo, 8–48 кГц и не длиннее
30 секунд. Сервер запускает анимацию и звук одним событием, поэтому окружающие
игроки видят и слышат их синхронно. `idle` идёт постоянно, `equip` — при взятии
предмета, `swing` — при взмахе, `attack` — при наведении на сущность и атаке,
`use` — по ПКМ, `custom` — по **F6**.

Для обратной совместимости доступны звуки действий `equip`, `swing`, `use`,
`attack`, `custom`; кроме них отдельный OGG можно назначить именованному клипу с
безопасным файловым именем: латинские буквы, цифры, `_`, `-` и `.`, кроме `.`,
`..` и системных имён вроде `CON`. `idle` обычно является зацикленной фоновой
анимацией и сам звук не запускает.

Именованные звуки и прямой выбор клипов требуют Model Props **1.3.0** и на
сервере, и у клиента. Старые модели, назначения действий и их OGG продолжают
работать без изменений.

Идентификатор файла `models/chair.json` — `modelprops:chair`, а файла
`models/mypack/furniture/chair.json` — `mypack:furniture/chair`.

## Команды и настройка в руке

- `/modelprops list` — список моделей.
- `/modelprops give <игроки> <модель> [количество]` — выдать предмет.
- `/modelprops reload` — перечитать файлы и синхронизировать игроков.
- `/modelprops reset <модель>` — сбросить положение модели в руке.
- `F6` — запустить единственную ручную анимацию или открыть меню нескольких.
- `F7` — открыть единое меню модели, текстуры, анимации и звуков.
- `F8` с предметом в руке — открыть живой редактор размера, позиции и поворота.

Предпросмотр F8 доступен игроку локально, но сохранить общую настройку может
только оператор уровня 2. Сервер проверяет значения, атомарно записывает их в
`config/modelprops/transforms.json` и сразу рассылает всем игрокам.

## Поддерживаемый формат

Поддерживаются `textures`, `elements`, `from`, `to`, поворот элемента, грани,
`uv`, поворот UV и `display`, а также плоские модели с `layer0`. Подходит экспорт
Blockbench «Java Block/Item».

Не поддерживаются Bedrock/GeckoLib JSON, наследование `parent`, tint/emissive,
`rescale` у поворота и произвольные некубические меши Blockbench.

Ограничения загрузки: до 256 КиБ для JSON модели, 4 МиБ для PNG, 512 КиБ для
объединённого JSON-анимаций, до 32 OGG, 2 МиБ на один OGG и 8 МиБ на все звуки
модели. Через меню можно объединить до 32 исходных JSON-анимаций. Сервер проверяет
структуру Ogg/Vorbis, длительность, формат анимации, контрольные суммы и
безопасные пути; одновременно у игрока выполняется только одна загрузка.
PNG ограничен размером 4096×4096 и 16 млн пикселей, модель — 1024 элементами.
В итоговом наборе анимаций допускается до 32 клипов длительностью до 60 секунд,
2048 треков и 8192 ключевых кадров суммарно (до 512 на один трек).
