# Комментарий к объединению принятых исправлений

Причина регрессии rc.1 — разные линии исходников. Его runtime происходил от
`b086e8892`, тогда как принятые окно TEST3, целые объекты и последующее исправление
каталога оставались в repair. Чистый список registry ID этой разницы не обнаруживал.

Настоящее локальное продолжение сохранено отдельным checkpoint
`41c20ee8b730c2d1567b2ab5a3d579d51bdbea1a` поверх TEST3 `3d07b4890`.
Оригинальный modified/untracked checkout пользователя не изменён. Интеграция
содержит все 30 production Java файлов и принятые logical/owner-контракты этого
checkpoint. Для 2 914 общих compatibility ID сохранены физические профили rc.1;
372 отличавшихся профиля нельзя было без проверки заменить repair-вариантами.

Карта основана на опубликованном rc.1, а не на diagnostic repair world.
Наличие более нового пользовательского сохранения не установлено. Ремонт
доказывает принадлежность по 26 804 успешным транзакциям принятого continuation
ledger и отдельно по 211 уже существующим logical-owner в rc.1. Второй источник
нужен для старых helper-масок фонарей, скамеек, дверей и других принятых семейств.
При пересечении объединяется весь граф владельцев. Неизвестные исторические
семейства не угадываются; поклеточного fallback нет.

Историческая точка реквизита `(-332,77,-137)` не доказана как целая принятая
стопка книг и не входит в успешный accepted ledger. Она оставлена как в rc.1.
Подменять её всей старой C003-сценой или поглощать соседние предметы нельзя.
Восстановленные 34 подтверждённые стопки приведены в полном отчёте транзакций.
`o_books`, `o_bag`, `o_barrel` и `o_cases_0` остаются отдельными предметами.

33 позиции прежнего intentional retirement сохранены точно как в rc.1, включая
NBT. В опубликованном rc.1 20 из них уже снова заняты после старой конвертации.
Этот ремонт не возвращает недоступные `m_*` из MODDED и не объявляет эти 33
позиции пустыми. Оба исходных ZIP неизменны.

Независимый review обнаружил и помог закрыть проверяемые ошибки: неполное
замыкание старых helpers, чужой block entity в отсутствующей helper-клетке,
orphan PART без NBT и scheduled tick у якобы уже корректной группы. Отдельно
исправлена общая проверка сохранности для `air → air` в отсутствующей секции и
побайтно неизменившемся чанке. Отрицательные тесты фиксируют эти случаи.

Офлайн PASS относится к подтверждённому адресному scope и совместимости полной
карты. Он не означает восстановления всех исторических объектов, прохождения
графического клиента или готовности к production. Первичные результаты и
ограничения находятся в [отчёте](REPORT.md) и [статусе](../RELEASE-STATUS.md).

Первый Linux CI (`36413734236`) выявил переносимый дефект старого owner-oracle:
зафиксированный SHA учитывает исходный завершающий CRLF, а Git выдавал LF.
Для одного этого файла закреплён `eol=crlf` в `.gitattributes`. Строгая
побайтовая проверка не ослаблена; модель, JAR и карта не менялись. Git checkout
без autocrlf теперь даёт исходный SHA; все 8 atomic-owner тестов проходят.

Второй Linux CI (`36414488232`) прошёл owner-oracle и обнаружил аналогичную
зависимость отчёта каталога от CRLF в хешах animation MCMeta. Исправлено
нормализованное хеширование MCMeta согласно уже заявленной textHashPolicy;
проверены равенство LF/CRLF и различие реального frametime. Обновлён только
отчёт доказательств: canonical IDs, source states, redirects и runtime JSON
остались точными; JAR и карта прежние. CI продолжает независимые задачи после
ошибки, чтобы собрать все отказы за один запуск, сохраняя общий failed exit.

Итоговый [Linux CI](https://github.com/Stasik1960/Dreamwalker/actions/runs/36415497358)
на `ae8150f7250f7810ffb836ae9eb922a67e3ead55` завершился успешно: 285 Python
тестов, 57/57 GameTests, JAR gate и независимая проверка полного поставляемого
города. Сохранены [результат](ci.json), [история двух переносимых дефектов](ci-platform-review.json)
и [SHA скачанных с GitHub файлов](remote-download-check.json). Проверочный
комплект остаётся тем же; ограничения графического клиента и полного модпака
не снимаются результатом CI.
