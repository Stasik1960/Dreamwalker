## 1. Окно: физика отдельно, декоративная модель отдельно

Цель для `o_shuttered_window`: один предмет/объект, ровно две вертикальные Minecraft-клетки. Корень `r`, единственный физический helper `r+(0,1,0)`. Столбец стены позади — другой столбец, не принадлежащий окну.

Для этого окна пользователь разрешает грубую физику: габарит 1×2×1, по одному единичному collision AABB `[0,0,0,1,1,1]` внутри каждой из двух клеток. Не выводить коллизию из полигонов рамы/створок. Open/closed, BASE/ALT и поворот не расширяют эту маску. Это конкретное разрешение для окна, НЕ правило превращать все остальные объекты в полные кубы.

Для наведения/разрушения/установки рядом используй доступную простую форму в этих же двух клетках, чтобы декоративные выступы не перехватывали нажатия в соседних клетках. Не вводить отдельную сложную систему raycast. Окно должно удаляться целиком через нижнюю или верхнюю физическую часть.

Размещение на боковую грань стены выбирает соседний передний столбец. Обычная стена позади не содержит root/helper окна. Не добавлять shared ownership для ванильных блоков, не патчить шерсть/камень/стекло и другие моды. Задник можно поставить до окна или после него, снять и вернуть обычным предметом. Окно не удаляет, не делает прозрачными и не превращает эти блоки в специальные носители.

## 2. Единственное необходимое изменение вида окна — убрать нижний зазор

Не менять углы раскрытия с 22.5° на 90°. Не перестраивать створки, раму, UV, текстуры, масштаб или художественную форму. Допустимое визуальное пересечение декоративной створки с задником больше НЕ блокер. Не запускать новые поиски идеального угла и не запрашивать разрешение на него.

Пользовательский результат: низ подоконника совпадает с нижней горизонтальной границей нижней физической клетки окна, то есть с верхом полного опорного блока непосредственно под ней. Щели под подоконником нет; сам подоконник не уходит ниже в опорную клетку.

Сделай одну постоянную вертикальную поправку всей модели окна. Вычисляй её после уже действующих transforms: `deltaY = целевая_плоскость_опоры - фактический_world_minY_подоконника`. Это однократная нормализация семейства при подготовке ресурсов, не подстройка по соседям при каждом размещении. Если кандидат уже удовлетворяет этому равенству, второй сдвиг не нужен. Не применять вслепую ни -1/8, ни +7/8 поверх уже внесённой поправки.

Одинаковая вертикальная поправка действует на все состояния. Root и pivot по сетке не переносить. Уже сделанное простое горизонтальное размещение перед стеной сохраняй, если задний столбец действительно свободен от физики окна. Не пытайся вписать все декоративные полигоны в физический габарит.

Ранее работающие shared-ownership и соединения кирпичной ограды сохранить. Для окна не развивать их дальше и не создавать новых специальных «стыков окна и стены».

## 3. Общая логика клеточных границ без новой фрагментации

Нужна одна общая машинная проверка/нормализация для существующего формата, а не ручной ремонт только скриншотов.

Для всех существующих описаний различай:
- identity и полный состав объекта;
- явно заданные физические клетки;
- collision внутри каждой клетки;
- декоративную геометрию.

Многоклеточный объект остаётся одним предметом/корнем с прежним составом. Не делать «всё = одна клетка», не создавать новые `city_*` фрагменты, не объединять/разделять семьи по внешнему виду и не менять источник конвертации.

Для незащищённых объектов с уже явно заданной физической маской нормализуй представление collision в пределах этой маски: положительные объёмы должны лежать в локальном диапазоне 0..1 своей клетки. Если одна допустимая глобальная коробка проходит через несколько уже разрешённых физических клеток, раздели её по их границам, сохранив объединение объёмов. Это разделение COLLISION, не модели и не предмета. Не отсекать существенную физику молча и не раздувать число примитивов без необходимости.

Если collision требует клеток вне утверждённой маски либо сама маска не доказана — автоматического расширения, обрезания и новой реконструкции нет. Запиши конкретный ID/состояние/причину и оставь прежнее поведение. Повторяемый однозначный дефект исправляй одним общим механизмом для всех затронутых незащищённых состояний.

Нельзя резервировать новую клетку только из-за render/selection bounds. Но пустая collision сама по себе НЕ означает, что существующий root/helper можно удалить: нужны подтверждённые ownership/interaction-правила. Существующее работающее совместное владение физической клеткой не разрушать.

Все ранее вручную исправленные семьи защищены от изменения физики, состава и внешнего вида. Окно — единственное явно разрешённое здесь исключение. На остальных запусти регрессионные проверки; общее изменение runtime не должно менять их поведение. Не переделывать C001, C474, C618, лестницы, двери и остальные принятые объекты.

Если аналогичные валидаторы уже есть — используй/исправь их, не строй новую систему контрактов. Отдельно отчитай охват, реально изменённые состояния, защищённые и пропущенные случаи. Не называть исправлением всей карты прохождение проверки двух координат.
