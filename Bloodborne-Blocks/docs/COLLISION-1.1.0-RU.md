# Аудит Bloodborne Architecture 1.1.0

## Что проверено

Просмотрен офлайн-каталог всех 503 исходных объектов; для каждого записаны фактические модели, назначение поведения и коллизии. Проверены все 18 968 состояний, а не только картинки предметов по умолчанию. Результат по каждому ID находится в `block-audit.csv` и `collision-audit.json`.

Коллизии построены из повёрнутых элементов моделей на сетке 1/16 блока. Для тонких элементов учитывается покрытие альфа-канала; пустые области не заменяются глухой стеной. Выделение и столкновения разделены для мягкого декора. Форма разбита на клетки; каждая локальная форма ограничена диапазоном [0,1] по всем осям. Объекты, занимающие несколько клеток, связываются через сохраняемые и синхронизируемые block entities без ежетикового пересчёта геометрии.

Автономная Java-проверка использует реальные классы VoxelShape из Minecraft, но не запускает игру, сервер, реестры или мир. Проверяются полное покрытие состояний, конечные размеры, границы каждой клетки и обход рёбер. Для трёх типов двойных дверей проверяется закрытый центр и свободный коридор шириной 0,6 и высотой 1,8 блока после открытия во всех четырёх направлениях.

Ресурсная проверка: 3 846 JSON, разрешение всех используемых моделей и текстур, допустимые координаты элементов, декартово произведение свойств и вариантов, основание новых закрытых объектов в нулевой точке. Для 497 объёмных item-моделей проверены радиус не более 7 модельных единиц и явные трансформации обеих рук, GUI, рамки и земли. GUI-масштаб 0,85 ограничивает диаметр геометрии 11,9 пикселя.

## Совместимость и исходные исключения

Сохранены все 503 публичных ID и старые сочетания свойств. Добавлены `assembled` и `open` там, где они нужны; служебный `architecture_part` не является отдельным предметом.

Исходный пак содержит полностью прозрачные и пустые варианты. У 10 ID пусто состояние по умолчанию; они скрыты из творческой вкладки, но не удалены из реестра. Их список записан в `resource-checks.json`. Пустые состояния в некоторых multipart-моделях допустимы: они означают отсутствие соединённых деталей, а не потерянный коллайдер.

Разные физические модели не могут случайно выбираться для одного серверного состояния. Поэтому 99 наборов закреплены за первым вариантом; одинаковая геометрия с разными текстурами по-прежнему может чередоваться. Случайное пространственное смещение растительности отключено. Это ограниченные визуальные изменения старой карты, которые нельзя считать побайтным сохранением её прежнего вида.

Книги остаются исходной моделью из 32 элементов; нормализация item-моделей не масштабирует установленную геометрию. Обратные стороны шести моделей дверей используют дверную текстуру вместо растянутого маленького участка кровли. Ранее восстановленные стороны других моделей используют существующие UV, а не неизвестные авторские изображения.

## Размещение, разрушение и миграция

Новые предметы получают нижнюю краевую точку отсчёта. Проверяются вся занимаемая область, сущности, границы мира и загруженные чанки. При занятости установка отменяется, соседние блоки не заменяются. Поршни не могут разорвать крупный объект. Служебные клетки перенаправляют использование, выбор и разрушение владельцу; потерянные части очищаются после загрузки соответствующих чанков.

Старые постройки автоматически не сдвигаются. Для заполнения свободных клеток их коллизией предусмотрены `/bloodborne repair 16 preview` и `/bloodborne repair 16 apply`; максимальный радиус — 32. При пересечении с чужим блоком объект пропускается целиком. Это не конвертер планировки и не автоматическая перестройка города. В предоставленных рабочих файлах нет пользовательского мира для проверки и миграции; мир пользователя не открывался и не изменялся.

## Что пока не измерено

По прямому указанию пользователя Minecraft не запускался. Нет замеров FPS на его ПК и подтверждения в живом мире для взаимодействия нескольких игроков, выгрузки чанков, сохранения/загрузки, взрывов и совместимости сторонних модов. Офлайн-рендеры предназначены для проверки геометрии и текстур, а не являются скриншотами из игры. После подготовки выпуска пользователь разрешил публикацию на GitHub.
