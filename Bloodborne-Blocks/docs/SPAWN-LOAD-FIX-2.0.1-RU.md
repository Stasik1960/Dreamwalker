# Bloodborne 2.0.1: остановка загрузки спавна на 58%

Исправление JAR дополняет исправленную карту `2.0.1-lightfix`. Сброс кэша
Starlight устранил ошибки чтения освещения, но не вторую причину остановки.

## Подтверждение по снимкам потоков

В `threads-1.txt` и `threads-2.txt`, снятых с интервалом 12,80 секунды, один и
тот же Server thread ожидал завершения загрузки чанка в следующей цепочке:

```text
getChunkBlocking
World.getBlockState
ArchitecturePartBlockEntity.validateOwner:48
ArchitecturePartBlockEntity.lambda$registerValidation$0:34
ServerChunkEvents.CHUNK_LOAD
```

Проверка `isChunkLoaded` в прежнем коде не гарантировала, что последующее чтение
через World не начнёт ожидать завершения подготовки чанка. Обработчик, который
сам ещё участвовал в этой подготовке, попадал в блокирующее чтение. Предыдущий
анализ исходников без снимков потоков ошибочно считал такую проверку достаточной.

## Исправление

- Для текущего чанка обработчик использует непосредственно `WorldChunk`,
  переданный событием, без повторного запроса через World.
- Другие чанки читаются через `ServerChunkManager.getWorldChunk(x,z)`.
  В закреплённой версии 1.20.1 этот метод проверяет future через `getNow` и
  возвращает null, пока чанк не готов. Проверка переносится до загрузки корня.
- Обработчик загрузки не изменяет мир. Потерянные части складываются в очередь
  без дубликатов и удаляются после повторной проверки на `END_WORLD_TICK`:
  максимум 256 кандидатов за тик. Проверка не отключена.

Registry ID, NBT, геометрия, инвентари и блоки карты не меняются.

## Проверка

`tools/check_chunk_validation.py` проверяет скомпилированный класс: запрещает
блокирующие чтения через World, разрешает удаление только в обработчике
очереди тика и проверяет неблокирующий `getNow` в байткоде закреплённого Minecraft.
Прежний dev-JAR 2.0.0 отклонён этой проверкой именно из-за блокирующего чтения;
исправленный класс проходит. Это проверка против конкретной цепочки из дампов,
без запуска игрового сервера.

`gradlew.bat --offline --no-daemon build` с Java 17: BUILD SUCCESSFUL (6 мин 17 с).
Проверки geometryCheck, modularDataCheck и упакованных mixin прошли.
Сравнение JAR 2.0.0 и 2.0.1 показало изменения только в
`ArchitecturePartBlockEntity.class` и `fabric.mod.json`; ресурсы не менялись.

Готовый файл: `bloodborne-blocks-2.0.1-mc1.20.1.jar`, 92 706 876 байт.
SHA-256: `e400442c1711b013dd73d2a7763fc7c34e778af05876d90b69c2bedced3c1212`.

Игровой запуск на удалённом сервере требует проверки администратором;
Minecraft на компьютере пользователя не запускался.

## Установка

Остановить сервер и заменить JAR Bloodborne 2.0.0 на 2.0.1 на сервере и клиентах.
Использовать уже выданную карту `Ether-Bloodborne-2.0.1-lightfix.zip`.
Повторно переносить карту или запускать команды обновления не требуется.
