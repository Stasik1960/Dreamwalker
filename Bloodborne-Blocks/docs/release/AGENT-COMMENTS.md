# Комментарии агента к controlled retirement

Решение пользователя снимает конкретную неопределённость для 23 отсутствующих
composite ID: сохранять их потерянную геометрию больше не требуется. Реализован
отдельный offline-инструмент, который принимает только закреплённый исходный
ZIP и точный список 33 клеток. Он проверяет все исходные состояния до создания
копии; несовпадение хотя бы одной клетки запрещает запись. Исторический recovery
не запускался.

Независимый verifier заново сравнивает клетки, типизированный NBT, raw payloads
неизменённых chunks и все файлы мира, а также фактические helper cells с их
owner roots и state footprints. Он не доверяет одному ledger: негативные тесты
подделывают ledger/file hashes, меняют соседнюю клетку и чужой NBT, добавляют
unknown palette entries и orphan helpers. Проверка прошла на настоящей копии.

Граница этого результата существенна: после удаления мир остаётся legacy.
Поэтому helper footprints проверяются по исходной legacy-схеме; current geometry
используется только для ID, которых в legacy-схеме нет. Поле
`notRuntimeCompatibilityProof: true` и отдельные 43,634 IDs вне rc.1 registry
не позволяют принять этот PASS за совместимость с новым runtime.

Полная конвертация проверялась отдельно на ещё одной новой копии существующим
whole-owner engine из локальной repair-линии. Зафиксированы хэши его кода и
данных; этот эксперимент не переносит весь незавершённый repair runtime в rc.1.
Нулевой повторный проход сам по себе недостаточен: отвергнутые группы тоже
могут оставаться неизменными. Нужны нулевые fragmentation/protected loss,
foreign overwrites, unknown/rejected и реальные dedicated/client запуски.

Выявленная нехватка ownership-доказательств относится к известным объектам,
а не к уже согласованным 23 ID. Например, исторический white-wool owner около
(-660,36,-92) не совпадает с текущими helpers/air; другая stair composition около
(-730,-31,-71) содержит несколько разных m_* states и неполную историческую
геометрию. Сохранённые clipped meshes не задают однозначную принадлежность этих
клеток целому owner. Придумывать связь, восстановить старую раскладку или удалить
дополнительные клетки означало бы выйти за разрешённый объём изменения карты.
Три отсутствующих runtime mappings лестниц — отдельная задача генератора;
их исправление не устраняет неполные owner-группы.

Работа разделялась на узкую разведку ownership/evidence, независимый review
writer/verifier и запуск проверок. Результаты агентов принимались только после
сверки с первичными файлами, exit codes и фактическими артефактами; ошибочные или
неполные запусковые отчёты не используются как доказательства PASS.

Отдельная копия с ровно 33 удалениями готова. Production-релиз пока не готов.
Фактические команды, новые proofs, остаточные отказы и gates находятся в
[status.json](status.json), [RETIREMENT.md](RETIREMENT.md) и
[RELEASE-STATUS.md](../RELEASE-STATUS.md). Старые комментарии сохранены в evidence.
