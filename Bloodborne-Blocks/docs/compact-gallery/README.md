# Bloodborne: компактный каталог и город с галереей

Мод и карта этой версии используются вместе. Удалите предыдущий Bloodborne JAR из `mods`, установите новый JAR и откройте мир из нового архива. Автоматически открывать старую карту с этим каталогом нельзя: удалённым техническим ID требуется выполненное в поставляемом мире преобразование.

Готовые файлы: `bloodborne-blocks-2.1.0-compact-gallery.1.jar` и `Bloodborne-Compact-City-Gallery-2026-10-04.zip`. Папку мира из ZIP поместите в `saves`, чтобы `level.dat` находился непосредственно внутри неё. На GitHub опубликованы собственный мод, карта, снимки и материалы проверки; полные клиентские архивы со сторонними модами доступны только локально.

Город преобразован полностью на основе исправленной карты `2.1.0-unified-gallery.3` и совпадающей по координатам исходной карты. Повреждённая rc.4 не используется. Сохранены ранее собранные цельные объекты, 23 результата «Правки финал», сторонние блоки и 416 блоков Yuushya.

Каталог сократился с 3 604 публичных блоков до 1 825; число состояний со служебным блоком — с 171 155 до 12 791. Основой остаются 49 утверждённых объектов beta.1 (`acc0e0dcae1ae895305b704b7c7e6cd145204d61`), отдельный куст, утверждённые исправления и цельные модели исходного ресурс-пака, необходимые всему городу. Поэтому новый каталог содержит больше 49 объектов: возврат только к этим 49 оставил бы большую часть городского оформления без моделей.

Из моделей больше не создаются отдельные блоки для каждой обрезанной ячейки. Совпадающие цельные модели объединяются с учётом поворота, текстур, формы и поведения. Для случайных вариантов исходного пака оставлен первый авторский вариант; все одновременно применяемые части multipart собираются вместе. Существенно отличающиеся конструкции сохраняются отдельно. Дерево и куст имеют разные ID; вертикальные лестницы остаются цельными. Установочный поворот выбирается по направлению взгляда.

При преобразовании мира сохранены 472 672 пересечения коллизий. Разрешение пересечений действует только при офлайн-сборке этой карты. Обычная установка после поломки проверяет занятость места, как раньше. В 1 629 местах коллизия конструкции соседствует со сторонним блоком: сторонний блок сохранён, его ячейка не превращалась в служебную часть Bloodborne.

## Как редактировать галерею

Галерея находится над городом на Y=228. Между соседними платформами ровно три блока. На каждой редактируемой платформе — один публичный ID и его цельная конструкция; её невидимые служебные части не являются отдельными образцами. Дополнительно есть одна подписанная служебная демонстрация, которую не нужно редактировать.

- Чтобы удалить объект из будущего мода, сломайте весь образец и оставьте площадку пустой.
- Чтобы заменить объект, поставьте вместо образца другой блок либо постройте нужную конструкцию из нескольких блоков.
- Стройте в границах своей платформы, выше её основания и ниже Y=320. Не меняйте табличку с цифровым ID и основание.
- Сохраните и верните весь мир, включая `editable-gallery-manifest.json`. Таблички и цифровые ID связывают правку с объектом; положение платформы не является новым ID блока.

`Gallery-Objects.csv` содержит ID, исходные материалы и команды телепортации. Все внутренние цифровые ID уникальны и состоят из пяти цифр, включая ведущие нули. Исходный файл разметки хранит ожидаемые клетки и служебные связи, а инспектор читает весь объём площадки, включая добавленную постройку.

## Память и проверка

Уменьшение числа состояний Bloodborne на 92,5% не означает такого же уменьшения общей памяти сборки. В ней есть другие крупные каталоги моделей; отдельно нагружают клиент генерация LOD и первый запуск инструментов KubeJS. Результаты конкретных запусков, лимиты памяти и состав проверяемых профилей находятся в `Verification/runtime.json`.

Локальный `Mods-Compact-2026-10-04.zip` содержит исходную сборку с заменённым Bloodborne. Это сохранённый состав, без отдельной проверки клиента с включённым Distant Horizons; в manifest он отмечен `runtimeVerified: false`. Его JAR извлекаются в `mods`.

Проверенный `Client-Compact-LowMemory-2026-10-04.zip` извлекается в **корневую папку игры**: внутри находятся `mods/` и `kubejs/config/probejs.json`. Перед установкой уберите предыдущий Bloodborne JAR и Distant Horizons из `mods`. В профиле отсутствует Distant Horizons, добавлен [FerriteCore 6.0.1 Fabric](https://modrinth.com/mod/ferrite-core/version/6.0.1) и выключен ProbeJS, генерирующий материалы для разработки скриптов при входе; KubeJS и игровые скрипты остаются. Остальные JAR сохраняются побайтно. FerriteCore не является обязательной зависимостью самого Bloodborne.

Проверка на 4 ГБ завершилась, но память подошла почти вплотную к лимиту, с задержками сборки чанков. Для полной сборки нужен запас; имя LowMemory означает сокращённую нагрузку, а не гарантию работы на слабом ПК. Ограниченный запуск не заменяет проверку длительной игры. `Foreign-Collision-Cases.csv` содержит полный список 1 629 мест, где сохранён сторонний блок в пересечении коллизий.

Повторный клиентский запуск с тем же составом при лимите 6 ГБ прошёл с проверкой геометрии всех 1 825 моделей и снимками города, дерева и куста. Dedicated-server при лимите 3 ГБ прошёл запуск и проверку 12 791 состояний / 66 064 переходов через WorldEdit. Полная сборка проекта: `check build`, 90 задач, успешно. В исходной пользовательской сборке остаются ошибки интеграции JEI с Create/Farmer's Delight и предупреждения совместимости Immersive Portals; версии этих модов не менялись.

## Воспроизведение разработчиком

Java 17, wrapper Gradle 8.8, Minecraft/Fabric/Yarn/Loom не обновлялись. Python требует NumPy; путь передаётся через `-PbloodbornePython=...`.

1. Получить LFS-архивы исходной карты, ресурс-пака, исправленного мира `.3` и замороженные JAR `2.0.1` и `.3`. Их SHA фиксируются в исходных проверках и материалах выпуска.
2. Создать каталог полных исходных моделей: `python tools/compact_source_catalog.py --states docs/compact-gallery/required-source-states.json --output build/compact-generated/source`.
3. Применить каталог: `python tools/assemble_compact_registry.py --source build/compact-generated/source --apply`. Неизменяемый снимок утверждённых объектов извлекается из проверенного JAR `.3`, а не из текущего каталога.
4. Обновить цифровые ID штатным `tools/sync_debug_ids.py`, затем заново сформировать `tools/build_creative_equivalence.py`. Не присваивать существующим объектам чужие цифровые ID.
5. Запустить `convert_compact_city.py` с исправленным архивом `.3`, исходной картой, новым каталогом, замороженным каталогом `.3` и `protected-world-oracle.json`. Конвертер разрешает пересечения только здесь, проверяет совпадение наборов чанков, связывает продолжение с хешами файлов и проверяет служебные части перед завершением.
6. Запустить `build_compact_approval_gallery.py` для полученного города с границами `-960 -64 -656 111 224 415`. Проверить инспектором исходное состояние галереи и `verify_compact_city.py --all-states` неизменность города за её пределами.
7. Выполнить `gradlew.bat check build`, `test_compact_assets.py --jar <готовый JAR>` и изолированные client/server-проверки `run_compact_pack_qa.py` на копиях мира. В JAR не допускаются файлы незарегистрированных промежуточных вариантов.
8. Упаковать согласованную пару `package_compact_release.py`. Пакет проверяет хеши JAR/карты, полное покрытие галереи, результаты проверок и сохранность остальных модов в локальных профилях.

Для последующего импорта правок пользователя: `python tools/inspect_editable_city_gallery.py --world <редактированный мир> --manifest <исходная разметка> --output <результат.json>`. Категории `deleted`, `replaced` и `multi-block-construction` определяют дальнейшее удаление либо замену объекта в моде. Сначала проверяется разметка, затем создаётся новая версия мода и преобразуется город.
