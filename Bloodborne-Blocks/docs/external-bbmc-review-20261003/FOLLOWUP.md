# Уточнения: клиент, размеры миров и экспорт моделей

Дата: 2026-10-03. Эти сведения дополняют [основное мнение](OPINION.md). Графический клиент пока не запускался; модели экспортированы локально, игровой код нашего Fabric-мода не менялся.

## Условия проверки клиента

Локально найдены Java 17, Forge 1.18.2 / 40.2.21 client profile, его libraries/native DLL и asset index. Это проверка наличия файлов, не успешного запуска. Profile не имеет inheritsFrom; отсутствие отдельной папки vanilla 1.18.2 само по себе не считается доказанным препятствием.

Для базовой проверки нужен отдельный game directory: Minecraft 1.18.2, Forge 40.2.21, предоставленные Bloodborne JAR и GeckoLib Forge 3.0.57, копия v16 и resource pack v15. Сначала запуск без Oculus/Rubidium/Kappa: это необязательный визуальный профиль. При ошибке чтения pack v13 разумнее проверить v15, не подменять ZIP parser незаметно.

Нужен обычный запуск через легитимную сессию лаунчера и возможность работать с окном игры. В текущем окружении доступен browser control, управление native Minecraft window недоступно. Полный обход, взаимодействие и оценку анимаций поэтому нельзя объявить выполненными по одному логу. Пользователь может вручную запустить выделенный профиль; пароль/token передавать не требуется. Для авторизации production Gravit ничего не меняется.

Успешный старт ещё предстоит подтвердить: меню → мир → resource reload → реальные объекты → save/reload. Dedicated Forge с Bloodborne и GeckoLib уже показал startup FAIL на клиентском PoseStack; клиент содержит этот класс, но другие ошибки не исключены.

## Насколько карты больше v1

За оригинал в этом сравнении принята предоставленная v1; она не автоматически равна нашему текущему MODDED-миру.

| Версия | Сохранённые terrain chunks | Non-air блоков | Колонки с поверхностью выше Y=0 по доступным heightmaps | Отношение колонок к v1 |
| --- | ---: | ---: | ---: | ---: |
| v1 | 17 970 | 39 632 662 | 229 485 | 1,00× |
| v13 | 35 890 | 37 347 952 | 513 920 | 2,24× |
| v14 | 35 890 | 64 727 833 | 748 684 | 3,26× |
| v15 | 35 890 | 64 726 060 | 748 683 | 3,26× |
| v16 | 35 890 | 64 725 520 | 748 683 | 3,26× |

Таким образом, v16 содержит на 99,72% больше сохранённых чанков и на 63,31% больше non-air блоков. Наблюдаемый надземный footprint по доступным heightmaps больше в 3,26 раза; его chunk-aligned внешняя рамка 1520×1552 против 816×576 у v1. Рамка включает пустоты и не является площадью застройки.

Heightmap отсутствует у 5085/17970 чанков v1 и 8654/35890 поздних миров: покрытие 71,70% и 75,89%. Метрика включает грунт/фундаменты, пропускает низкие/подземные части и entity geometry, может использовать устаревшие после внешнего редактирования heightmaps. Совпадают только 46702 измеренные колонки v1/v16; положение объектов сильно изменилось. Это не доказательство, что каждую прежнюю именованную локацию увеличили в 3,26 раза. Для её точного сравнения нужны границы конкретных локаций и графический обход. v15/v16 практически одинаковы по этой метрике; их различия главным образом в декоре.

Данные: [map-growth.json](map-growth.json), [полный block/NBT audit](map-analysis.json). Первые 12 массивов высот сверены с полным NBT-декодером; итог v16 совпал с предыдущим рендером. Оба используют одну формулу упаковки высот, поэтому это cross-check воспроизводимости.

## Что целесообразно внедрять сейчас

1. Расширение законченных архитектурных семейств: витражи и разбитое стекло; кладка; углы/края крыш; лестницы, стены и карнизы. Добавлять согласованные варианты в наш каталог, сохранять старые registry IDs.
2. Статуи, настенные лампы, мини-фонари, люстры. Свет, render/outline/collision и опору задавать явно, привязывая составные части к одному owner.
3. Статичный geo-декор: мебель, гробы и их композиции, кареты, деревья. Выбрать позу, преобразовать геометрию и UV, создать наши collision/support/helper shapes. Для запечённой статичной геометрии GeckoLib не требуется.
4. Авторские инструменты как идеи: выбор цельного объекта, допустимый поворот, preview установки, атомарное удаление с сохранением соседних/shared объектов. Реализацию адаптировать к нашим ownership и permission правилам.
5. Композиции карты как контрольные образцы стыков, проёмов, крыш и размещения декора. Они полезны для проверки геометрии, но не восстанавливают автоматически исторические registry IDs и потерянное membership нашего города.

Лучший первый этап — архитектура и статичный декор. Подвижные двери/ворота/рычаги доступны как художественные образцы и анимации, но требуют собственной серверной state machine, NBT, синхронизации и корректной ориентированной физики. Бой, mobs, stamina/rally, Insight и Blood Echoes — отдельная следующая задача. Прямой перенос Forge-кода не исправляет наши текущие owner/shared-cell проблемы.

Исходный комплект содержит условия согласования повторного использования ресурсов. Идеи и наша реализация могут изучаться сейчас; включение авторских файлов в распространяемую сборку требует разрешённых условий использования.

## Какие модели и анимации уже извлечены

Локальный ZIP содержит 339 исходных asset files: 101 geo JSON, 32 animation JSON с 235 именованными записями анимаций, 95 PNG и 111 обычных item/block model JSON. Повторяющиеся имена в разных JSON здесь считаются отдельными записями. ZIP CRC и SHA-256 всех 339 файлов сверены с исходным JAR; JSON syntax проверен.

Добавлены наши manifest и CSV связей «AnimatedGeoModel class → geometry → texture → animation». Есть полные наборы для дверей, главных ворот, рычага, Saw Cleaver и Cleric Beast. В исходнике нет .bbmodel проектов: извлечены экспортированные geometry/keyframes. GeckoLib/Bedrock formats можно изучать в соответствующем редакторе/Blockbench; [официальная документация Blockbench](https://blockbench.net/wiki/guides/bedrock-modeling/).

Не все 101 модели анимированы: 64 ссылки кода указывают на 27 animation paths, отсутствующих в исходном JAR. Большинство относится к статичному декору с predicate STOP; это само по себе не доказывает ошибку рендера. AI, условия проигрывания, controllers, event timings и программные движения костей из Java не превращаются автоматически в JSON-анимации.

Экспорт оставлен в локальной папке Downloads под именами BBMC-extracted-models-20261003 и BBMC-extracted-models-20261003.zip. Авторские assets и декомпилированный код в GitHub не загружены. Публикуются этот анализ, вычисленные числа и наш переносимый скрипт.
