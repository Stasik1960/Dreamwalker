# Audit-only: полнота Bloodborne-Blocks, 2026-09-24

Проверен checkout `4ac9c190a8a728417282374c0c586bb6653b943e`, выданный production JAR
и `production-palette-gallery-ready-20260924.zip`. Историческая база сравнения:
`62346a93595a1ce8fa1bc453658e1d0bebe0f6a0` и сохранённые authoring manifests.

## Главный вывод

**Текущая галерея — ограниченная production-палитра из 33 logical ID, по одному
каноническому BASE/closed/default образцу каждого. Это НЕ полный каталог ресурспака
и НЕ полный каталог вариантов даже этих 33 объектов.** Название PRODUCTION означает
прохождение нынешнего фильтра, а не подтверждённую визуальную приёмку.

Причина основной потери покрытия найдена: генератор берёт семейства только из
замороженного Contract V2, исключает hidden/retired ID и специально возвращает C282.
Он не строит production-палитру из всего исходного мира или всего ресурспака.
251 прежнее non-V2 семейство осталось за этим фильтром. Это подтверждённое сокращение
runtime-каталога, но само прежнее наличие семейства не доказывает корректность его
старой модели/поведения. Ещё 14 удалённых ID относятся к семантическим заменам,
разделениям, объединениям, дублю и совместимости; это отдельная категория.

## Что произошло с дверями и «исправленными» объектами

- `o_acacia_door`, `o_birch_door`, `o_dark_oak_door`, `o_shuttered_window`
  действительно отсутствуют: non-V2 → UNRESOLVED → исключение из runtime.
  Их carriers и модели присутствуют в исходной карте; причина не в отсутствии source.
- C282 **есть**: `o_c282`, координаты галереи **49 64 126**. Это одна двустворчатая
  дверь; отдельные `_a/_b` сняты согласно последнему изменению семантики.
  Она не заменяет автоматически все три прежних семейства дверей.
- Железные ворота **есть**: `o_iron_gate`, **67 64 160**. Галерея показывает closed,
  а не отдельный open-образец.
- 21 из 251 исключённого семейства раньше имели не-static behavior: двери, ставни,
  соединяемые ограды/бордюр, лестницы, освещение, скамьи. Полный список — в FINDINGS.
- C002 по сохранённому решению оставлен целой композицией, C003 — OBJECT из частей
  1–6. Их нынешняя составность не возникла при последнем cleanup. C1979 разделён
  на пять **групп**, не на каждый component. Для дальнейшего split надо сначала
  указать, какая из этих записанных границ больше не соответствует намерению.
- Для **32 сохранившихся семейств** все textured vertices совпали с замороженной
  исправленной базой после точных texture aliases. C282 намеренно перекомпилирован.
  Это подтверждает сохранность геометрии при cleanup, **не** визуальную правильность
  исходных исправлений. Проверки человеком в клиенте в этом аудите не было.

## Недостатки отчётности и QA

1. Проверки registry и галереи сверяют один и тот же отфильтрованный manifest.
   Такая проверка не замечает выпавшие за его пределы семьи. Проверки только количества
   потомков одного review также не гарантируют правильные ID/границы частей.
2. У всех production-строк общий provenance «NightmareRunning QA», но восемь семейств
   явно NOT_MENTIONED в исходном coverage. Это не доказательство визуального PASS.
3. Исторические SAFE_BLOCKED случаи C282/C654/C1491 не стали автоматически успешной
   миграцией от прохождения free-space gallery/tests. В этом проходе конвертация
   вообще не запускалась. У трёх live wall-family остаётся неопределённая mount plane;
   неизвестный забор из image 9 по-прежнему NEEDS_USER_DEBUG.

## Следующие три шага — только после согласования

1. **Сначала утвердить целевое покрытие и потери.** Из готового missing-list выделить
   обязательные двери/ставни и остальные 21 ранее функциональные семьи. Явно решить
   «вернуть/заменить/отложить»; не восстанавливать вслепую 46 тысяч fragment ID.
   Одновременно точечно уточнить границы C002/C003/C1979 по существующим карточкам.
2. **Исправлять одним согласованным пакетом.** Сначала обязательные семейства и
   подтверждённые split-решения, сохраняя оригинальный source. Использовать готовые
   census/geometry/mapping; не повторять discovery или конвертацию города. Одна
   накопительная сборка/галерея после пакета, затем проверка в клиенте.
3. **Запретить молчаливое выпадение.** Независимый coverage manifest «source family →
   требуемые ID/state/части → registry → gallery», golden geometry/partition checks
   и явная запись причины каждого исключения. Проверять open/closed, направления,
   варианты и source conflicts отдельно; не считать BUILD/LevelStorage визуальным PASS.

## Границы этого аудита и воспроизведение

Мод, tools, production manifests, JAR, original ZIP и галерея не изменены.
Созданы только файлы в этой audit-папке. Нет build, cleanup, auto-fix, world-conversion,
клиентского запуска, commit или push. Существовавший до аудита dirty GameTest XML
и посторонние untracked файлы оставлены нетронутыми.
