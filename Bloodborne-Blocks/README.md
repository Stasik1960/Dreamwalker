## Пересборка 2.0.1

Строительная палитра из исходного Bloodborne resource pack. Мод не генерирует город: отдельно подготовлена копия предоставленного мира Ether с перенесёнными блоками. Исходные архивы и рабочий мир не изменяются.

Обычная кладка, секции оград, карнизы и другие строительные детали разделены по клеткам. Их можно ставить и ломать по одной секции; модель и простая коллизия находятся внутри той же клетки. Повороты доступны через направление установки. Большие двери, деревья и мебель остаются цельными объектами. Старые 503 registry ID сохранены для чтения прежних миров.

Старые предметы строительных моделей в инвентаре при установке выбирают одну новую секцию. Они не возвращают на карту прежние многоблочные ограды. Обычные ступени, полублоки и большие функциональные предметы сохраняют своё поведение.

- Вместо физики старого блока-носителя используются формы и названия по назначению модели. У секции не больше четырёх простых коробок столкновения и одна рамка выделения. Мягкая растительность не сталкивается с игроком.
- Полноценные кубы кладки имеют обычное отсечение скрытых граней. Статические секции не используют block entity, поиск соседних частей и периодические тики.
- Разрезанные модели получают торцы с UV из исходной текстуры. Плоским декоративным элементам добавлена небольшая толщина. Геометрия предметов ограничена размерами ячейки/инвентаря.
- Сохраняются открывание больших дверей по ПКМ, сидение на чугунной лавке и подъём по лестницам. Новые лестничные секции входят в `minecraft:climbable`.
- Старые пересечения нескольких моделей в одной клетке карты превращаются в статические составные секции. Их технические варианты скрыты из творческой вкладки, но доступны через выбор блока на карте. Это сохраняет композицию без отдельных тикающих объектов.
- Каменный мусор, ранее носивший ID `spruce_button`, удалён из перенесённой карты. Настоящие ванильные кнопки не затрагиваются.

## Установка

Для Ether используйте последний исправленный архив **2.0.2-positions** с JAR
**2.0.1**. В нём удалены все 4 905 барьеров и восстановлено исходное положение
смещённых объектов; ранее выполненное исправление освещения сохранено.
[Восстановление расположения и ограничения](docs/MAP-POSITIONS-2.0.2-RU.md).
В первом архиве
2.0 остались метки Starlight после удаления массивов света, что вызывало ошибки
при подготовке спавна. Свет исправлен в карте, а остановка обработки чанков —
в JAR 2.0.1. Нужны оба исправления.
[Диагностика и проверка исправления](docs/LIGHTING-FIX-2.0.1-RU.md).
[Исправление ожидания загрузки чанков](docs/SPAWN-LOAD-FIX-2.0.1-RU.md).

Готовый мод: [bloodborne-blocks-2.0.1-mc1.20.1.jar](../releases/Bloodborne-Blocks/bloodborne-blocks-2.0.1-mc1.20.1.jar).

Нужны Minecraft **1.20.1**, Java **17**, Fabric Loader **0.16.10+**, Fabric API **0.92.9+1.20.1**. Мод ставится на сервер и клиент. Замените прежний JAR Bloodborne; два выпуска одновременно оставлять нельзя. Исходный Bloodborne resource pack и старый `bloodborne_transparency_fix` следует отключить. Для используемой ранее связки Sodium 0.5.11 требуется Indium 1.0.34.

Подготовленный мир — отдельная копия, его не нужно обновлять командами в каждом чанке. Оставьте остальные моды из прежней сборки: в карте сохранены их блоки и данные. В 2.0.2 прежние автоматические перемещения декора отменены, исходная композиция имеет приоритет. Для пересекающихся крупных объектов полнота столкновений и открывание всех дверей требуют игровой проверки. Сам архив мира с данными игроков выдаётся локально и не включается в Git.

Замена JAR сама по себе не разделяет старую карту. Для другой карты предназначен офлайн-конвертер `tools/convert_modular_world.py`: он требует новый выходной каталог и не перезаписывает источник. Таблица переноса в текущем выпуске покрывает состояния предоставленного Ether; неизвестные состояния другой карты отклоняются с ошибкой, а не удаляются.

## Проверки и ограничения

`geometryCheck` проверяет старые состояния и игровые формы; `modularDataCheck` — новую палитру, координаты, UV и геометрию всех направлений. Python-проверки проверяют ресурсы, разрезание моделей и сохранность чанков, сторонних блоков, биомов и block entity при переносе.

Minecraft на компьютере пользователя не запускался. Доступной удалённой игровой машины в этой сессии нет. Офлайн-рендеры и проверки данных **не являются замером FPS/TPS или полноценным тестом клиента/сервера**. Реальные взаимодействия, освещение после пересчёта и совместимость всей сборки требуют игровой проверки.

Полные данные переноса и результаты: [отчёт пересборки](docs/REBUILD-2.0-RU.md). Документы `VALIDATION-RU.md`, `OPTIMIZATION-1.2.0-RU.md` относятся к предыдущим выпускам.

## Сборка и генерация

```sh
bash ./gradlew check build
```

Windows: `.\gradlew.bat check build`, Java 17. Закреплены Gradle 8.8, Loom 1.6.12 и Yarn `1.20.1+build.10`. Готовые ресурсы включены в исходники; повторная генерация для сборки не требуется.

Дополнительная проверка взаимодействий на headless Minecraft-сервере:
`.\gradlew.bat logicalGameTest` (Linux: `bash ./gradlew logicalGameTest`).
Тестовый мир изолирован в `build/gametest`; сервер сам завершается, XML-результат —
`build/test-results/gametest/TEST-logical-gametest.xml`. Тестовые классы не входят в
пользовательский JAR. Этот прогон не заменяет визуальную приёмку 23 примеров.

Начало регенерации: каталог назначений → `build_modular_palette.py` → `convert_modular_world.py SOURCE NEW_TARGET`. Один исходный конвертер не даёт готовый мир. Отчёт пересборки описывает исторические стадии 2.0; для актуальной карты обязательна последующая правка [2.0.2](docs/MAP-POSITIONS-2.0.2-RU.md). На восстановленной карте нельзя повторять автоматические relocation-стадии и `repair_modular_interactions.py`: они снова сместят объекты. Нельзя запускать первый генератор после переноса карты отдельно: он удалит составные варианты, на которые уже ссылается эта карта. `prepare_architecture.py` относится к первоначальному импорту и повторно к нынешним ресурсам не применяется.
