# Решения при оптимизации готовой карты

Карта города остаётся декорацией. Приоритет: стабильность, сохранность внешнего вида, точных коллизий, блоков v12 и ранее согласованных цельных конструкций.

- Физические состояния объединяются только при полном совпадении формы, оптики, функций, render layer и признака AO. Визуальный индекс хранится отдельно в чанке. Геометрия и исходные индексы каталога сохранены.
- Цельные конструкции используют прежние native_grid ID и роли. Их части не превращаются в независимо разрушаемые фрагменты. Данные существующих механизмов и NativeGridBase на служебных блоках не переносятся.
- Миграция выполнена по копии уже готовой карты: 2 140 585 обычных ячеек в 3 643 чанках. Исходный город заново не экспортировался. Перепаковка 13 изменённых регионов сохраняет сжатое содержимое чанков побайтно.
- Прежняя отменённая задача очистки пустых служебных файлов в эту работу не включена.
- В проверке цельного разрушения непосредственный запрос сущностей в тот же тик не увидел уже созданный предмет. Исходный FAIL сохранён. Отдельная сверка штатно сохранённого NBT подтвердила ровно один правильный предмет и отсутствие оставшихся частей конструкции. Повтор всей проверки ради задержки измерителя не выполняется.
- Первый графический запуск был прерван до подключения клиента вместе с ходом работы. Это не принятая проверка и не измерение производительности. Выполняется новый конечный запуск.
- Следующая попытка остановилась из-за неверных 40 тиков в плане измерителя (его контракт: 80..400). План исправлен на 80, добавлена проверка до запуска JVM; исходный отчёт об ошибке сохранён. Производственный мод и карта из-за этого не менялись.
- В диагностическом запуске замечено отклонённое клиентом значение simulationDistance=4. В последующих сопоставимых профилях явно задано допустимое клиентское 5, серверное 4. Диагностический запуск не используется как сопоставимый FPS-замер.
- Смешанные исходные объекты ранее целиком отправлялись в translucent. В клиентском рендере теперь общий существующий анализ UV/alpha на всех mip-уровнях отправляет доказанно непрозрачные грани в solid. Неоднозначные и полупрозрачные грани сохраняют прежний translucent, прочие вырезанные грани — cutout. Координаты/UV/цвета/освещение и физические данные не изменяются. Это устраняет неправильную категорию прозрачности; точный исходный сквозной провал у книг на трёх видах сверху не воспроизведён, поэтому низкие ракурсы добавлены в полный маршрут.
- После этой правки SHA256 всех 11 278 прочих файлов JAR совпал с проверенной версией: повтор всех физических проверок не нужен. Изменены только клиентский StaticArchitectureClient и его вложенные классы (в том числе номера строк отладки). Доказательство: client-layer-change-proof.json.
- Два добавленных дальних ракурса оказались преимущественно направлены в небо. Они не включаются в основной FPS. Основные цифры получены по девяти прежним реальным видам фасада/статуи/дерева, остальные пять ракурсов и движение сохранены в сырых данных.
- В одной сопоставимой паре новый формат уменьшил длинные кадры и улучшил 1% low; средний FPS практически прежний. Снижение пиковой RSS клиента не подтверждено (5,76 → 5,80 ГиБ). Уменьшение состояний само по себе не выдаётся за равнозначное снижение RAM или рост FPS.
- Дополнительные шейдеры и Iris будут подбираться после основной приёмки. Отсутствие влияния на FPS заранее не предполагается: вариант принимается по реальной совместимости и измерениям. Неудачные сочетания останутся только в тестовых профилях.
- Предложение изменить частоту/порции загрузки чанков будет только проанализировано; соответствующее поведение мода в этой задаче не меняется.

Дополнение25.10, Iris, до графической приёмки:

- Карта ради шейдеров не меняется. Индексы передаются с immutable-снимками секций Sodium, без глобальной таблицы координат.
- Старые статические модели передаются через прежний рендерер в Indium, с прежними цветами/AO/светом. Повторное освещение вершин отключается только внутри такого вызова.
- Source-корни на Sodium используют существующий BE-рендерер: его ограниченный по высоте снимок не даёт всех проекционных выборок. Это общее правило формата, без исключений по ID и изменений данных v12.
- При активном шейдере отдельный GPU batch уступает штатным BE consumers для атрибутов Iris и прохода теней; без шейдера прежний batch сохраняется.
- Направленное отсечение граней Sodium отключается, frustum расширяется до полного допустимого диапазона упакованных вершин. Выход за диапазон явно проваливает тест вместо незаметного обрезания.
- QA-only preLaunch загружает7 настоящих классов через Knot и выходит до открытия мира. Это быстрая проверка ABI, не замена графического маршрута. Первый неверно настроенный запуск и исправленный PASS сохранены.
- Шейдеры сравниваются с минимальными эффектами. MakeUp — тёплая палитра Cocoa. Sildur при необходимости выдаётся локально, без перепубликации его ZIP на GitHub; для восстановления будет официальный URL с хешем.

Решения по завершённым центровым опытам25.10:

- Iris1.7.6 вместе с Sodium0.5.11 падал при включении шейдера (POSITION). Выбрана официально совместимая пара Sodium0.5.13/Indium1.0.36/Iris1.7.6; ошибочный профиль сохранён как отрицательный опыт.
- Sildur Fast и MakeUp NoEffects проверены на тех же девяти видах. Без шейдера производительность значительно выше. Для необязательных теней выбран MakeUp9.6 NoEffects с SHADOW_CASTING=true и Cocoa: он лучше выдержал плотный фасад и steady1%low. По умолчанию шейдер выключен в интересах стабильности города. Нулевое влияние шейдера не обещается.
- Попытка ограничить тени32метрами настройкой Iris остановлена до измерений: пакет перекрывает эту настройку. Затем проверен отдельный исходный вариант MakeUp с тремя ближайшими shadowDistance75→32. Устойчивого улучшения не получено; этот вариант не поставляется. Сравнение32м не строго однофакторное: тогда же заморожены два защитных условия GPUcache при активном Iris; это явно отмечено в отчёте.
- Два дополнительных условия запрещают обход штатного рендера Iris через ранее накопленный GPUcache. Остальная физика/пакеты/ресурсы не менялись; физические проверки повторно не запускаются. Отдельное доказательство byte-delta сохраняется.
- Рантайм computer-use не инициализировался (kernel assets/path error). Вместо дальнейшей настройки UI для короткой проверки используется публичный IrisApiConfig на потоке Minecraft. QAhelper не попадает в пользовательскую сборку и не участвует в FPS-замерах. Если в off-фазе retainedcache пуст, результат on/off/on не объявляется проверкой непустого retainedcache.
- Для переноса на другой ПК подготовлена полная эффективная sourceZIP с ресурсами; небольшой Git reviewtree не заменяет этот архив. Старые релизы сохраняются, у нового релиза будет одна текущая карта. Токены/аккаунты/аргументы пользовательского запуска не публикуются.
- Обновление Desktop выполняется через проверенный staging и переименование явно названных папок с полным резервным сохранением оригиналов. Порты, IP, ops/whitelist и личные options/keybindings не заменяются.

Результаты полного маршрута, холодного открытия и доставки дополняются после их фактического завершения.
