# Bloodborne RP Adventures — Fabric 1.20.1

Отдельный RP-мод для Dreamwalker. Он работает рядом с Bloodborne-Blocks, использует namespace `bloodborne_rp` и не требует интеграции с архитектурным модом.

Есть 18 типов монстров с обычным здоровьем Minecraft, три семейства оружия с двумя формами, фонари с маршрутами, 76 размещаемых объектов, двери, ворота, рычаги и открываемые сундуки. Мобы появляются только по решению ведущего: яйцами или `/summon`. Оружие переключается ПКМ или клавишей R; форма хранится в том же ItemStack, вместе с прочностью, именем и зачарованиями. Boom Hammer в активной форме поджигает цель и возвращается в обычную форму.

Своей системы HP, stamina, Rally, Blood Echoes, Insight, глобального HUD, сброса врагов и восстановления мира от фонаря нет. Флакон крови лечит обычное здоровье, но отключён по умолчанию. Его можно включить в `config/bloodborne-rp.json`. Баланс монстров изменяется обычными командами `/attribute`, их AI можно отключить стандартным NBT `NoAI` или `bloodborne_rp_frozen`.

Это новая реализация для Fabric. AI и урон адаптированы для RP; это не точное воспроизведение боевой системы Forge-мода. Статичные декорации, лестницы, транспорт и лифт являются декором; сундук в этой версии открывается как механизм и не создаёт добычу или инвентарь.

## Установка

Java 17, Minecraft **1.20.1**, Fabric Loader **0.16.10**. На клиент и сервер установите:

- `bloodborne-rp-1.0.0-rp.1.jar`;
- Fabric API **0.92.9+1.20.1**;
- GeckoLib **Fabric 1.20.1 4.4.9**.

Bloodborne-Blocks устанавливается отдельно. Старый Forge-мод и GeckoLib 3, Oculus, Rubidium и шейдеры из исходного комплекта для этого мода не требуются. Мир Forge 1.18.2 не конвертируется автоматически: новые ID принадлежат другому моду. Сначала используйте копию тестового мира.

## Работа ведущего

Предметы доступны в вкладке Bloodborne RP. Декор размещают creative-игроки или OP уровня 2. Для редактирования объект выбирается поблизости; команда показывает выбранный UUID. Сейчас выбор команды основан на ближайшем объекте в пределах шести блоков.

```
/bbrp object list
/bbrp object rotate
/bbrp object lock
/bbrp object unlock
/bbrp object link <UUID_двери>
/bbrp object unlink <UUID_двери>
/bbrp object delete
```

Разместите `hunterlamp_placer`, зарегистрируйте фонарь, затем повторите для второго. UUID получите командой `list`. Маршруты направленные: для обратного перехода создайте вторую связь.

```
/bbrp lamp register Центральный фонарь
/bbrp lamp list
/bbrp lamp rename <UUID> Новое имя
/bbrp lamp link <UUID_откуда> <UUID_куда>
/bbrp lamp unlink <UUID_откуда> <UUID_куда>
/bbrp lamp route open <UUID_откуда> <UUID_куда>
/bbrp lamp route close <UUID_откуда> <UUID_куда>
/bbrp lamp remove <UUID>
```

Обычный игрок использует фонарь ПКМ. Сервер проверяет живого игрока, дистанцию, однократный контекст, доступный маршрут, загруженность чанка и безопасное место рядом с реальным фонарём. Маршруты сохраняются в `world/data/bloodborne_rp_lamps.dat`. Максимум — 256 фонарей, окно выбора поддерживает страницы. Замки двери и рычага проверяются и при связанной активации.

## Сборка и проверка

Нужен полный JDK 17; обычного JRE недостаточно. Wrapper использует Gradle 8.8.

```powershell
.\gradlew.bat check build
.\gradlew.bat -PcoexistenceJar="C:\path\bloodborne-blocks.jar" rpGameTest
```

По умолчанию собирается публичный JAR с простыми резервными моделями и ванильными текстурами/звуками. Художественные материалы Potomy и декомпилированный Java-код в исходники не включены. Для локального изучения своего экземпляра исходного JAR:

```powershell
python tools/import_private_assets.py "C:\path\Bloodborne_X_Minecraft_mod_6.0.jar"
.\gradlew.bat -PprivateAssets=private-assets check build
.\gradlew.bat -PprivateAssets=private-assets -PcoexistenceJar="C:\path\bloodborne-blocks.jar" runClientSmoke
```

Импортёр принимает только проверенную версию 6.0 по SHA-256, копирует художественные ресурсы в gitignored `private-assets`, исправляет три опечатки звуков, регистр имён файлов и незавершённые выражения анимаций. Forge-классы не копируются. Полный локальный JAR находится в `build-private/libs`; публичный — в `build/libs`. Исходники воспроизводятся из каталога проекта или полного source ZIP; `-sources.jar` предназначен для просмотра Java-кода.

Правила распространения исходных моделей, анимаций, текстур и звуков изложены в [ASSET-NOTICE.md](ASSET-NOTICE.md). Результаты выполненных проверок находятся в [VALIDATION.md](VALIDATION.md).
